# g10 報告: local の範囲の導入は、自動更新で実行される版が切り替わるか（Claude Code 2.1.289、2026-10-04/05、macOS、隔離 `CLAUDE_CONFIG_DIR`・未ログイン、localhost の smart HTTP の git 型、`autoUpdate: true`）

生ログは scratch（`.../scratchpad/g10/logs/`）。条件は g9 と同じ（`DISABLE_AUTOUPDATER=1`・`FORCE_AUTOUPDATE_PLUGINS=1`、対話は tmux で 1 通送信）。

## 結論

仮説「自動更新は local の範囲の記録を書き換えない」は**成り立たない（棄却）**。local 導入でも、自動更新が `installed_plugins.json` の local 項目を新版に書き換え、`/reload-plugins` 無しで、次に起動したプロセスは新版から動いた。この環境では会社 PC の観測は再現しなかった。

## 比較（2 周目。作業フォルダは config ごとに別）

| 項目 | L（`--scope local`、WL から導入） | U（`--scope user`） |
|---|---|---|
| 自動更新 | 走った（送信から約 3 分 23 秒後。`re-cloning` → `updated feas@g10-mkt from 0.2.0 to 0.3.0`） | 走った（約 4 分 53 秒後。同じ行） |
| `installed_plugins.json` | scope=local、version=0.3.0、installPath=cfgL2/…/0.3.0、projectPath=WL | scope=user、version=0.3.0、installPath=cfgU2/…/0.3.0、projectPath 無し |
| cache | 0.2.0（`.orphaned_at` 付き）と 0.3.0 | 同じ |
| 新プロセス `-p "/feas-where"`（WL / WU から） | `code=code-v3 … root=…/0.3.0` | `code=code-v3 … root=…/0.3.0` |
| `plugin list` | Version 0.3.0、Scope local | Version 0.3.0、Scope user |
| `/reload-plugins` の後 | 不要だったため実施していない | 同左 |

1 周目（0.1.0→0.2.0）も同じ結果: L は 3 分 43 秒後、U は 9 分 43 秒後に自動更新、L の local 項目は 0.2.0 に書き換わり、`-p` は code-v2。待ち時間は 3〜10 分でばらつく（g9 と整合）。

## 注意: 1 周目の交絡

1 周目は L と U が同じ作業フォルダ W を共有した。L の `plugin install --scope local` が `W/.claude/settings.local.json` に `enabledPlugins: feas@g10-mkt` を書くため、U（user 導入）も W から起動すると、U の `installed_plugins.json` に **local 項目が自動で増えた**（installedAt が最初の W からの起動時刻。自動更新は user・local の 2 項目を更新し、`updated` が 2 行出た）。
2 周目は config ごとに別の作業フォルダ（WL・WU）で再実施し、この混入が無い状態で上の表を得た。L の結果は 1 周目・2 周目で同じ。

## 事実と推測

事実（本 Mac、2.1.289、localhost の http git 型）:
- local 導入でも自動更新は走り、local 項目の version・installPath が書き換わる。次のプロセスは `/reload-plugins` 無しで新版
- `plugin marketplace add` は `settings.json` に `extraKnownMarketplaces` を宣言形式で書くが `autoUpdate` は付かない。手で `autoUpdate: true` を足す必要がある（足さないと対象外になる可能性。未検証）
- 同じ作業フォルダを共有する別 config にも、project の `settings.local.json` の `enabledPlugins` 経由で local 項目が増える

推測（未検証。会社 PC の観測の原因候補）:
- 会社 PC の local 導入では `autoUpdate: true` の付き方・場所が違い、cache の取得だけが走って記録の更新が別の経路になった
- ssh の git 型、Bedrock、managed settings、会社 PC の本体の版の違い
- 会社 PC で「再起動しても旧版」だったのは、`installed_plugins.json` の local 項目の projectPath と起動したフォルダが一致していなかった可能性（本検証は一致するフォルダからのみ起動。不一致の場合は未検証）

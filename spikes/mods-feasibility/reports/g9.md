# g9 報告: 自動更新で実行される版が切り替わる条件（Claude Code 2.1.289、2026-10-04、macOS、隔離 `CLAUDE_CONFIG_DIR`・未ログイン、localhost の smart HTTP の git 型、`autoUpdate: true`）

生ログは scratch にあったが、セッションの中断で失われた。以下は担当の報告の写しで、監督が生ログで照合した点を末尾に記す。

## 結論

「再起動で切り替わらない」は再現しなかった。自動更新が走って `installed_plugins.json` に新版が書かれれば、次のプロセスは `/reload-plugins` 無しで新版から動いた。
会社 PC の観測は交絡か環境差の可能性が高い（原因は特定していない）。

## 条件ごとの結果（`DISABLE_AUTOUPDATER=1` は全 cfg。FORCE は `FORCE_AUTOUPDATE_PLUGINS=1`）

| 条件 | 自動更新 | installed_plugins.json | 再起動で切り替わったか |
|---|---|---|---|
| B（FORCE 有）新版の公開後、対話で 1 通送信 | 走った（送信から 7分49秒後。`re-cloning` → `updated 0.1.0→0.2.0` → `reload required`） | 直後に新版 | 動作中の対話は旧版。新しいプロセス（`-p`・対話）は新版 |
| B の 2 周目 | 走った（3分21秒後。0.2.0→0.3.0） | 0.3.0 | 新しいプロセスは新版 |
| A（FORCE 有）送信せず放置 15 分 11 秒 | **走らなかった**（`Synced autoUpdate=true` だけ） | 旧版のまま | – |
| A の続き、送信 | 走った（4分31秒後。0.1.0→0.3.0、版を飛ばして最新へ） | 0.3.0 | 新しいプロセスは新版 |
| 再起動の繰り返し | – | 自動更新の完了時点で新版 | `/reload-plugins` 無しで切り替わった |
| C（`-p` のみ約 14 回） | **走らなかった** | 旧版のまま | – |
| D（FORCE 無し、送信） | **走らなかった**（`Plugin autoupdate: skipped (auto-updater disabled)`） | 旧版のまま | – |

- 自動更新は、対話でメッセージを送ってから 3〜8 分後に走る。未ログインで送ってエラーになっても走る
- `DISABLE_AUTOUPDATER=1` だけだとプラグインの自動更新も skipped。`FORCE_AUTOUPDATE_PLUGINS=1` を足すと走る
- 未ログインの隔離 config は初回の対話がログイン方法の選択で止まる。隔離の `.claude.json` に `hasCompletedOnboarding: true` を書いて回避した

## 推測（会社 PC の観測の原因候補。未検証）

1. 自動更新が走る前の再起動を、更新済みと取り違えた
2. cache に新版が入ったが `installed_plugins.json` が更新されていなかった（会社 PC では未確認。最有力の確認点）
3. 会社 PC 固有の条件（ssh、Bedrock など）
- 未検証: `DISABLE_AUTOUPDATER` 無しの既定の端末、ssh・Bedrock・managed settings、`/plugin` の操作、更新の最中の再起動

- `installed_plugins.json` は、送信した config（A・B）で 0.3.0、`-p` だけの config（C）で 0.1.0 だった（セッションの中断の前）

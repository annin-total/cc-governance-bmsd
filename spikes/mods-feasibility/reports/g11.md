# g11 報告: 古い状態を持つ別プロセスが、自動更新後の `installed_plugins.json` を旧版で書き戻すか（Claude Code 2.1.289、2026-10-05、macOS、隔離 `CLAUDE_CONFIG_DIR`・未ログイン、localhost の git 型、`--scope user`、`autoUpdate: true`）

生ログは scratch（`.../scratchpad/g11/logs/`。`ops.log`・`watch.log`・各プロセスの debug log）。`DISABLE_AUTOUPDATER=1`・`FORCE_AUTOUPDATE_PLUGINS=1`、対話は tmux で 1 通送信。`installed_plugins.json` は 0.5 秒間隔の監視で mtime・内容の変化を記録した。

## 結論

仮説「自動更新の後、古い状態のまま開いている別プロセスが、旧版で `installed_plugins.json` を書き戻す」は、この環境では**再現しなかった**。3 つの条件・全操作（メッセージ送信、`/plugin` の開閉、`/exit`、約 60 秒の放置）の前後で、ファイルの mtime は自動更新の時刻のまま動かず、version・installPath も新版のままだった。新しいプロセスは新版（`-p "/feas-where"`、`plugin list` とも）。

## 根拠（debug の行）

- 更新したプロセスだけに `Marketplace checkout probe: local … remote … — re-cloning` → `Plugin autoupdate: updated feas@g11-mkt from 0.1.0 to 0.2.0` が出る（B1 15:18:05、A1 15:24:47、A3 15:26:07。UTC）。
- 古い状態の P2（A2・B2）の debug log には、起動時の `Loaded 1 installed plugins` 以外に、`installed_plugins` を書く・更新する行は無かった。
- 監視ログ `watch.log` に、新版への 1 回の変化の後、旧版へ戻る行は無い。

## 事実と推測

事実（本 Mac、2.1.289、localhost の http git 型、user の範囲、cache ・installed_plugins.json とも隔離 config 内）:
- 古い状態のプロセスは、メッセージ送信・`/plugin` の開閉・`/exit` のいずれでも、`installed_plugins.json` を書き換えなかった（mtime 不変）
- 自動更新の発火までは 4〜6 秒の場合と約 6 分 46 秒の場合があり、ばらつく（g9・g10 の 3〜10 分と整合。今回は 6 秒で走った回もある）
- 更新後に起動したプロセスは `/reload-plugins` 無しで新版から動いた

推測（未検証）:
- 会社 PC の現象の原因は、本検証の範囲外にある。候補は、複数プロセスが同時に更新を走らせた競合（本検証は更新を起こすプロセスを 1 つずつにした）、別のセッションが旧版を持つ別の記録（local・project の項目）を書く経路、`/reload-plugins`・`/plugin` の更新・install 操作（本検証は行っていない）、ssh の git 型・Bedrock・managed settings・本体の版の違い
- 「同時に複数のプロセスが更新を起こす競合」は本検証で試していない（g11 の次の候補）

## 未検証

- 複数プロセスが同時に自動更新を起こしたときの競合
- `/plugin` からの update・install・`/reload-plugins` を P2 で実行した場合
- 会社 PC と同じ版・認証（Bedrock）・managed settings

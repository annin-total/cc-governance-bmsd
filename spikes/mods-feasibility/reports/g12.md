# g12 報告: 別のフォルダ X で自動更新が走ると、local 項目（導入フォルダ F）は書き換わるか（Claude Code 2.1.289、2026-10-05、macOS、隔離 `CLAUDE_CONFIG_DIR`・未ログイン、localhost の git 型、`--scope local`、`autoUpdate: true`）

生ログは scratch（`.../scratchpad/g12/logs/`。`X-tui.debug.log`・`F-tui.debug.log`・`watch.log`）。`DISABLE_AUTOUPDATER=1`・`FORCE_AUTOUPDATE_PLUGINS=1`。`installed_plugins.json` は 0.5 秒間隔で監視した。

## 結論

仮説「自動更新を起こしたセッションが projectPath と別のフォルダで動いていると、cache には置くが local 項目の記録は書き換えない」は、**記録を書き換えない点は支持された。ただし「cache に置く」のは X の自動更新ではなかった**。

- X で送信した自動更新は、12 分待っても local 項目を書き換えず、cache にも 0.2.0 を置かなかった。debug には `Plugin autoupdate: checking installed plugins` だけが出て、`updated` は出なかった
- cache に 0.2.0 が現れたのは、F から `claude plugin list` を実行した瞬間だった（`plugin list` を単独で実行して再現。`-p` では置かれない）。会社 PC の「cache に新版があるが旧版のまま」は、この状態と一致する
- F で対話を起動して `/reload-plugins` を実行すると、その場で code-v2 に切り替わった。記録は旧版のまま、新しい F のプロセス（`-p`）は code-v1
- F で送信すると、3 分 16 秒後に F 自身の自動更新が local 項目を 0.2.0 に書き換えた（g10 と整合）

## 事実と推測

事実（本 Mac、2.1.289、localhost の http git 型、local 導入、cache・記録とも隔離 config 内）:
- X（feas が有効でないフォルダ）の自動更新は、marketplace の clone を新しくしたが、F の local 項目を書き換えず、cache にも版を置かなかった（12 分）
- `claude plugin list` を F から実行すると、cache に marketplace の最新版（0.2.0）が置かれる。記録は書き換わらない（単独実行で確認。`-p` は置かない）
- cache に新版があり記録が旧版のとき、`-p` の起動は旧版のまま。対話での `/reload-plugins` は新版に切り替える
- F の自動更新が走ると local 項目は書き換わり、以後の起動は新版

推測（未検証）:
- X の自動更新が F の項目を触らなかった理由は、更新の対象が「そのフォルダで有効なプラグイン」に限られるためと思われる（X のコードは読んでいない。X では feas は無効）
- X が marketplace の clone を新しくしたため、F の後続の probe は `up to date` になった。それでも F の自動更新は 3 分 16 秒後に走ったので、clone 済みが更新を妨げるとは言えない（待ち時間は 3〜10 分でばらつく）
- 会社 PC の cache の新版は、`plugin list` のような読み取り系の操作が置いた可能性がある（会社 PC で実行した操作は未確認）。会社 PC で F が長く旧版だった理由は、F 自身の自動更新が走るまで（または走らなかった）と考えるのが整合的だが、断定できない

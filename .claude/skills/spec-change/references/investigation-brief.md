# 調査 共通指示書

## 依頼

<依頼の言い直し（1〜2 文）>。利用者の元の言葉: 「<引用>」

調査だけを行う。**ファイルは変更しない。**直す案を思いついても、提案として書くだけにする。

## 対象

スナップショット: `<取り出したパス>`（ここを読む）

| リポジトリ | ブランチ | commit |
| --- | --- | --- |

報告に書くパスは、各リポジトリからの相対パスにする。最初に `docs/README.md` で文書の置き場を確かめる。

## 書くこと

事実と推測を分ける。各項目に確度（確認済み / 推測 / 未検証）を付ける。

1. **現状**: 今どうなっているか。根拠は `ファイル:行`、または文書のパスと見出し名
2. **決着済みの判断との関係**: 依頼に関係する記録（採らない理由・受け入れた限界・既知の課題・未検証事項）を引用する。
   依頼がそれを覆すなら、記録の理由のどこが今は成り立たないのかを書く。
   **「記録なし」と書く前に、`docs/` 全体を関連語で全文検索する。**検索した語も書く
3. **影響範囲**: 変更が触れるファイル・契約・サーバ・文書・テスト。submodule をまたぐかどうか
4. **守り**: 変更が崩しうる不変条件（`CLAUDE.md` の Design、`docs/spec/` の規約）
5. **選択肢**: 実現の方法が複数あれば並べる。それぞれの長所と短所、規模の目安も書く
6. **利用者に確認すべきこと**: 調査では決められない判断

件数を埋めない。無い項目は「無し」と書く。

## 決まりごと

- 上流（Claude Code など）の仕様は、古い知識を前提にしない。`docs/knowledge/` と公式の情報で確かめ、URL と確認日を書く
- 調べるのは、変更が触れる範囲だけにする。範囲外で見つけた問題は「別件」として 1 行ずつ書くにとどめ、深追いしない
- **動的な確認（実行・実機での観測）は、結果によって選択肢や推奨が変わる事実に限る。**読めば分かることは読んで済ませる。
  行うときは、スクラッチパッドの `work-<レーン>/` の中だけで行う。隔離の方法は `CLAUDE.md` に従い、利用者本人の設定には触れない
- 起動したプロセスと一時ファイルは、終わる前に片付ける

## 出力

`local/<作業名>/L<n>-<名前>.md` に書く。最終メッセージでは、ファイルパスと要点 3 行だけを返す。

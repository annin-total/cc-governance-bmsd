# 進捗記録と委任指示のひな形

どれも出発点にすぎない。作業に合わない欄は消してよい。書き足すより、状態を書き換えて短く保つ。

## 全体の記録 `local/<作業名>/progress.md`

PR が 1 本のときは、これ 1 つで PR の記録も兼ねる（「PR 一覧」を消し、PR の記録の欄を足す）。

```markdown
# <作業名>（一時文書。いつ消してもよい。ここを参照するものを作らない）

## 目的と承認済みの方針（<日付>）
- 目的:
- 変える / 変えない:
- 覆す判断:（無ければ「なし」）

## 基準（<作業開始時のブランチ> @ <commit>。submodule も）
- テスト件数・リンタの状態

## ワークフロー
| # | 段階 | 担当 | 状態 |
| --- | --- | --- | --- |
| 1 | 調査 | | |
| 2 | 方針の承認 | 責任者 | |
| 3 | PR1: <目的> | | |
| 4 | PR2: <目的> | | |
| 5 | 完了報告 | 責任者 | |

## PR 一覧
| # | リポジトリ | ブランチ | base | 目的 | 状態 | URL |
| --- | --- | --- | --- | --- | --- | --- |

## 判断の記録
- <日付> 何を、なぜ

## 別の作業の候補（今回は直さない）
-
```

## PR ごとの記録 `local/<作業名>/pr<n>-<目的>.md`

その PR に着手するときに作る。

```markdown
# PR<n>: <目的>（一時文書）

## 範囲
- やる:
- やらない:
- 触らない場所:

## 作業
| 手順 | 担当 | 状態 |
| --- | --- | --- |

## 完了条件（検証）
-

## 報告（担当が書く）
- コミット一覧、テスト件数の前後と理由、検証の結果、判断を待つもの

## 次の PR への引き継ぎ
-
```

## 担当への指示

```markdown
<作業名> の <調査 | 実装 | 検証> 担当です。日本語で書く。
指示された範囲の外には手を出さない。想定外の問題や判断が要る点は、直さずに報告して止まる。

- 対象: <リポジトリ・ブランチ>。触らない場所: <paths>
- まず読む: CLAUDE.md、<文書を書くなら docs/CLAUDE.md>、<進捗記録のパス>
- やること: <具体的に。前提となる調査結果と、壊してはいけない制約を添える>
- 完了条件: <確かめること>
- （実装）テストを先に書き、今の実装で落ちることを確かめてから実装する。変えたパスだけを git add してコミットし、push しない
- （検証）作業ツリーにもファイルにも触れない。壊して確かめるときは作業ツリーの外の複製で行う
- 一時ファイルはスクラッチパッドの <サブディレクトリ> の下だけに置く
- 返答: 何をしたか・結果・判断を待つものを短く。長くなるものは <進捗記録のパス> の「報告」に書き、返答ではそう伝える
```

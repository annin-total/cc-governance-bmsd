# 減らす作業

目的は**振る舞いを変えずに減らすこと**。機能は足さない。不具合も直さない。
途中で見つけた不具合や改善案は記録だけして、報告で別の「増やす作業」として挙げる。
混ぜると、差分のどこが振る舞いを変えたのかを追えなくなるためである。

## 規模を決める

対象を読み、次のどれかに当たれば**大規模**、当たらなければ**小規模**とする。判断は利用者への最初の提案に 1 行で添える。

- 1 本の PR に収まらない（レビューできる大きさを超える、依存の順に分けたい）
- 複数のリポジトリにまたがる（サブモジュールを含む）
- ファイルの移動・改名・分割が多く、参照の追従が広い
- テストの削除やテスト ID の変更について、先に方針を決める必要がある

**大規模なら `references/large-scale.md` を読み、そちらの流れで進める。**本文の「変えてよいもの」「検証」「並行作業の注意」はどちらにも適用する。

## 小規模の流れ

1. **提案して合意を取る**：対象を読み、候補（何を・どれだけ減るか）と、やらないもの（理由つき）を短く示す。一度だけ確認し、いきなり手を動かさない
2. **ブランチを切る**：作業開始時のブランチから切り、PR もそこへ向ける
3. **基準を記録する**：テスト件数・リンタの状態・対象の行数
4. **実施する**：候補ごとに 1 コミットにし、どのコミットでもテストが全件通る状態を保つ。サブエージェントに任せるかは量で決める。任せるなら、問題をその場で直させず、報告させる
5. **検証する**：下の「検証」から、当てはまるものだけを確かめる
6. **報告する**：変えたもの、確かめたこと、やらなかったもの、見つけた既存の問題

## 変えてよいもの・いけないもの

- **ロジックとテストのアサーションは変えない。**変えてよいのは、import パス・差し替え先・検査対象のパスの追従だけ
- 挙動が変わるものは、1 件ずつ承認を取ってから入れる
- **テストの削除は「完全に包含される」ものだけ。**同じ入力・同じ期待値を検査しているだけでは足りない。
  消すテストが、他の検査では捕まらない壊れ方（パス計算の誤りで検査対象が 0 件になる、など）を唯一捕まえていないかも確かめる
- 書き換え禁止のもの（生成物・実採取データなど）は、各リポジトリの `CLAUDE.md` が名指ししている。触らない
- docstring とコメントの基準は `CLAUDE.md` の Coding に、文書の基準は `docs/CLAUDE.md` に従う。
  文書は一方的に追記せず、直すときは周辺の古い記述・重複の削除とセットにする

## 検証

当てはまるものを確かめる。

| 変えたもの | 確かめること |
| --- | --- |
| 何であれ | テストが全件通る。件数の増減を説明できる。`CLAUDE.md` の Commands のリンタ・フォーマッタが通る |
| コメント・docstring だけ | docstring を除いた `ast.dump` が作業前と一致する。比較スクリプトも壊して（定数を 1 文字変えるなど）差を検出できることを確かめる |
| 名前・場所 | 旧名の grep が、コード・テスト・`docs/`・`README.md`・各 `CLAUDE.md`・設定ファイルで 0 件 |
| テストの構造（共通化・パラメタ化・分割） | テスト ID が変わらないなら、`--collect-only` の一覧が作業前と一致する。変わるなら、対応表を機械的に作って PR に添える |
| 守りに関わる箇所 | `CLAUDE.md` の Design や各リポジトリの規約が挙げる守りを壊し、検査が落ちることを確かめる |
| 実行されるコード | 実行基盤の版（`CLAUDE.md` が指定するもの）でテストを通す。アプリなら実際に起動して確かめる |

利用者の実環境の設定には触れない。触れうる作業では、作業の前後で更新時刻を比べる。

## 並行作業の注意

- コミットは自分が変えたパスだけを明示して `git add` する（`-A` や `commit -a` は使わない）
- コミットの前に `git status` と `git log -1` を見る。自分以外の変更やコミットが混ざっていたら触らず、判断を仰ぐ
- 変異検査は必ずコミットしてから行い、1 ファイル単位で戻す。一括で戻すと、未コミットの変更まで消える

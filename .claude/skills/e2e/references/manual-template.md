# 手動確認の手順書のひな形 `local/<作業名>/manual.md`

利用者が上から順に打てば終わる形にする。人が読むので、変数を使わず、実際のパスをコマンドに直接書く。
実行してみないと分からない値は `<準備 3 で出たパス>` のように日本語で差し込み位置を示す。
項目の中身（何を見て何を合格とするか）は e2e.md の手動確認の項目から取る。ここには書き方だけを置く。

## 構成

```markdown
# 手動確認: <作業名>（終わったら消す）

Claude Code から起動されていないターミナルで行う（Claude Code の `!` や Bash では行わない）。

## 準備
1. 隔離ルート — 済み: `<実際のパス>`
2. 起動のしかた（下の「OS ごとの書き方」）と、動くことの確かめ方（例: `--version`）
3. 実行してみないと分からない値の確かめ方（例: 導入先のファイルのパス）
4. 変えた本物を導入先に写す（E2E が見本を重ねていて変更を通らない場合だけ）

## A. <モジュール>: <項目>
1. 手順（コマンドはコードブロックに 1 つずつ）
   合格: 何が見えればよいか。無いことが正常なら、確かめるコマンドと「何が出れば合格か」も添える
（後の確認で状態が変わる項目は、順序を明記する）

## 片付け
## 結果の返し方（項目ごとに合格／不合格と見えたものを伝える。不合格ならルートを残す）
```

## OS ごとの書き方

認証は環境変数で渡す（`/login` させない）。値そのものは書かず、利用者の環境にある変数の名前だけを示す。
ファイルを書き換える手順は、どの OS でも、短い Python のファイルを作ってそれを実行させる（その場の 1 行はシェルの引用符で壊れやすい）。

**macOS・Linux（bash / zsh）**：親の変数を持ち込まないよう `env -i` で空にし、基本の変数と認証の変数だけを渡す。
毎回打たせるのが長ければ関数にしてよい（パスは関数の中に直接書く）。一致しない glob がエラーになるシェルがあるので、無いことの確認は `ls` より `find` が確実。

```bash
cd <ルート>/project && env -i HOME="$HOME" USER="$USER" TERM="$TERM" PATH="$PATH" \
  CLAUDE_CONFIG_DIR=<ルート>/config <認証の変数>=... claude
```

**Windows（PowerShell）**：Claude Code から起動されていない新しいウィンドウで行う。
隔離の変数はそのウィンドウの中だけで設定し、終わったらウィンドウを閉じる（閉じないと、後で打つ `claude` が隔離側を見る）。

```powershell
Get-ChildItem Env: | Where-Object Name -like 'CLAUDE*'   # 何も出ないこと（親の変数を持ち込んでいない）
Set-Location <ルート>\project
$env:CLAUDE_CONFIG_DIR = "<ルート>\config"
claude
```

- Python はリポジトリの `.venv\Scripts\python.exe`。スクリプトのファイルは UTF-8 で保存させる（PowerShell 5.1 の既定の文字コードでは日本語が壊れる）
- 深い場所のファイルの有無は `Get-ChildItem -Recurse -Filter <名前> <ルート>`（何も出なければ無い）
- 認証の情報はキーチェーンではなく config の中に置かれるので、ルートと一緒に消える
- ルートの削除は `Remove-Item -Recurse -Force <ルート>`（未検証。読み取り専用のファイルで失敗したら、その旨を返してもらう）

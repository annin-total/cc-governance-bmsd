# 一時スクリプトで状況を確かめる

E2E が起こさない状況（更新・撤回・壊れた入力・送信の失敗・負荷など）、上流の事実の採取、漏れの監査、手順の通しを、
使い捨てのスクリプトで実物を動かして確かめるときの約束と型である。スクリプトはその場で現物に合わせて書く。
常に流す価値があると分かったものは、E2E に足す提案として報告する（足すのは plan-implement）。

## 一時スクリプトの約束

1. **先に聞く。**何を事実として持ち帰るか（仮説と、どう壊れうるか）を示す。認証ありで流す回数か重い負荷があれば、
   見積もりを添えて選択式で承認を得る
2. **置き場。**スクリプト・ログ・生データはすべて `.local/<作業名>/` に置く。`plugin/`・`e2e/`・`tests/` は書き換えない。
   `plugin/` のコードは import しない（要るときは `python -B` か、複製したものを動かす）。実採取した hook の入力（`tests/` の fixtures）は読むだけ
3. **隔離は自作しない。**`e2e/` の共通部分（隔離ルート・組み立てと導入・セッション・hook の行の読み出し・Docker のサーバ）を import する。
   隔離・送信先の空化・自動更新の抑止がそのまま付いてくる。
   hook を直接起動する（API も実セッションも要らず速い）ときは 4 つを守る。
   プラグインの複製を指す／状態の置き場を隔離する／複製の送信先を空かローカルにする（e2e.md の、E2E の外でプラグインを動かすときの注意）／
   送信の間引きは状態の置き場にある最後に送った時刻の印で制御する。
   起動時の hook を直接起動すると、設定の書き込みとブラウザの起動を伴う
4. **`CC_E2E_RUN`。**同時に動く実行ごとに一意な値（`<作業名>` か `<作業名>-<番号>`）を付ける。
   Docker のラベルと隔離ルートの名前に入り、片付けの持ち主を区別できる
5. **排他は並行するときだけ。**他の検証と並行するなら、重い段（`claude` の多数起動・大きな DB・計測）は
   `mkdir` で取るロックで 1 つずつ流し、ロックは `trap` で必ず返す。計測は他を止めた時間帯に行う
6. **判定を先に壊す。**流す前に 2 つを確かめる。自己検査（判定に、手作りの合格と不合格の入力を与える）と、
   変異（実装を壊した複製か上書きで、判定が落ちる）。確かめられなかった判定は「未検証」として報告する
7. **事実と推定を分ける。**版（`claude`・OS）・負荷（load average）・回数を添える。1 回だけの観測は 1 回だったと書く
8. **秘密。**認証の値を表示しない・書かない。ログに出たら、そのログを残さない。実データ（CSV・実在のメールアドレス）は `.local/` の外へ出さない
9. **実物で棚卸しする。**終えたら、一時ディレクトリの `cc-e2e-*`・自分の `CC_E2E_RUN` の Docker 資源・プロセス・大きな生成物を実際に見る。
   担当の「片付けた」という申告は証拠にしない。自分のものでない残骸は、消す前に聞く
10. **残し方。**結果は記録に書く。上流の事実は `docs/knowledge/` へ、手順の誤りは e2e.md へ、
    常に流す価値があるものは plan-implement へ、それぞれ提案する。スクリプトは記録と一緒に、消すかを聞く

## 型の表

| 型 | 起こし方 | 判定の置き場 | 範囲外・注意 |
| --- | --- | --- | --- |
| T1 状態の遷移（更新・撤回・撤去・無効化・版の混在） | 導入 → 隔離した settings.json や状態に既存の値を入れる → 上書きつきで次の版を組み立てて更新 → セッション | settings.json と状態ファイルの中身。policy 行の適用済みの記録は証拠にならない | 組み合わせの網羅は `tests/` |
| T2 壊れた入力・壊れた配布物 | 壊したものは導入先か複製に作る | 「無言」を観測する（行が 0・バイト不変・終了コード・標準エラー・`claude doctor`） | 網羅は `tests/` |
| T3 送信の失敗と回復 | hook の直接起動で積む。閉じたポート・誤ったトークン・応答を捨てる中継で失敗を起こす | 自分の印（イベントやセッションの ID）で DB と突き合わせ、欠けと重複を見る | 上限の境界値は `tests/` |
| T4 受信と取込 | Docker のサーバに、正常な行で挟んだ 1 リクエストを送る | DB の全行を書き出して突き合わせる。画面の「成功」を合格としない | 本番と同じ DB 製品での確認は範囲外 |
| T5 同時実行・負荷・計時 | 判定は直接起動で先に固め、実物の `claude` は閾値を測るのに使う | 数字は相対比較だけに使い、条件を添える | E2E に昇格させない |
| T6 上流の事実の採取 | 未ログインの `-p` で足りるかを先に考える（`SessionStart` は未ログインでも発火する） | 生の入力を版つきで控える | 対話でしか出ないものは手動確認 |
| T7 監査（漏れの走査） | 一意の印を仕込む。先に陽性対照で、走査が印を検出することを確かめる | 送信経路と、端末に残るもの（バックアップ・キャッシュ）を分けて答える | — |
| T8 手順の通し | `docs/guide/` の手順を 1 段ずつたどる。順序を誤った場合も 1 回試す | 手順どおりで届くか、誤ると止まるか | 実行基盤でしか見えないものは範囲外 |

## 常に断る範囲

- 本番の環境・本番の受信先・実利用者のデータ
- 利用者の手元でしか動かないもの（Windows での実行・Bedrock・実行基盤）と、対話でしか見えない表示。これらは手動確認の手順書を渡す
- 集計ロジックと効果の測定（`server/` のテストの担当）

# CLAUDE.md - verification

`verification/` 配下を書き換えるときの規約の正本。

## 構成

```
verification/
  CLAUDE.md              ← この文書。規約の正本
  README.md              ← 道具のカタログ。何があり、どう動かすか
  fixture-sanitization/  ← 実採取した hook stdin を無害化して tests/fixtures/ を作り直す
  hook-behavior/         ← Claude Code が hook に何を渡すかを調べる
  autoupdate/            ← 配布経路が端末まで降りるかを調べる（擬似マーケットプレイスを含む）
  performance/           ← 性能の測定を再現する
```

確かめる順序と合格の条件は `docs/guide/local-e2e.md` にある。**道具の使い方は
`README.md`、確かめる順序と合格の条件は `docs/guide/local-e2e.md`。**片方にしか書かない
こと。両方に書くと必ず食い違う。

## 何を置き、何を置かないか

**置くのは、再実行できる道具だけである。**次に使う人が、同じ手順で同じことを確かめられるもの。

置かないもの:

- **実行結果**（採取したログ・スクリーンショット・計測値）
- **実採取した生データ**（hook stdin にはプロンプト本文が入る）
- **一度きりの解析**（その場で書き捨てた集計スクリプト）

実行のたびに要る作業ディレクトリは `.gitignore` に入れる。
**git に入らないものを README の手順が前提にしてよい。**用意する手順を書けばよい。

## 群の選び方

新しい検証を足すときは、**何を知りたいのか**で群を選ぶ。

| 知りたいこと | 群 |
| --- | --- |
| Claude Code が hook に何を渡すか | `hook-behavior/` |
| 配布したものが端末まで降りるか | `autoupdate/` |
| 速いか、インデックスが効くか | `performance/` |
| テスト用フィクスチャをどう作り直すか | `fixture-sanitization/` |

どれにも当てはまらないなら**新しい群を作る**。既存の群に無理に入れない。
群の名前は中身を表すものにし、**採番の接頭辞を付けない。**

## 規約

1. **各スクリプトに「何を確かめるものか」を 1 行で添える。**docstring か先頭コメント。
2. **README に使い方を書く。**引数・環境変数・前提・出力先。
   **コードを読まないと使えないものは未完成である。**
3. **実リポジトリに書き込むものは、README で警告する。**
   書き込み先が引数で変えられないなら、そのことを明記する。
4. **実データ・プロンプト本文・個人情報・社内のホスト名を置かない。**
5. **`autoupdate/marketplaces/` を手で編集しない。**bare リポジトリとスナップショットの
   一致を `tests/integration/` が検査している。変えるときは bare を正本として更新する。
6. **`tests/fixtures/hook_inputs/` を書き換えない。**実採取した記録であり、改竄になる。

## なぜこの規約があるか

**検証の道具は、次に使う人が読んで動かせなければ、存在しないのと同じだからである。**

動かないまま置かれた道具は、使おうとした人の時間を奪ったうえで、結局その人が
同じものを書き直すことになる。**1 行の説明と README の使い方は、道具の一部である。**

実行結果を置かないのは、**古い結果が新しい事実を上書きするからである。**
「前はこうだった」は次に確かめる人を惑わせる。確かめ方だけを残し、結果はその都度取る。

実リポジトリへの書き込みを警告するのは、**検証のつもりで動かした道具が成果物を壊した
からである。**読むだけのつもりの操作が破壊操作であることがある。

## 文書記述ルール

`docs/CLAUDE.md` の文書記述ルールをそのまま適用する。
**現時点で正しいことだけを書き、事実と推測を区別し、日本語で書く。**

## 課題

### 1. 再開したセッションで、セッション単位の内訳が 2 つに割れる

セッションを再開すると、元の会話が新しいセッションの jsonl に複製される。重複排除は最初に見た行の側に寄せるので、
本体の行が再開側に数えられ、元のセッションにはサブエージェントの分しか残らない。
その結果、元のセッションは `sessions.details` で `turns: 0`・`sidechain_ratio: 1.0` と表示される。

実データでは、出力 1 位のセッションの本体の requestId 597 件（assistant 1,265 行）と、user の uuid 613 件が、出力 2 位のセッションと重なっていた。
合計値は正しいが、上位セッションを「人の入力がない自動実行」と読み違えやすい。通し実行では、監督役が jsonl を直接調べてようやく気づいた。

改善案（いずれか）:
- 案 A（Recommended）: `history-notes.md` に現象と見分け方（`turns: 0` かつ `sidechain_ratio: 1.0` で、本体の jsonl に user 行があれば再開を疑う）を書く。コードは変えない
- 案 B: `collect` が、重複排除で行を取られたセッションの組を数えて `sessions.details` に出す（例: `shared_with`）

**完了条件** — 案 A なら、上記の見分け方が `history-notes.md` にある。案 B なら、再開を模したフィクスチャ（2 ファイルが同じ requestId・uuid を持つ）で
`shared_with` が出ること、その出力処理を壊すとテストが落ちることを確かめる。

### 2. 自セッションの扱いが SKILL.md の中で食い違う

守ること 4 は「起動前の同セッション分は利用者の実際の利用なので集計に含まれる」としている。
一方、環境検出の手順では `${CLAUDE_SESSION_ID}` が置換されていれば `--exclude-session` に渡すので、起動前の分も含めてセッションごと外れる。
通し実行では、置換済みの ID が渡り、起動前の作業 171 行・18 件が外れた。

改善案: どちらかに揃える。
- 案 A（Recommended）: `--exclude-session` を渡す手順を消し、開始時刻での打ち切りだけにする（守ること 4 の意図どおり）
- 案 B: 守ること 4 を「セッションごと外す」に直す

**完了条件** — 守ること 4・環境検出の手順・`progress-template.md` の記述が一致している。

### 3. `file_extensions` の数え方が文書に無い

`file_extensions` は、入力に `file_path`・`notebook_path` を持つツールすべて（Read・Write・Edit など）を数え、読み込みと書き込みを区別しない。
`history-notes.md` は「ファイル系ツールの拡張子別件数」としか書いていない。
通し実行では、監督役が `.png` の 602 回を「画像の読み込み」と書き、検証役に指摘された。

改善案: `history-notes.md` のスキーマ表に、対象のツールと、読み書きを区別しないことを書く。

**完了条件** — `history-notes.md` の `file_extensions` の行に、上記の 2 点がある。

### 4. 検証役が、監督役の確認済みの事実を断定として指摘する

検証役には下書きと集計 JSON だけを渡す設計なので、監督役が jsonl で確かめた事実（課題 1 の再開の判定など）は根拠が見えない。
今回は 1 件で、監督役が根拠を `progress.md` に残し、観測のまま配置した。運用で吸収できる範囲で、手当てするかは判断が要る。

改善案: 段階 5 の指示に「集計 JSON に無い観測は、根拠（例: jsonl で確認）を本文に一言添える」を足す。

**完了条件** — 足すか見送るかを決め、足すなら SKILL.md の段階 5 にある。見送るなら項目を消す。

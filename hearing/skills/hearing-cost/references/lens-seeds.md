# 観点の種（確認日 2026-10-01）

出発点にすぎない。各観点は「collect の集計 JSON のどこを見るか」と「誤検知の注意」だけを書く。根拠の多くは単一ユーザーの報告や二次情報なので、断定せず確度は「推定」止まりにする。

## 重い寄りになりやすい（影響が大きい順の目安）
- 長時間・`/clear` しないセッション: 1 ターンごとに全会話が再送される。セッション長、ターン数、キャッシュ読み込み量の大きさを見る。誤検知: 読み込みは軽いので、量が多いだけで重いとは言わない。
- キャッシュの失効・破壊: 休憩後（5 分／1 時間超）やモデル・effort の切り替え直後に、キャッシュ書き込みが跳ねる。書き込みと読み込みの比、モデルや effort の切り替え回数を見る。誤検知: 新しい作業の開始でも書き込みは増える。
- サブエージェント・並列実行: 親のキャッシュを読まず、短い TTL で再書き込みが多い。sidechain 分のキャッシュ書き込みと全体に占める割合を見る。誤検知: 必要な分担なら避けられない。
- 高いファミリーの常用: ファミリー別のトークン量と比率を見る。誤検知: 難しい作業なら妥当。補助モデルの消費は履歴に出ない（transcript 外の消費の注記を見る）。
- effort・拡張思考: effort が高い行の比率、出力トークンの多さを見る。誤検知: effort が記録されない古い版は「記録なし」であり「低い」ではない。効果の大きさは情報源で割れている。

## 発生すると大きい（頻度は低い）
- 無人・自動実行（`/loop`・スケジュール・CI）: 人の入力がない等間隔のターン、短い間隔の連続を見る。誤検知: 履歴だけでは人の操作と区別しづらい。利用者談で補う。
- 版に依存するキャッシュ異常: 版別のキャッシュ読み込みの比率が極端に低くないか。現行版で再発するかは未確認。
- 大きなツール結果: tool 結果の文字数の上位、ツール種別・拡張子の分布を見る。一度入ると以後の全ターンで再送される。誤検知: 単発の大きさは文字数でしか分からない。
- MCP 定義の常駐: MCP サーバ数、セッション開始直後のキャッシュ書き込みを見る。ツール検索が既定の版では寄与は小さく、ゲートウェイ経由では大きくなりうる。

## ほか
- transcript 外の消費: cost-state と assistant 集計の差。差が大きければ補助モデルの消費を注記する。
- スキルの使われ方: 冗長なワークフローのスキルの多用、無関係な作業での発火、導入数・description の多さによる常駐量を見る。誤検知: 起動回数は distinct で数える。常駐量は小さいことが多い。
- CLAUDE.md の肥大: 初回ターンのキャッシュ書き込みの大きさ。通常サイズなら寄与は小さい。

これに縛られず発散してよい。

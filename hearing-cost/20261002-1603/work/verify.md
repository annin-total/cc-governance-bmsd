直すべき点は、JSON と食い違う記述 2 件、推測の事実化 3 件、読み手向けの補足 数件。重要度順に並べる。

## 指摘一覧

### 1. 区分: その他（JSON と矛盾）／重要度 高
- 該当箇所: 6 章「調書を作ったセッションは、開始時刻で打ち切って除外した」
- 理由: JSON は `params.exclude_session_given=false`、`coverage.excluded_session_lines=0`、`excluded_session_records=0`。除外は行われていない。さらに `slash_commands` に hearing-cost が 1 回あり、このセッションの 49 行が集計に入っている。
- 直し方: 「調書作成のセッション自体も集計に含まれる（全体に対して小さい）」と書く。除外した事実があるなら、その根拠を JSON 側に出す。

### 2. 区分: 推測の事実化／重要度 高
- 該当箇所: 4 章「Opus（一部で high・xhigh の effort）は品質を重視して選んでいる」、2 章 effort 分布、1 章 4 点目
- 理由: xhigh の 2,647 件は、Agent SDK セッションの API 呼び出し 2,647 件、および Opus 4-7 世代の 2,647 件と同数。xhigh は自動セキュリティレビュー（本人が知らなかったもの）の設定である可能性が高く、本人が選んだ effort とは限らない。本人談との整合がとれていない。
- 直し方: 「xhigh は件数が Agent SDK 起動分と一致しており、自動レビュー由来と推定（確度: 推定）。本人の選択は high までか、聞き直して確認」とする。4 章の該当文は本人に確認した内容だけに絞る。

### 3. 区分: 推測の事実化／重要度 中
- 該当箇所: 3 章「画像ファイル（.png）を扱う操作が 602 回」
- 理由: JSON の拡張子別は .png 1,403 件。602 の出どころが本文に無く、JSON とも合わない（絞り込み条件の違いかもしれないが説明がない）。「デザイン案のスクリーンショット確認」も推定。
- 直し方: 「.png を扱う操作が約 1,400 回（全体、拡張子別の集計）」に直すか、602 の絞り込み条件（最上位セッションに限る等）を一言添える。

### 4. 区分: 推測の事実化／重要度 中
- 該当箇所: 1 章 4 点目「自動起動するレビューが 461 回」
- 理由: 461 は Agent SDK 起動のセッション数。先頭の依頼が脆弱性レビューだったと確認できたのは 459 本（3 章に記載）。1 章では「観測・推定」とあるが、数が 3 章と違い、起動のきっかけ（ファイル変更のたび）は推定なのに断定調。
- 直し方: 「Agent SDK 起動のセッション 461 本（うち 459 本が脆弱性レビュー依頼。ファイル変更のたびの起動は推定）」。確度は「量は観測／起動元は推定」と 3 章に揃える。

### 5. 区分: 推測の事実化／重要度 中
- 該当箇所: 3 章「出力の上位 2 本（計 19%）は、同じ作業の元のセッションと、それを再開したセッション」
- 理由: 2 本は同じプロジェクトだが、JSON 上の性格が違う。1 本は人の入力 0 回・呼び出しの 100% がサブエージェント、もう 1 本は人の入力 47 回・サブエージェント比 11%。単純な複製とは見えない。再開の起動は全体で 1 回しか記録がない。ファイルを開いて確認したとあるが、この食い違いに触れていない。
- 直し方: 確認の根拠を具体化する（何が一致したか）。説明できなければ「同じ作業に当たる可能性が高い（推定）」に弱める。

### 6. 区分: 推測の事実化／重要度 中
- 該当箇所: 5 章 3 点目「長いセッションで…引き継ぎ書を作って新しいセッションに移すと、キャッシュの読み書きが減るかもしれない」、3 章「長いセッション」
- 理由: 上位セッションの呼び出しの 74〜100% はサブエージェント側（最長の 1 本は 89%、サブエージェント 51 体）。重さの主因は、本体の会話が長いことより、サブエージェントの数と実行時間の可能性が高い。「長いセッション」と「サブエージェントの多用」は同じ重さを二重に数えており、2 つの割合を足し合わせると誤読を招く。
- 直し方: 「上の『サブエージェントの多用』と重なる分がある（足し合わせない）」と一言入れる。引き継ぎ案は、本体の会話が長い 1 本（人の入力 47〜86 回のもの）に限定して書く。

### 7. 区分: 推測の事実化／重要度 低
- 該当箇所: 2 章「transcript 外・過小分（推定）」（Opus 約 550 万・Sonnet 約 140 万、Haiku の新規入力 約 690 万）
- 理由: JSON の注記は「再開・分岐の挙動は未確認」。Opus ではキャッシュ書き込みが累積記録のほうが 1,600 万少ないなど、符号が逆の差もある。差を「過小分」と読み切れるのは出力だけで、他は説明が付かない。「cost-state」という語も読み手に通じない。
- 直し方: 「出力の差だけを過小分の目安とし、ほかの種別の差は説明できていない」と書く。「cost-state（Claude Code が残す累積の記録）」と言い換える。

### 8. 区分: その他（確度の付け方）／重要度 低
- 該当箇所: 1 章の各点の「（観測／業務上必要そう）」
- 理由: 確度（観測・推定・利用者談）と判断（必要そう・避けられそう）が 1 つの括弧に混ざっている。3 章は分けて書けているので、1 章も揃えると読みやすい。「避けられそう」の根拠が利用者談だけの項目は、そう明記したほうが安全。
- 直し方: 「確度: 観測／判断: 業務上必要そう（利用者談）」の形式で統一。

### 9. 区分: その他（数字の読み方）／重要度 低
- 該当箇所: 3 章の出力の割合（11%・19% など）
- 理由: サブエージェントの出力は履歴上で過小（2 章に自記）。サブエージェント側が多いセッションの割合は、実際より小さく出ている可能性がある。
- 直し方: 「出力の割合は過小な履歴上の値による」と 3 章冒頭に一言。

### 10. 区分: その他（稼働日の偏り）／重要度 低
- 該当箇所: 2 章「30 日のうち稼働 15 日」
- 理由: 稼働日は 9/8・9/9 と 9/20 以降に偏り、9/10〜9/19 は 0。履歴の欠損か未使用かは JSON から言えない。保持期間は「既定を仮定」で、6 章の「欠損の疑いはない」はその仮定の上の判断。
- 直し方: 「9/10〜9/19 は記録なし（未使用か欠損かは不明）」と一言添える。

## 秘密の混入

## 抽象度・読み手
- 良い点: 数字ごとに「観測／推定／利用者談」と根拠（どのファイルで確認したか）が添えてあり、改善案は断定を避けている。固有名詞は plugin 名（security-guidance）程度で、判断に使える具体性がある。
- 不足: 「effort」「compact」「clear」「hook」の用語説明が無い（キャッシュとサブエージェントだけ説明あり）。ガバナンス課が使うなら、用語に 1 行ずつ足す。
- 不足: 費用の大きさの目安が無い。「合算しない」方針は妥当なので、どのトークン種別が費用に効くかを一言書くと判断しやすい（確定額は不要）。
- 5 章の候補は、効果の大きさの見込みが無い。自動レビューは 1 割前後、サブエージェントのモデル変更は Opus 分担先 13,589 件が対象、と JSON の数字で桁感を添えられる。

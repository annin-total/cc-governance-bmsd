# 画面のスタイル仕様

**画面の見た目に関する決まりは、この文書に閉じる。**他の文書にスタイルの話を書かない。
実体は `server/ccgov/web/static/app.css`（`:root` のトークン）と `server/ccgov/web/templates/_macros.html` にあり、
値や画面ごとの構成はそちらを見る。ここにはコードから読み取れない意図だけを書く。

## 原則

**見るのは管理者だけである。装飾を増やさない。**手間は、**どの数字がどの母集団の、
どの期間のものかを取り違えさせないこと**に使う。ダークモード・印刷用スタイル・グラフ描画・
CSS フレームワーク・ビルド工程・アニメーションは入れない。

## 表

- `<table>` と `<tr>` に属性を足さない規約（`server/CLAUDE.md`）に合わせ、表は `.tbl` で包み、
  要素セレクタで整える
- `nowrap` は数値列と日付列にだけ当てる。`user_email` などの長い値にまで当てると横スクロールが
  常態化する
- 枠と表は内容幅にする。列の少ない表を画面幅に広げると、値の対応が読み取れなくなる
- `data-testid` で行数を検査されている表は、0 件でも表のまま出す

## 数字

- 生の値を出さない。`day` は epoch 日なので、整形は `server/ccgov/web/filters.py` のフィルタに寄せる
- **率は分子・分母を併記する。**分母が 4 種類（イベント数／利用者数／イベントを送った利用者数／
  コストの記録がある利用者数）あり、％だけでは読み分けられない
- **節の見出し直下に期間と母集団を書く。**7 日・14 日・30 日・全期間が 1 画面に混在する
- 仕様上の欠落（相対日 0 の除外、度数 0 のビンを出さないこと）は注記で明記する。書かなければ
  障害に見える
- 同じ値を 2 箇所に出さない

## 色

- 直値を書かず、トークンを使う
- 文字色のコントラストは WCAG AA（4.5:1）を満たす水準に置いてあり、余裕が小さい。
  `--muted` を明るくしない。注記と状態表示の文字を 12px より小さくしない
- 状態表示の修飾子は `ok` / `warn` / `ng` / `neutral` の 4 つだけ。どの状態をどの色に写すかは
  テンプレート側で決める

## 変えるとき

- 表示の形を変えたら、その文字列をテストが検査していないか確かめる。検査していたら同じ強さの
  検査に書き直し、値を差し替えて落ちることまで確認する
- 集計したのに画面に出していない変数は `server/tests/test_web_views_completeness.py` が落とす。
  この検査を迂回しない

## 未検証

- コントラスト比は WCAG 2.1 の式による計算値であり、実機の表示では測っていない
- `sticky` な見出しセルを、縦に長い実データで確かめていない
- 画面幅を狭めたときの折り返しは確かめていない。想定は広い画面である

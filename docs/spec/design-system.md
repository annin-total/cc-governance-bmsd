# 管理画面のデザインシステム

**画面の見た目と部品の決まりは、この文書に閉じる。**他の文書にスタイルの話を書かない。
値・画面ごとの構成・部品の中身は実装を見る。ここにはコードから読み取れない意図と、変えるときの手順だけを書く。

## 原則

- **見るのは管理者だけである。**手間は、どの数字がどの母集団の、どの期間のものかを取り違えさせないことに使う
- **描画はサーバ（Jinja）で行い、JS は操作だけを受け持つ。**JS が無くても全部の一覧が読める。JS は `static/app.js` の 1 本で、
  `data-*` 属性だけを見て動き、値を HTML として組み立てない
- 端末から届いた値は Jinja の自動エスケープに任せる。端末由来の値に `|safe` を使わない。
  文言の書式（`text.fill`）の雛形は `labels.py` の文字列だけで、端末由来の値を雛形にしない
- ダークモード・印刷用スタイル・CSS フレームワーク・ビルド工程・配色の切り替えは入れない

## CSS 変数

`static/tokens.css` の `:root` だけに値を書く。ほかの CSS とテンプレートは変数を参照し、直値を書かない。
例外は、変数にできない幅の境目（メディアクエリ）と、1〜2px の線の太さである。

| 接頭辞・名前 | 役割 |
| --- | --- |
| `--bg` `--card` `--tabs` `--track` `--chip*` | 面の色（地・カードと一覧の枠・分段タブの地・棒の地・増減の印） |
| `--ink` `--ink-2` `--muted` `--rule` | 文字の 3 段と罫線 |
| `--accent` `--accent-2` `--ghost` | 強調と、グラフの系列（直近・2 番目・前の期間） |
| `--ok` `--warn` `--ng` `--neutral`（と `-bg`・`--warn-2`・`--warn-3`） | 状態の 4 区分の色と、その薄い地・段階 |
| `--dept-*` | 部の色（部署の絞り込みのチップとコストの多い課の印）。状態とチップの色と紛れない紫と青緑で、課はその薄い色（`-2`）、不明は `--neutral`。色は 2 つを部の順に回すので、部が 3 つ以上あると別の部が同じ色になる |
| `--fs-*` `--fw-val` `--lh` | 文字の大きさ・大きな数字の太さ・行の高さ |
| `--sp-*` `--cell-y` | 余白の段階 |
| `--r-*` | 角丸 |
| `--card-min-w` `--card-min-h` `--col-*` `--table-max-h` など | 格子の最小幅・列の幅・表の最大の高さ |
| `--shadow-tip` `--tip-max-w` `--link-dim` | ツールチップの影と最大幅・連動で当てていない棒を薄くする度合い |

文字の大きさは `--fs-val` を上限とし、大きな数字の太さ `--fw-val` を 600 より上げない。
文字色は WCAG AA（4.5:1）を `--card` と `--bg` の上で満たす水準に置いてあり、余裕が小さい。`--muted` を明るくしない。
文字の大きさは 5 段に限る。`--fs-*` は使う場所ごとの枠であり、`--fs-xs` と `--fs-sm`、`--fs` と `--fs-label`、`--fs-unit` と `--fs-h2` を
それぞれ同じ段にし、`--fs-h1`・`--fs-val` と合わせた 5 つ以外の大きさを作らない。

## 部品

部品は `templates/components/` の Jinja マクロで、見た目は `static/components.css`、画面の配置は `static/layout.css` にある。

| 部品 | 使いどころ |
| --- | --- |
| 指標カード（`card.html`） | 上段の要点。1 枚に値は 1 つ。注意・要確認のカードだけ右上に状態の印を出し、ほかは（正常も）「一覧」を出す。開くタブの無いカードは押せず、「一覧」も出さない。別の画面のタブを開くカード（概況）は「一覧 →」を出し、押すとその画面へ移ってタブの見出しまで送る（同じ画面のタブを開くカードは「一覧 ↓」） |
| 状態の絞り込み（`card.html` の `state_filter`） | 概況の見出しの右。すべて・注意以上・要確認のチップで、選んだ状態の札の無いカードを薄くする（カードは `data-state` に札の状態を持つ）。JS が出し、JS が無ければ出さない（カードはすべて読める）。区分のチップと同じ見た目にする |
| 分段タブ（`tabs.html`） | 下段の一覧の切り替え。開いているタブは URL の `#タブ:区分` で保持する |
| 絞り込み（`table.html`・`org.html`） | 文字入力・区分のチップ・部署・件数。区分のチップは軸を複数持てる（軸ごとに 1 つ選び、すべての軸に当たる行を出す）。区分は行の `data-tags`（2 つ目以降の軸の id は `軸-区分`）、文字入力は `data-q`、部署は `data-dept`・`data-sec` だけを見る。部署は行の右端の「部署: すべて」のボタンで開くパネルに、部と課を押すと塗られるチップ（角丸は `--r-m`）で並べ、選んだ部に入らない課は押せなくする。状態の区分のチップや分段タブと同じ見た目にしない |
| 並べ替えつきの表（`table.html`・`cells.html`） | 列見出しで並べ替える。値の比較はセルの `data-v`（数値なら数値として比べる）。利用者の列は氏名とその下に小さく「部 · 課」を出し、メールアドレスは `title` にだけ置く（本文に出すのは名簿に無い人だけ）。カードの中の名前は氏名だけにする |
| 状態の印（`marks.html`） | 点＋語。色だけで状態を伝えない |
| 小さなグラフ（`charts.html`） | カードの折れ線・帯・2 本の棒・積み上げ・横棒の並び・区間ごとの前後の棒と、タブの棒グラフ。座標は `web/charts.py` が計算する |
| 期間の切り替え（`period.html`） | 期間のページ（概況・コストと利用者・利用状況）の見出しの右。サーバで描き直すリンク（`?period=`）で、JS は開いているタブ（`#…`）を持ち越すだけ |
| ツールチップ（`app.js`・`components.css` の `.tip`） | カードの小さなグラフの点と、丸めた値に当てると出す。文言はサーバが `data-tip` で渡し、JS が無ければ同じ文言の `title` で読む。下段のタブのグラフには出さない（値は連動した表の行で読む） |
| 月の一覧（`settings.html`） | 「データと設定」の「書き出す」の節。表ではなく `details`/`summary` の格子（`--month-cols`）で、JS なしで開閉する。開いた行は太字にせず薄い地で示し、開いた中身には地を付けず、点線と余白で区切る。`details`/`summary` で開閉する一覧はすべてこの見た目にする |

**固定**: 画面の上端に固定するのはヘッダーだけにする。ページの見出し・絞り込み・期間の帯はページと一緒に流す。固定する帯が増えるほど、表を読む高さが減る。

**一覧の折りたたみ**: 行の多い一覧を折りたたむときは、`constants.py` の `TABLE_FOLD_ROWS` 行まで出し、残りを「さらに表示」で開く。
件数は一覧ごとに `table.html` の `table` の `fold` で変えられ、件数を超える一覧にだけ `data-fold` を付ける。サーバは全行を描き、
JS が超えた行を隠す。JS が無ければ全行が見える。絞り込み中は残った行を、並べ替えた後は今の並びの先頭から数える。

**カレンダー**: 基準日を選ぶ格子と選択肢はサーバで描き（`period.html`・`calendar.css`）、日はリンク（`?asof=` など、`url_for` で作る URL）にする。
開閉は `details` で行い、JS は月の送りと、外を押す・Esc で閉じることだけを受け持つ。日の区分は `data-*` で受け取る。
JS で格子の HTML を組み立てない。JS が無ければ描いた月がすべて並ぶ。日の 3 区分（利用明細あり・取り込み待ち・利用明細なし）は点・斜線・無地で示し、状態の色を使わない。

**グラフと表の連動**: 下段のグラフの棒（`svg g.col`）と表の行（`tr`）に同じ `data-link` を付け、`app.js` の 1 つの処理で双方向に強調する。
`data-key` は表を見分ける属性であり、連動には使わない。連動するグラフを足すときは `screens/tab_charts.py` の `KEY` に、行の値の名前を足す。
区分でグラフも切り替わるタブ（今月のコストの「営業日」「暦日」）は、グラフに `data-when` を付け、「すべて」の無い区分（`Tab` の `chips_all=False`）にする。
今月のコストの既定は営業日である。暦日では、休みの日（週末・国民の祝日・会社の休日）を薄い帯と表の名前で示す。

データに無いものをグラフで補わない。端末ごとの版や受信の日ごとの推移は持っていないので、分布と前後 2 本の棒で表す。
比べる線や基準の値は、`constants.py` の定数と集計結果から出せるものだけを引く。モデルの上限を仮定した「しきい値のトークン数」のような推定の線は引かない。

量を比べるグラフ（2 本の棒・区間ごとの棒）の縦軸は 0 から始める。期間ごとに記録の件数が違う分布は、件数ではなく各期間の中の割合で並べる。
2 本の棒は `terms` の順に並べ、最初（前の期間・適用前）を薄い色にする。

## 画面の型

4 つの画面はすべて同じ型である。

- **上段の要点**: カードを群に分け、群の見出しの横に期間と母集団を書く。カードを押すと、対応するタブ（と区分）が開く
- **下段の一覧**: 分段タブ 1 つにつき、見出し・期間と母集団・（あれば）グラフ・絞り込み・表・注記を置く。表の棒の列（見出しなし）は、表す値の列のすぐ右に置く

群のカードが格子の行を埋めないときは、空けたままにする。埋めるためだけのカードを作らない。

月数の期間（`LONG_MONTHS`）での扱いは画面の定義の `long` で決める（`screens/__init__.py`）。
出さないカードは群ごとに 1 行の注記に名前を並べ、出さないタブは消さずに残して同じ場所に `labels.py` の `NOT_LONG` を書く。

「データと設定」はこの型の外にある。入口は見出し帯の右端に 1 つだけ置き、4 画面のナビに並べない。
節は使う頻度の順（取り込む → 書き出す → 会社の休日）に縦に並べる。

画面ごとの構成は `ccgov/web/screens/<画面>.py` の定義（`Card`・`Tab`・`Col`）にあり、`screens/view.py`・`screens/table.py` が
集計結果と組み合わせて表示用の値にする。集計（合計・平均・状態の判定）は `ccgov/metrics/` と `ccgov/reports/` で行い、定義とテンプレートでは計算しない。

## 文言

- 語は短くする。説明は見出しや値の下に、薄く小さく 1 行で添える
- 用語と表示名（処理段階・項目名・権限モード・設定名・状態・前後・増減）と、画面をまたぐ文言の正本は `ccgov/web/labels.py` である。
  群・カード・タブ・列の文言は、画面の定義が id で引く `ccgov/web/screens/words.py` にある。テンプレートに日本語の用語を書かない
- `command_source` のように端末が記録した値をそのまま並べる列には表示名を付けない（`spec/server.md` の `/activity`）
- 期間の文言（「直近 7 日」など）は定数から組み立てる。数字を文言に書かない
- 数値は丸めて短く出す。しきい値は `filters.py` の `WHOLE_FROM`（金額と小数 1 桁の値を整数にする境）と `TOKEN_K`・`TOKEN_M`・`TOKEN_M_WHOLE_FROM`（トークンの k・M）にある。
  整数にするか・単位を上げるかは、丸めた後の値で決める
- 丸めた値は、正確な値をツールチップと `title` で持つ（`components/values.html` の `exact`）。丸めで何も失わない値は包まない
- 表の列の中では単位と桁を混ぜない。`screens/table.py` の `SCALED` の列は、列の最大から全行の書式を決める。
  0 でなく単位の解像度に満たない値は「<1k」のように書き、0 と区別する
- 生の値を出さない。`day` は epoch 日なので `filters.py` で整形する。表示名の無い値（未知の処理段階など）は値そのものを出す
- 率は分子・分母を併記する。仕様上の欠落（相対日 0 の除外、両方の期間で 0 件の区間を出さないことなど）は注記で明記する
- 記録が 1 件も無い側の件数と割合は「—」にし、0 と書かない。0 は「記録はあるが、その区間には無い」の意味に限る
- 長い値はセルの最大幅（`--cell-max`）で折り返す。区切りの無いキー名は、折り返さないと隣の列に重なる。
  `nowrap` は数値・日付・短いコードの列にだけ当てる

## 設定の効果の画面

- 主に見る数字は設定の作用点（セッションの大きさと自動コンパクトに達した割合）であり、コストより前に置く。
  コストの前後差は時期の変動を含み、施策の効果とは読めない（`decisions/server.md` の「採らないと決めたこと」）ので、
  最後に置く。どのカードも状態の札と増減の印を付けず、適用前と適用後の値を並べるだけにする
- 前後差を効果と読まない注意は、コストのカードの注記と日ごとのタブの注記に書く。0 日目の除外・0 件の区間を出さないことは、
  群の見出しの横とタブの注記に、薄く小さく書く。囲みや強調の色で目立たせない

## 状態

状態は `ok`（正常）・`warn`（注意）・`ng`（要確認）・`neutral`（良し悪しを言わないもの）の 4 つに限る。
判定は `ccgov/metrics/`（`states.py` と各判定）で行い、しきい値は `constants.py`（`NULL_RATE_*`・`ERROR_COUNT_ELEVATED`・
`NON_COMPLIANT_USERS_HIGH`・`NOT_INTRODUCED_ELEVATED`・`CORE_OUTDATED_ELEVATED`・`PLUGIN_OUTDATED_ELEVATED`）に置く。**しきい値はいずれも仮の基準であり、運用で見直す。**
どの状態をどの語に写すかは `labels.py` の `STATE` などにある。

増減のチップは、カードの定義が持つ良し悪しの向きで色を分ける。悪化は要確認の札と同じ色（文字 `--ng`・地 `--ng-bg`）、改善は緑系、
向きの無い差は灰にする。札とは形で見分ける（札は点と語、チップは符号つきの数）。良し悪しの判定は札が受け持ち、チップの色は補助にとどめる。

## 項目を 1 つ足す

1. 値の集計を `ccgov/reports/<画面>.py` の `build` の戻り値に足す（計算は `metrics/` に純粋関数で。単体テストを付ける）
2. カードなら `screens/<画面>.py` の `CARDS` に `Card` を 1 行、文言を `screens/words.py` の `CARD` に 1 項目足す。
   タブなら `TABS` に `Tab` を 1 要素、文言を `TAB` と `COL` に足す。表の列なら `Col` を 1 つ足す。id は画面をまたいで一意にする
3. 見たことのない見た目のセルが要るときだけ、`components/cells.html` に種類を 1 つ足す。数値のセルなら `screens/table.py` の `NUMERIC` にも足す（右寄せと数値の並べ替え）

## 変えるときのテストの注意

- 表示の形を変えたら、その文字列をテストが検査していないか確かめる。検査していたら同じ強さの検査に書き直し、値を差し替えて落ちることまで確かめる
- 集計したのに画面に出していない値は `tests/test_web_views_completeness.py` が落とす（テンプレートの変数と、画面の定義が参照する集計結果の名前の両方）。画面を足したら、この検査の対象にも足す。この検査を迂回しない
- 表は `data-testid` で見分ける。行とセルには絞り込みと並べ替えの `data-*` を付けてよいが、見出し行は最初の `<tr>` に 1 行だけ置く（`tests/conftest.py` の `rows_in_table`）
- 端末から届く文字列を足したら、`tests/test_web_views_escape.py` に場合を足す
- 見た目を確かめるときはサーバを再起動し、JS を切った表示も見る

## 未検証

- コントラスト比は WCAG 2.1 の式による計算値であり、実機の表示では測っていない
- 幅を狭めたとき（メディアクエリの境目より下）の配置は、崩れないことだけを見ており、使い勝手は確かめていない
- `sticky` な見出しセルを、縦に長い実データで確かめていない
- グラフから当てた行を表の枠の中でスクロールして見せる処理は、表の枠が画面の下にはみ出すときの見え方を確かめていない

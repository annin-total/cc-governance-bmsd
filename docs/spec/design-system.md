# 管理画面のデザインシステム

**画面の見た目と部品の決まりは、この文書に閉じる。**他の文書にスタイルの話を書かない。
値・画面ごとの構成・部品の中身は実装を見る。ここにはコードから読み取れない意図と、変えるときの手順だけを書く。

## 原則

- **見るのは管理者だけである。**手間は、どの数字がどの母集団の、どの期間のものかを取り違えさせないことに使う
- **描画はサーバ（Jinja）で行い、JS は操作だけを受け持つ。**JS が無くても全部の一覧が読める。JS は `static/app.js` の 1 本で、
  `data-*` 属性だけを見て動き、値を HTML として組み立てない
- 端末から届いた値は Jinja の自動エスケープに任せる。端末由来の値に `|safe` を使わない。
  文言の書式（`text.fill`）の雛形は `labels.py` の文字列だけで、端末由来の値を雛形にしない
- ダークモード・印刷用スタイル・CSS フレームワーク・ビルド工程・配色の切り替えは入れない

## CSS 変数

`static/tokens.css` の `:root` だけに値を書く。ほかの CSS とテンプレートは変数を参照し、直値を書かない。
例外は、変数にできない幅の境目（メディアクエリ）と、1〜2px の線の太さである。

| 接頭辞・名前 | 役割 |
| --- | --- |
| `--bg` `--card` `--tabs` `--track` `--chip*` | 面の色（地・カードと一覧の枠・分段タブの地・棒の地・増減の印） |
| `--ink` `--ink-2` `--muted` `--rule` | 文字の 3 段と罫線 |
| `--accent` `--accent-2` `--ghost` | 強調と、グラフの系列（直近・2 番目・前の期間） |
| `--ok` `--warn` `--ng` `--neutral`（と `-bg`・`--warn-2`・`--warn-3`） | 状態の 4 区分の色と、その薄い地・段階 |
| `--fs-*` `--fw-val` `--lh` | 文字の大きさ・大きな数字の太さ・行の高さ |
| `--sp-*` `--cell-y` | 余白の段階 |
| `--r-*` | 角丸 |
| `--card-min-w` `--card-min-h` `--col-*` `--table-max-h` など | 格子の最小幅・列の幅・表の最大の高さ |

文字の大きさは `--fs-val` を上限とし、大きな数字の太さ `--fw-val` を 600 より上げない。
文字色は WCAG AA（4.5:1）を `--card` と `--bg` の上で満たす水準に置いてあり、余裕が小さい。`--muted` を明るくしない。
注記と状態の印の文字は `--fs-sm` より小さくしない。`--fs-xs` はグラフの目盛り・凡例・列見出しの補足にだけ使う。

## 部品

部品は `templates/components/` の Jinja マクロで、見た目は `static/components.css`、画面の配置は `static/layout.css` にある。

| 部品 | 使いどころ |
| --- | --- |
| 指標カード（`card.html`） | 上段の要点。1 枚に値は 1 つ。状態を持つカードだけ右上に状態の印を出し、ほかは「一覧」を出す |
| 分段タブ（`tabs.html`） | 下段の一覧の切り替え。開いているタブは URL の `#タブ:区分` で保持する |
| 絞り込み（`table.html`） | 文字入力・区分のチップ・件数。区分は行の `data-tags`、文字入力は行の `data-q` だけを見る |
| 並べ替えつきの表（`table.html`・`cells.html`） | 列見出しで並べ替える。値の比較はセルの `data-v`（数値なら数値として比べる） |
| 状態の印（`marks.html`） | 点＋語。色だけで状態を伝えない |
| 小さなグラフ（`charts.html`） | カードの折れ線・帯・2 本の棒・積み上げ・横棒の並び・区間ごとの前後の棒と、タブの棒グラフ。座標は `web/charts.py` が計算する |

データに無いものをグラフで補わない。端末ごとの版や受信の日ごとの推移は持っていないので、分布と前後 2 本の棒で表す。
比べる線や基準の値は、`constants.py` の定数と集計結果から出せるものだけを引く。モデルの上限を仮定した「しきい値のトークン数」のような推定の線は引かない。

量を比べるグラフ（2 本の棒・区間ごとの棒）の縦軸は 0 から始める。期間ごとに記録の件数が違う分布は、件数ではなく各期間の中の割合で並べる。
2 本の棒は `terms` の順に並べ、最初（前の期間・適用前）を薄い色にする。

## 画面の型

4 つの画面はすべて同じ型である。

- **上段の要点**: カードを群に分け、群の見出しの横に期間と母集団を書く。カードを押すと、対応するタブ（と区分）が開く
- **下段の一覧**: 分段タブ 1 つにつき、見出し・期間と母集団・（あれば）グラフ・絞り込み・表・注記を置く。表の棒の列（見出しなし）は、表す値の列のすぐ右に置く

群のカードが格子の行を埋めないときは、空けたままにする。埋めるためだけのカードを作らない。

画面ごとの構成は `ccgov/web/screens/<画面>.py` の定義（`Card`・`Tab`・`Col`）にあり、`screens/view.py`・`screens/table.py` が
集計結果と組み合わせて表示用の値にする。集計（合計・平均・状態の判定）は `ccgov/metrics/` と `ccgov/reports/` で行い、定義とテンプレートでは計算しない。

## 文言

- 語は短くする。説明は見出しや値の下に、薄く小さく 1 行で添える
- 用語と表示名（処理段階・項目名・権限モード・設定名・状態・前後・増減）と、画面をまたぐ文言の正本は `ccgov/web/labels.py` である。
  群・カード・タブ・列の文言は、画面の定義が id で引く `ccgov/web/screens/words.py` にある。テンプレートに日本語の用語を書かない
- `command_source` のように端末が記録した値をそのまま並べる列には表示名を付けない（`spec/server.md` の `/assets`）
- 期間の文言（「直近 7 日」など）は定数から組み立てる。数字を文言に書かない
- 生の値を出さない。`day` は epoch 日なので `filters.py` で整形する。表示名の無い値（未知の処理段階など）は値そのものを出す
- 率は分子・分母を併記する。仕様上の欠落（相対日 0 の除外、両方の期間で 0 件の区間を出さないことなど）は注記で明記する
- 記録が 1 件も無い側の件数と割合は「—」にし、0 と書かない。0 は「記録はあるが、その区間には無い」の意味に限る
- 長い値はセルの最大幅（`--cell-max`）で折り返す。区切りの無いキー名は、折り返さないと隣の列に重なる。
  `nowrap` は数値・日付・短いコードの列にだけ当てる

## 設定の効果の画面

- 上段の最初の群は「設定は働いているか」（コンテキストの大きさの分布）であり、主に見る数字はここに置く。
  コストの前後差は時期の変動を含み、施策の効果とは読めない（`decisions/server.md` の「採らないと決めたこと」）ので、
  後ろの群に置き、増減の印を付けない。前後の値を並べるだけにする
- 前後差を効果と読まない注意・0 日目の除外・0 件の区間を出さないことは、群の見出しの横とタブの注記に、薄く小さく書く。
  囲みや強調の色で目立たせない

## 状態

状態は `ok`（正常）・`warn`（注意）・`ng`（要確認）・`neutral`（報告停止など、良し悪しを言わないもの）の 4 つに限る。
判定は `ccgov/metrics/`（`states.py` と各判定）で行い、しきい値は `constants.py`（`NULL_RATE_*`・`ERROR_COUNT_ELEVATED`・
`NON_COMPLIANT_USERS_HIGH`・`NOT_INTRODUCED_ELEVATED`）に置く。**しきい値はいずれも仮の基準であり、運用で見直す。**
どの状態をどの語に写すかは `labels.py` の `STATE` などにある。

## 項目を 1 つ足す

1. 値の集計を `ccgov/reports/<画面>.py` の `build` の戻り値に足す（計算は `metrics/` に純粋関数で。単体テストを付ける）
2. カードなら `screens/<画面>.py` の `CARDS` に `Card` を 1 行、文言を `screens/words.py` の `CARD` に 1 項目足す。
   タブなら `TABS` に `Tab` を 1 要素、文言を `TAB` と `COL` に足す。表の列なら `Col` を 1 つ足す。id は画面をまたいで一意にする
3. 見たことのない見た目のセルが要るときだけ、`components/cells.html` に種類を 1 つ足す。数値のセルなら `screens/table.py` の `NUMERIC` にも足す（右寄せと数値の並べ替え）

## 変えるときのテストの注意

- 表示の形を変えたら、その文字列をテストが検査していないか確かめる。検査していたら同じ強さの検査に書き直し、値を差し替えて落ちることまで確かめる
- 集計したのに画面に出していない値は `tests/test_web_views_completeness.py` が落とす（テンプレートの変数と、画面の定義が参照する集計結果の名前の両方）。画面を足したら、この検査の対象にも足す。この検査を迂回しない
- 表は `data-testid` で見分ける。行とセルには絞り込みと並べ替えの `data-*` を付けてよいが、見出し行は最初の `<tr>` に 1 行だけ置く（`tests/conftest.py` の `rows_in_table`）
- 端末から届く文字列を足したら、`tests/test_web_views_escape.py` に場合を足す
- 見た目を確かめるときはサーバを再起動し、JS を切った表示も見る

## 未検証

- コントラスト比は WCAG 2.1 の式による計算値であり、実機の表示では測っていない
- 幅を狭めたとき（メディアクエリの境目より下）の配置は、崩れないことだけを見ており、使い勝手は確かめていない
- `sticky` な見出しセルを、縦に長い実データで確かめていない

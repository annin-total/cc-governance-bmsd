## 4. テストの方針

**テストを書くのは「壊れたときに実害が出る 4 領域」に限る。** それ以外は往復テスト 1 本と実機確認で担保する。

| 領域 | 計画 | 壊れたときの実害 | 進め方 |
| --- | --- | --- | --- |
| 契約からの DDL / INSERT 列の生成 | [1] | 列がずれるとサーバが起動しない。気づかなければ全端末のイベントが失われる | TDD |
| hook 入力からの値の抽出（`dig` / `coerce`） | [2] | 上流のキー変更で列が静かに NULL になる | TDD（実サンプルを fixture に使う） |
| `settings.json` の読み書き | [3] | **利用者の既存設定を壊す。端末側で実害が出る唯一の箇所** | TDD |
| CSV 取込の冪等化 | [6] | コストが二重計上され、効果測定の曲線が施策と無関係に跳ねる | TDD |

| 領域 | 担保の方法 |
| --- | --- |
| 受信から集計まで | 往復テスト 1 本（[4]）。NDJSON を POST し、集計が期待値を返すところまでを 1 本で通す |
| 集計クエリ | 既知のデータを入れて期待値と突き合わせる（[5]）。**重複行を含めた検証を必ず入れる** |
| 画面のテンプレート | 目視と、「クエリが返す行数と画面の行数が一致する」検査（[5]） |
| hook の登録と発火 | 実機で `claude -p` を走らせて確認（[2] [3]） |
| デプロイ | 実際に 1 回通す（[8-A]） |

テストの実行基盤は **pytest**。リントとフォーマッタは **ruff**。どちらも `requirements-dev.txt` に分離し、**本番の直接依存は flask / waitress / pymysql の 3 つのまま保つ**（設計書 §4.3）。

**テストは `cc-governance-bmsd/tests/` に置く。** 端末側は `tests/client/`、それ以外は直下。サーバのディレクトリにも `governance/` にも置かない。前者はフレームワークの import を検査する `grep` の対象から外すため、後者は**配布物にテストが混入しないようにする**ためである（`governance/` はそのままマーケットプレイスへ差し込まれる）。

hook 入力の実サンプルを fixture に使うときは、**自由文の値をセンチネルに置換した写し**を `tests/fixtures/` にコミットする。生の収集データは git に入れない。置換によってキーの構造は保たれるため抽出のテストに使え、同時に「センチネルが出力のどこにも現れない」という形で流出の回帰テストが書ける。

## 5. 共通の制約

すべての計画に適用される。各計画の要件はこれを暗黙に含む。

| 項目 | 値 |
| --- | --- |
| サーバの Python | **3.9 固定**。3.10 以上の構文・標準ライブラリを使わない |
| サーバの待受 | `waitress-serve --listen=0.0.0.0:5000 app:app` |
| 公開形態 | サブパス配下。`BASE_PATH` を `SCRIPT_NAME` として与える |
| 永続領域 | `/mnt/data` |
| 本番の直接依存 | flask / waitress / pymysql の 3 つのみ。**推移的依存を含めて `==` で完全固定する**（`requirements.txt` は 9 行になる） |
| 開発依存 | pytest と ruff。`requirements-dev.txt` に分離する |
| 1 ファイルの行数 | **200 行以内**を目安とする |
| 契約の正本 | `governance/hooks/contract.py` ただ 1 つ。複製しない |
| フレームワークの import | `app.py` ただ 1 ファイル。他のファイルに現れないことを `grep` で確かめる |
| SQL を書く場所 | `queries_events.py` / `queries_policy.py` / `ingest.py` / `csv_import.py` / `db.py` のみ。画面とルーティングに SQL を書かない |
| DB の方言 | 主キーなし・日時型なし・UPSERT なし・JSON 型なし。プレースホルダは `?` で書く |
| 件数の数え方 | `COUNT(DISTINCT event_id)`。分布と率の**分子も**必ず通す。`day` で絞らない全期間集計を画面に置かない |
| 収集する値 | 契約に名指しされたキーパスのみ。`prompt` / `tool_response` / `message` に触れない |
| hook の終了コード | 常に `exit 0`。標準エラーにも出さない |
| ドキュメントの言語 | 日本語。ファイル名・関数名・変数名は英語 |
| 端末側の依存 | **標準ライブラリのみ。** 配布物に `pip install` を要求しない。HTTP は `urllib.request` |

## 5.1 計画をまたいで一致させる値

複数の計画が同じ名前・同じ値を使う。**片方だけを変えると静かに壊れる。**

| 値 | 決め | 関係する計画 |
| --- | --- | --- |
| 契約が持つもの | 5 定数（`HOOK_FIELDS` / `EXTRA_COLUMNS` / `POLICY` / `POLICY_COLUMNS` / `CSV_COLUMNS`）と 4 関数（`dig` / `coerce` / `to_day` / `ddl`） | [1] [2] [3] [4] [5] [6] |
| 受信トークンのヘッダ名 | `X-Ingest-Token` | [2] [4] |
| `/ingest` の応答ボディ | `{"stored": n, "dropped": n}` | [4] |
| 効果測定の対象 `provider` | `aws-bedrock`（他社は `openai` として別行に出る） | [5] [6] |
| `apply_result` の値域 | `already_ok` / `applied` / `skipped_conflict` / `parse_failed` / `write_failed` | [3] [5] |
| `policy_state` の値の文字列表現 | 契約の `coerce(value, "VARCHAR(255)")`。**真偽値は小文字の `true` / `false`** | [1] [3] [5] |
| 直近を見る窓 | 健全性・配布物の比較は **7 日**、離脱端末の判定は **14 日**、その走査範囲は **30 日** | [5] |
| コンテキスト分布のビン幅 | 20,000 トークン | [5] |
| `POLICY` の項目 | `env.CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` と `extraKnownMarketplaces.cc-marketplace-governance-bmsd.autoUpdate` の 2 つ | [1] [3] [5] [7] |
| CSV 取込の起動 | ボタンは 1 つ。押すたびに全ファイルを取り直す。未取込判定を持たない | [5] [6] |
| 本番の依存 | 直接依存 3 つ、推移的依存を含めて 9 パッケージ。`markupsafe` だけがコンパイル済み拡張を含む | [8] |

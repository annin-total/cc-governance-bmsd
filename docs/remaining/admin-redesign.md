# 管理画面の作り直し

管理画面を下の構成に作り直す。判断は `../decisions/server.md` の「管理画面のアクセス制御」「利用者単位の分析」「期間の終わりと基準日」、見た目の決まりは `../spec/design-system.md` にある。
ページ・群・カード・タブの名前は目安であり、画面の語の正本は実装（`labels.py`・`words.py`）である。

**完了条件**: 下の表のページがすべて実装され、`../spec/server.md` の「管理画面」の節がこの構成で書き直されている
（ページごとの問い・群の期間と母集団・カード・タブの表として。今の 4 画面の記述は消す）。あわせて、実装で古くなる次の記述を直す。

- `../spec/system.md`: 管理画面の数
- `../decisions/server.md`: 受け入れている限界の「版の分布」「`/` 概況は最も重い画面」
- `../spec/design-system.md`: 「画面の型」（4 画面・概況の見出し）と「部品」の期間の切り替え、データと設定の入口
- `../guide/onboarding.md`・`../guide/e2e.md`・`../guide/release.md`・`../guide/deploy-aip.md`: `/policy`・`/assets`・概況を指す箇所

## 共通

- ヘッダー: アプリ名「Claude Code 管理」・概況・コストと利用者・利用状況・設定の適用状況・設定の効果・収集の状態・サマリー・データと設定。ヘッダーだけを固定する
- 期間のページ（概況・コストと利用者・利用状況・設定の効果）: 期間のタブ（7 日・28 日・12 か月）と期間の表示「09/10〜09/16 ▾」。期間は利用明細の最終日で終わる。
  表示を押すとカレンダー（左に「最新」「1 つ前の期間」「先月末」「前の月末」、右に月の格子）。日は 利用明細あり・取り込み待ち（押せない）・利用明細なし の 3 区分で、
  選べるのは利用明細の最初の日の 27 日後〜最終日。基準日は URL でページをまたいで保つ
- 状態のページ（設定の適用状況・収集の状態）: 帯は「MM/DD 時点」で押せない
- 利用明細の最終日が今日の `CSV_STALE_DAYS` 日前以前なら、期間の表示の横に小さく警告を出し、押すとデータと設定へ移る
- 状態の札（注意・要確認）を判定を持つ全カードに出し、ページ上部に「すべて・注意以上・要確認」の絞り込み（該当しないカードを薄くする）
- 増減のチップは良し悪しの向きを持つ。12 か月は前の期間と比べず、札もチップも出さない
- 「不明」の行・利用者に札を付けない（名簿に無い利用者の、利用者ごとのコストと基準を超えた利用者の状態の札を外すかは未決。カタログの画像は札を出している）
- 時系列のグラフは 7 日・28 日で前の期間を同じ軸に並べる（前＝薄い、直近＝濃い）。カードのグラフには値のツールチップ

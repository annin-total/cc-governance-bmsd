## 1. 実機で確認済みのこと

ここに挙げるものは**確認済みであり、繰り返さない。**（macOS / Claude Code 2.1.278）

| 事項 | 確認したこと |
| --- | --- |
| hook の発火と収集 | `UserPromptSubmit` / `PostToolUse` / `Stop` が発火し、キューに行が積まれる。列は `kind` と契約の 19 列ちょうどで、本文由来のキーは 1 つも無い |
| コンテキスト量の取得 | 実セッションの `Stop` で transcript 末尾からの算出が機能する |
| 無効化スイッチ | `CC_GOVERNANCE_DISABLE=1` でキューが作られない |
| hook が画面を汚さないこと | トレースバック等の出力は 0 件。中断シグナルを送っても終了コード 0・標準エラー空 |
| 設定の自動適用 | 値の無い端末で適用され、2 回目の起動で前の値が記録される。既存のキーが保たれ、入れ子のエントリが無ければ作らずに記録だけ残す |
| お知らせの表示 | セッション開始時に接頭辞つきで表示される。接頭辞が付くのは 1 行目だけで、未読 2 件が空行 1 つ区切りの 1 つのメッセージになる。日本語 614 字はファイルへ退避されずそのまま出る |
| 本人の環境が汚れないこと | このプラグインの痕跡が利用者の設定ディレクトリに 1 件も残らない |
| 受信とサブパス | 実サーバ（waitress + curl）で、非 ASCII のトークンの一致・不一致、毒の行の破棄、4 画面の応答を確認済み |
| CSV 取込の冪等性 | 実ファイルで 3 回押しても行数と合計が不変。BOM・書式違い・権限なし・無関係な CSV の混在を同時に置いても、成功と失敗が区別されて表示される |

## 2. 社内の環境でしか確かめられないこと

### 端末の Python の可用性

**未確認。** 開発機から社内端末に到達できない。

**確かめること** — 配布対象端末の構成の種類ごとに 1 台で `python3 --version` が応答すること。

**不合格だったとき** — hook の起動コマンドを、解決できるインタプリタの絶対パスにするか、
Claude Code に同梱される実行環境を使う形にする。
どちらも取れない構成があれば、その構成を測定の対象外とし、**分母から除いた事実を画面に出す。**
除外を黙って行うと準拠率が実態より良く見える。

**検知の手段は既にある** — `python3` が解決できない端末は、適用状況画面の未導入者一覧に必ず現れる。

### MySQL 接続に関する一式

**すべて未検証。** SQLite でしか確認していない。
手順は [deploy.md](deploy.md) の「MySQL 接続時の初期化を確かめる」にある。

| 事項 | 確かめること |
| --- | --- |
| `sql_require_primary_key` の値 | 有効なら主キーなしテーブルの作成が拒否される |
| DDL の適用と列の突き合わせ | 起動時の初期化が通ること |
| 統計情報の更新 | MySQL で動くこと |
| ドライバの戻り値の列位置 | `SHOW INDEX` の `Key_name`、`SHOW COLUMNS` の `Field` |
| プレースホルダ変換と複数行 INSERT | 置換の結果が実接続で通ること。部分失敗の粒度 |
| 置換後の文字列 | 符号化できない文字を置換した値が保存できること |
| `INTEGER` の桁 | 2038 年以降の `ts` が格納できないこと（桁の事実は `../knowledge/db-and-framework-facts.md`） |
| 初期化の失敗時のロールバック | SQLite では DDL が暗黙コミットのため確認できない |
| インデックスキー長 | 接続先の行フォーマットで作成が通ること |
| 8.0 系での挙動 | `sql_require_primary_key` と `CREATE INDEX IF NOT EXISTS` の扱い |

### 実行基盤に関する一式

**すべて未検証。** 手順は [deploy.md](deploy.md) にある。

- サーバの起動時間（依存の install を含む）。**端末側の送信タイムアウト 60 秒の妥当性がこれで決まる**
- アイドル時にコンテナが停止するか
- 前段が公開サブパスを剥がすか剥がさないか
- 依存の install に使うコマンドが `pip` か `pip3` か
- **リクエストボディの上限。**前段の `client_max_body_size` が端末の送信 1 回分より小さいと、
  大きい spool ファイルが**永久に送信できないまま破棄される**。端末は仕様どおり静かに失敗するため気づけない

### 配布経路に関する一式

**すべて未検証。** 手順は [distribution.md](distribution.md) にある。
自動更新が端末へ降りるまでの時間は隔離環境で 1 度だけ観測しており（15 分 23 秒）、
**この間隔が固定かどうかは未検証である。**

## 3. 実データが溜まってから測ること

いずれも**未測定**であり、壊れても検知できるか、後から直せる。

- 年間規模（1,500 万行）での集計時間。上限密度の 30 日窓が 1.3 秒前後であることは測ってある
- MySQL で被覆インデックスが選ばれるか、統計情報の更新頻度が足りるか
- 統計情報の更新そのものの所要時間。取込ボタンの応答時間に上乗せされる

## 4. 検査の網が無いところ

いずれも**実装は正しいことを確認済みだが、回帰を検知するテストが無い。**
境界のデータを共有フィクスチャへ足せば塞がる。

| 事項 |
| --- |
| 準拠の前後を分ける境界（準拠開始日ちょうどの日） |
| 未導入者の判定における 30 日の窓 |
| 途絶えと見なす日数の境界 |
| 同一の `ts` を持つ行のタイブレーク（実装側も未定義。→ `../decisions.md`） |

## 5. 観測されていない値

| 事項 | 現況 |
| --- | --- |
| サブエージェント由来の識別子の実値 | サブエージェント内のツール呼出にのみ付く。手元の採取では値が出ていない。**抽出は契約のキーパスを回すだけで hook の種類に分岐しないため、値が来れば同じ経路で列に入る** |
| 自動圧縮による `PreCompact` | 値の語彙を検査しないため、実装上の影響は無い |
| 長期にわたるオフライン時の spool の実分布 | 上限での破棄はテストで確かめてある。実運用での分布は観測しない |
| HTTPS の前段の背後でリダイレクトが平文へ降格しうるか | **未検証。** 末尾スラッシュだけが違う URL を作らない設計により、この経路自体を持たない |

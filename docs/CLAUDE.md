# CLAUDE.md - docs

`docs/` 配下を書き換えるときの規約の正本。

## 構成

```
docs/
  CLAUDE.md      ← この文書。規約の正本
  design.md      ← 設計の正本。何を作るかを定める
  release.md     ← 運用手順
  onboarding.md  ← 導入案内
  knowledge/     ← 外界の事実。完全独立
  decisions.md   ← 現在のコードがなぜそうなっているかの記録
  remaining/     ← まだ終わっていない作業
```

## 参照規約

| 文書 | 参照してよい先 | 参照してよい元 |
| --- | --- | --- |
| `knowledge/` | **何も参照しない（完全独立）** | 誰でも |
| `design.md` | `knowledge/` | 誰でも |
| `release.md` / `onboarding.md` | `design.md` / `knowledge/` | 誰でも |
| `decisions.md` | 上のどれでも | **この `docs/CLAUDE.md` だけ** |
| `remaining/` | 上のどれでも | **この `docs/CLAUDE.md` だけ** |

`decisions.md` と `remaining/` は互いを参照してよい。どちらも削除してよい側であり、
片方が消えるときにもう片方も同時に見直せる。

参照とは、リンク・ファイル名の記載・章番号の記載のすべてを指す。
ドキュメントだけでなく、**実装コード・設定ファイル・コミットメッセージにも同じ規約が及ぶ。**

## なぜこの規約があるか

**削除してよい文書を削除するとき、直すべき箇所が 1 か所に閉じるようにするためである。**

`decisions.md` と `remaining/` は役目を終えたら消える文書である。
`remaining/` は作業がすべて片付けばディレクトリごと消え、`decisions.md` はいつ消してもよい。
他の文書から参照されていると、**参照が壊れるために消せなくなる。**
参照してよい元をこの文書 1 か所に限ることで、削除の影響はこの文書の書き換えだけで済む。

`knowledge/` が完全独立なのは、**外界の事実は、定義上どこも参照する必要がないからである。**
我々の設計が変わっても真であり続けるものだけを置くので、設計の側を指す必要が生じない。
参照しないから、誰からでも安全に参照できる。

## 文書記述ルール

1. **本文に修正の経緯を残さない。** 「〜に変更した」「当初は〜だったが」といった記述を本文に書かない。
   **現時点で正しいことだけを、初めからそう設計されていたかのように書く。**
2. **更新時は、経緯・変更履歴を末尾の「改訂履歴」章に分離・集約する。**
3. **旧実装の固有名詞・検証の経緯を持ち込まない。** 特定のファイル名・検証番号・過去の判断への言及を書かない。
4. **事実と推測を区別する。** 未検証のことは「未検証」と明記する。
5. 日本語で書く。ファイル名・関数名・変数名など英語が適する箇所は英語を使う。

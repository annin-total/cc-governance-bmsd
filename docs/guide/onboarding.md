# 導入案内と段階的な展開

利用者へ送る導入案内の雛形と、案内を 2〜3 回に分けて日付をずらす進め方を記す。

## 1. 案内を送る前に（全端末）

- **Claude Code 本体は 2.1.287 以上を求める。**お知らせは mod が出し、公式はこの版から mod を既定で有効とする。
  実測では 2.1.286 でも読み込まれたが、2.1.283・2.1.278 では読み込まれず（`../knowledge/claude-code-behavior.md`）、収集と設定の適用は動くがお知らせは表示されない。
  公式の記述に沿って 2.1.287 を最低の版にする
- **お知らせはターミナルの Claude Code で表示する。**VS Code 拡張には表示されない。Desktop は対象外で、確かめていない（`../decisions/plugin.md`）
- **社内リポジトリは ssh の scp 形式（`git@<ホスト>:<パス>`）で登録する。**`ssh://`・`file://`・`git://` の形は受け付けられない
  （`../knowledge/claude-code-behavior.md`）。社内の環境では https の URL での登録に応答が返らなかった（原因は未特定）。
  利用者の ssh の鍵が社内リポジトリに登録されていることが前提になる。ssh のポートが 22 でなければ、利用者の `~/.ssh/config` に
  `Host <別名>` と `HostName`・`Port` を書いてもらい、`<ホスト>` にその別名を入れる

## 2. 案内を送る前に（`python3`）

プラグインの記録と設定の適用は `python3` というコマンドで動く。macOS でも Windows でも、このコマンドが無ければ**記録と設定の適用は画面にエラーを出さずに止まる。**
お知らせは `python3` を使わずに表示されるので、導入できたように見えたまま止まり、利用者の画面からは区別できない。そのため、次の確認は全端末で導入手順の一部であり、省略できない。

- ターミナルで `python3 --version` が応答し、版が 3.9 以上であることを確認してもらう
- Windows の標準的な Python のインストーラでは、この名前のコマンドが入らないことがある。その場合は Microsoft Store 版の Python を入れると使えるようになる
- **確認できない場合は導入を進めず、情報システム部門に連絡する**

## 3. 案内文の雛形

利用者へそのまま送れる文面である。`<...>` の箇所を差し込んで使う。

---

**件名: Claude Code ガバナンスプラグインの導入について**

お疲れ様です。Claude Code の利用状況の把握と設定の一元管理のため、社内配布のプラグインを導入してください。

**事前確認**

ターミナルで次を実行し、版が 2.1.287 以上であることを確認してください。古い場合は先に Claude Code を更新してください。

```
claude --version
```

次も実行し、3.9 以上の版が表示されることを確認してください。応答しない・版が古い場合は、導入を進めずに `<連絡先>` へご連絡ください。

```
python3 --version
```

**送信に使うメールアドレスの確認**

利用状況は会社のメールアドレスで AI Gateway の記録と突き合わせます。ターミナルで次を実行し、会社のメールアドレスが表示されることを確認してください。

```
git config --global user.email
```

何も表示されない・個人のアドレスが表示される・git が入っていない場合は、`~/.claude/settings.json` の `env` に `"CC_GOVERNANCE_USER_EMAIL": "<会社のメールアドレス>"` を書いてください。一致しないと、導入済みでも未導入として扱われます。

**導入手順**

Claude Code の中で、次の 2 つを順に実行してください。

```
/plugin marketplace add git@<ホスト>:<パス>
/plugin install governance@cc-marketplace-governance-bmsd
```

**導入できたことの確認**

1. `/plugin` の一覧に `governance` が版番号つきで現れることを確認してください
2. ターミナルで Claude Code を開き直し、入力欄の上の枠にお知らせが表示されることを確認してください（VS Code の拡張機能の画面には表示されません）

お知らせは、それぞれの「既読にする」を押すまで、開き直すたびに表示されます。押し方は枠の先頭に表示されます。
ctrl+x に続けて tab を押すと 1 件目の「既読にする」が選ばれるので、Enter を押してください。tab で次のお知らせのボタンへ移ります（上下の矢印キーは枠の中をスクロールします）。クリックで押せる画面もあります。Esc で入力欄に戻ります。

枠が表示されないときは、次を確かめてください。

- `claude --version` が 2.1.287 以上か
- 起動したフォルダを信頼したか（初回に出る確認で信頼を選ぶまで表示されません）
- お知らせをすべて既読にしていないか（新しいお知らせが無ければ、表示されないのが正常です）

お知らせの表示は、記録と設定の適用が動いていることを示しません。そちらは管理者がサーバ側で確かめます。

**収集する項目**

Claude Code の利用状況（利用日時・利用したツールの種別・セッションの単位・コンテキストのトークン数・導入している設定の値など）を、会社のメールアドレスと端末名とともに収集します。管理者は利用者ごとの設定の適用状況を画面で確認します。プロンプトの本文、ツールの応答内容、会話の内容は一切収集しません。

**更新が届かない場合**

通常は自動で更新されますが、環境によっては手動での更新が必要です。その場合は次の 2 つを両方実行してください（1 つ目だけでは更新されません）。

```
claude plugin marketplace update cc-marketplace-governance-bmsd
claude plugin update governance
```

**困ったときの連絡先**

`<連絡先>`

## 4. 導入していない人を見つける

案内を送った後、管理画面 `/policy` の未導入者一覧を見る。AI Gateway の利用記録には現れるのに、どの端末からも直近に報告が届いていない人が並ぶ（CSV を取り込んでいる間だけ。`../spec/server.md`）。「案内を送る前に（`python3`）」の確認で止まっている端末や、導入したが `python3` が無く記録が届かない端末も、その人のほかの端末から届いていなければここに現れる。**記録と設定の適用が動いたことは、利用者の画面ではなくこの一覧で確かめる。**

一覧に残っている人には、案内が届いていないか、事前確認で止まっているかのどちらかなので、個別に声をかける。案内を送るたびにこれを繰り返す。

## 5. 案内を分けて送る

全員に同じ日に案内すると、施策の効果と、同じ時期に起きた他の変化（モデルの変更・料金改定・繁忙期・社内アナウンスなど）が区別できなくなる。**案内する日をずらし、準拠開始日を散らす。**散らしても同じ時期の変化は打ち消されない。配布の仕組みは変えず、案内する相手と日付を分けるだけでよい。

- **2〜3 回に分け、1〜2 週間ずつずらす**
- **部署を横断して分ける。**同じ部署の人が別々の回に入るようにする。部署ごとに分けると、部署の業務の違いと区別できなくなる
- 各回の人数は大きく偏らせない
- 決めた案内日を前後させない。ずれた場合は、実際に送った日を記録する

## 6. 記録欄

**案内した日付だけ**を、送った時点で記入し、後から書き換えない。誰がどの回かの名簿は作らない（効果の測定には使わず、異動や入退社で古くなるだけである）。

| 案内日 | 案内した範囲の呼び名 | おおよその人数 |

## 7. 効果測定を読むときの注意

案内日はずらせても、実際にいつ導入するかは利用者が決める。早く導入する人と遅い人の違いは効果の数字に混ざったまま残る。

コストの前後差は施策の効果ではない（`../decisions/server.md` の「採らないと決めたこと」）。施策が効いたかは、コンテキスト分布が準拠の前後でずれたかで見る。

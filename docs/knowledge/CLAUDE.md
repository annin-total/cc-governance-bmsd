# CLAUDE.md - knowledge

`knowledge/` 配下を書き換えるときの規約。

## 判定の基準

**この記述は、我々のリポジトリが消滅しても真であり続けるか。**

真であり続けるならここに置く。そうでないなら置かない。判定はこの 1 つだけで行う。

**我々の設計・実装・採否・使用状況には、一切言及しない。**
「使っている／使っていない」「採る／採らない」は上流の性質ではなく我々の状態であり、
設計が変われば書き換えが要る。書いた時点で独立性を失う。

## 置くもの・置かないもの

| 置く | 置かない |
| --- | --- |
| X が存在する | X を使っていない・登録していない |
| X はこう振る舞う | X は採らない・今回は見送る |
| X を測るとこうなる | 我々の契約・設計・実装がどうなっているか |
| X には Y という制約がある | だから我々は Z にした（理由・判断） |
| | まだ終わっていない作業 |
| | 今の実装が受け入れている限界 |

右列はいずれも我々の状態であり、リポジトリが消滅すれば意味を失う。

## どの文書に置くか

**事実の性質で決まる。**文書は次の 4 つの性質に対応する。

| 性質 | 例 |
| --- | --- |
| 上流に実在する項目の目録 | キー・hook・環境変数 |
| 上流の振る舞い | 発火の条件、変更が効くタイミング、引き継がれるもの |
| 測って出た数字 | 所要時間・容量・分布。**測定条件を必ず添える** |
| 測らなくても決まっている仕様 | 型の幅、上限、フレームワークの挙動 |

**数字が出てきたら数字の文書へ、測らずに決まっていることは仕様の文書へ。**
どちらにも書きたくなったら、片方に置いて他方には書かない。

## 参照規約

**ここから外を参照しない。**他の文書へのリンクも、他の文書の章番号も書かない。
外界の事実は、定義上どこかを参照する必要がない。
**配下の文書どうしも、番号や章で互いを指さない。**

**参照しないから、誰からでも安全に参照してよい。**

## 追記の作法

1. **1 項目は数行。**事実と、それがいつ効くかだけを書く。背景の説明も再現手順も書かない。
2. **確認したものは、いつ・どの版で確認したかを添える。**
   確認していないものは **「未確認」「未検証」「推測」と明記する。**事実と推測を同じ文に混ぜない。
3. **章立ては変えず、既存の表に行を足す。**新しい章が要ると思ったら、まず既存のどれかに入らないかを見る。
   新しい文書を足したときは `README.md` の一覧にも行を足す。ファイル名に採番の接頭辞を付けない。
4. 機微情報（実在のメールアドレス・ホスト名・社員 ID）を書かない。

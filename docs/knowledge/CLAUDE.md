# CLAUDE.md - knowledge

`knowledge/` 配下を書き換えるときの規約。

## 置くもの・置かないもの

**置くのは外界の事実だけである。**我々の設計が変わっても真であり続けるものを指す。

| 置く | 置かない |
| --- | --- |
| DB・フレームワーク・言語・OS の仕様として決まっていること | どう作るか（設計の正本が持つ） |
| 実測値（性能・容量・所要時間） | なぜそう決めたか |
| 実在が確認できたが、今回は使わないもの | まだ終わっていない作業 |
| 条件が変われば検討しうる選択肢 | 今の実装が受け入れている限界 |

右列はいずれも**我々の設計に依存する**ため、設計が変わると嘘になる。ここには置かない。

**「使っていない」は書いてよいが、「なぜ使わないか」は書かない。**
前者は上流に何が在るかの事実であり、後者は我々の判断である。

## どの文書に置くか

**事実の性質で決まる。**文書は次の 5 つの性質に対応する。

| 性質 | 例 |
| --- | --- |
| 上流に在るが、この実装が使っていないものの目録 | キー・hook・環境変数 |
| 上流の振る舞い | 発火の条件、変更が効くタイミング、引き継がれるもの |
| 測って出た数字 | 所要時間・容量・分布。**測定条件を必ず添える** |
| 測らなくても決まっている仕様 | 型の幅、上限、フレームワークの挙動 |
| 条件を満たせば開く選択肢 | 開く条件とセットで書く |

**数字が出てきたら数字の文書へ、開く条件が要るなら選択肢の文書へ。**
どちらにも書きたくなったら、片方に置いて他方には書かない。

## 参照規約

**ここから外を参照しない。**他の文書へのリンクも、他の文書の章番号も書かない。
外界の事実は、定義上どこかを参照する必要がない。
**配下の文書どうしも、番号や章で互いを指さない。**

**参照しないから、誰からでも安全に参照してよい。**

## 追記の作法

1. **1 項目は数行。**事実と、それがいつ効くかだけを書く。背景の説明も再現手順も書かない。
2. **確認したものは、いつ・どの版で確認したかを添える。**
   確認していないものは **「未確認」「未検証」「推測」と明記する。**事実と推測を同じ文に混ぜない。
3. **章立ては変えず、既存の表に行を足す。**新しい章が要ると思ったら、まず既存のどれかに入らないかを見る。
   新しい文書を足したときは `README.md` の一覧にも行を足す。
4. 機微情報（実在のメールアドレス・ホスト名・社員 ID）を書かない。

# 将来の選択肢

今は使わない。**「いつ検討に値するか」の条件**を満たしたときだけ開く。

| 選択肢 | 中身 | いつ検討に値するか |
| --- | --- | --- |
| `env.FORCE_AUTOUPDATE_PLUGINS` | 本体の自動更新を抑止している端末でも、プラグインの更新だけを生かす保険。hook プロセスまで値が届くことは確認したが、**本体の入れ替えを起こす効果は観測できていない** | 本体の自動更新を抑止している端末が社内に実在すると分かり、かつその端末でプラグインの版が古いまま止まったとき |
| マネージド設定による配布 | 管理者が配る層（`managed-settings.json`）でマーケットプレイスと施策を配る。利用者の `settings.json` より優先される | 端末の `~/.claude/settings.json` への書き込みが上位の設定に負けて効かない端末が出たとき、または導入そのものを利用者任せにできなくなったとき |
| `model` によるモデル別の層別 | `SessionStart` の `model` を文字列のまま保存して `GROUP BY` する。率を出さないので名寄せ表は要らない | `PreCompact` 時点の文脈量の分布が多峰性を示し、窓サイズの違いのせいで解釈が止まったとき。**AI Gateway CSV の `Model` とは突き合わせない**（名寄せ表という人手の保守が発生する） |
| `PostCompact` の登録 | 圧縮**後**のコンテキスト量が取れれば、「圧縮がどれだけ効いたか」を直接測れる。キー構成は未確認 | 圧縮の回数と `PreCompact` 時点の分布シフトだけでは効果を説明できなくなったとき。先にキー構成の調査が要る |
| `seconds_since_last_response` / `prompt_cache_likely_expired` の収集 | 「前回応答から N 分でキャッシュが切れる」を実データで示せる、唯一の組み合わせ。どちらも公式ドキュメント未記載で消失リスクがある | 「**N 分以内に再開せよ**」型の施策を立案する段になったとき。測るだけでなく閾値を決めたくなったら、これ以外に材料が無い |
| `estimated_cache_write_usd` の収集 | 上流が算出済みの USD 見積。AI Gateway CSV の日次 Cache Write を「どの再開が生んだか」に分解できる | コストの上位者が特定できた後、その内訳を「どの行動が生んだか」まで割りたくなったとき |
| transcript 読取窓（256KB）の拡大 | 末尾から `message.usage` を取れない割合を下げるつまみ | その割合がベースライン（窓由来 約 0.5% ＋ 応答なし由来 約 3%）を大きく超えたとき。**1 行が窓を超える構造は拡大では消えない**ので、上限のある対処ではない |
| MySQL 側の `ANALYZE TABLE` と索引の見直し | SQLite では `ANALYZE` の有無で 10 倍以上の差が出た。InnoDB では skip-scan の可否も統計の要否も別問題 | MySQL を本番に選び、画面が遅いと感じたとき |
| データの保持期間 | 年間 1,500 万行で DB は 6 GiB を超える見積もり | ディスクが逼迫したとき、または窓を跨いだ集計が遅くなったとき |

01概要

社内で使う Claude Code について、設定を全員の端末に配り、利用状況とコストを見える化し、その設定の効果を確かめる仕組み。

  • 設定の配布全員の端末へ同じ設定
  • 見える化利用状況とコスト
  • 効果の確認配った設定の効果

対象: BMSD 本部の利用者（約 200 名）

しないこと

  • 本文・ツールの入出力は集めない対象は使われ方の記録だけ
  • リアルタイムには見ない設定の反映は分単位、コストは日次

03仕組み

層 1 配る

配る流れ

  • セッション開始時設定の適用・お知らせの表示
    • 配られた設定値を settings.json に書き込む（変更前の settings.json は自動でバックアップ）
    • 未読のお知らせを表示（関連ページを 1 回だけブラウザで開くことがある）

配布中の設定値

設定値狙い
プラグインの自動更新有効設定値・お知らせの変更を全端末へ届ける
Claude Code 本体の自動更新常に最新版全員の版をそろえる利用者が自動更新を切っていても打ち消す
自動コンパクトの閾値施策の例（第 1 弾）コンテキストの 60%大きなコンテキストのまま払うコストを抑える

配り方は強制。利用者が変えても、次のセッション開始時に配った値へ戻る（利用者が選ぶ方式は無い）。「初回だけ書き込み、以後は利用者に任せる」配り方も可能（現在は不使用）。

層 2 集める

集める流れ

  • 利用中イベントの記録
    • フックで端末内に記録
  • セッション開始時・応答完了時まとめて送信
    • 前回の送信から 10 分以上経っていれば、溜まった記録を裏で送る
    • 送れなかった記録は端末に残し、後で送る（14 日・20 MB まで。超えた分は古い順に捨てる）

記録・送信は裏で行い、Claude Code の操作を待たせない。エラーが起きても Claude Code は止まらない。

04収集範囲層 2 集める

端末からの収集項目

項目内容
利用者会社のメールアドレス（AI Gateway の CSV と照合するため）・端末名
イベント種類（セッション開始・プロンプト送信・ツール使用・ツールのエラー・自動コンパクト・応答完了 など）・イベント時刻・セッション ID
ツールツール名（MCP はサーバ名を含む）・サブエージェントによる使用か・中断か
スキル・コマンドスキル名・コマンド名・出所
状態コンテキストのトークン数（自動コンパクト直前・応答完了時）・エフォート・権限モード
版Claude Code 本体の版・プラグインの版
設定の適用結果設定ごとの変更前の値・配った値・適用の結果
プラグインのエラー処理の段階名とエラーの種類だけ（エラーメッセージは送らない）

CSV からの項目（AI Gateway）

日付・メールアドレス・モデル・コスト・トークン数（入力・出力・キャッシュ）Claude Code 以外の利用も含む

収集しない項目

  • プロンプト本文・Claude の応答本文・会話内容
  • ツールの入出力読み書きしたファイルの中身・実行したコマンドの中身
  • コスト端末では数えない。CSV から入る
  • モデル名端末からは取らない。CSV に含まれる

05管理画面の内容層 3 見る

分かること中身
コストと利用者全体のコスト・1 人あたり・月末のコスト見込み・利用者数・利用者ごとの一覧（コスト・利用状況）
使われ方ツール・スキル・コマンド・MCP・サブエージェントの利用

設定の効果配った設定の前後での使われ方（コンテキストの大きさなど）の変化
収集の状態データの届き具合・プラグインのエラー・記録が途絶えた端末
状況の要約注意・要確認の表示・管理者が書く週次のサマリー

効果の読み方コストの前後差は時期・業務量・料金でも動くため、効果の根拠にしない。効果は使われ方の変化で見る（自動コンパクトの例なら、コンテキストの大きさが小さい側へずれたか）。

アクセスは推測しにくい URL ＋ パスワード（社内 VPN の内側）。月ごとのデータのダウンロードもここで行う。未導入者の一覧は CSV を取り込んでいる間だけ出せる。

06運用

誰いつ何を
利用者導入時に 1 回
  1. （Windows）python3 の動作確認（端末に Python 3 が必要）
  2. git に会社のメールアドレスが設定されているかの確認
  3. Claude Code で 2 つのコマンドを実行して導入
  4. 開き直してお知らせが出れば完了
日常操作なし（更新も自動）。届かない場合だけ手動更新のコマンド 2 つ
管理者導入を進めるとき案内を 2〜3 回に分け、1〜2 週ずつずらす（部署を横断して分ける）施策の効果を、同時期のほかの変化と区別するため
1〜2 週に 1 回AI Gateway の CSV を管理画面からアップロード
随時管理画面での確認（届き具合・エラー・未導入者）と、未導入者への声かけ
設定・お知らせの変更時プラグインの版を上げて配布用リポジトリへリリース（各端末へ自動で届く）

07限界

  • 取りこぼしは許容する（オフラインが長い・端末の上限超過・エラー時の記録）。利用ログに厳密な正確性は求めない
  • プロジェクト単位の設定などで上書きされた場合は、適用率に現れない
  • 端末ごとの停止に気づけるのは、記録が途絶えて 14 日経ってから
  • 利用明細 CSV には今日と前日の分がまだ無い（コストは 2 日遅れ）

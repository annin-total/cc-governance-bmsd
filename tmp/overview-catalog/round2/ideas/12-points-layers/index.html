Claude Code 利用管理の要点

BMSD 本部の Claude Code 利用管理の仕組みを、7 つの要点で示す。

1

概要

設定の配布・見える化・効果の確認。本文は集めない

設定の配布全員の端末へ同じ設定
利用状況とコストの見える化誰がどれだけ使い、いくらかかるか
設定の効果の確認配った設定が効いたか

対象約 200名（BMSD 本部の利用者）

しないこと会話の本文・ツールの入出力の収集、リアルタイムの把握（設定の反映は分単位、コストは日次）

2

構成

配る・集める・見るの 3 層。サーバから端末への経路は無い

配る設定とお知らせを全端末へ
管理者リリース配布用リポジトリBitbucket（社内）git で自動更新利用者の端末Windows / macOS
× 集計サーバ → 利用者の端末の経路は無い
集める使われ方とコストをサーバへ
利用者の端末まとめて送信集計サーバAIP（または One Cloud）
AI Gateway利用明細 CSV を日ごとに出力管理者アップロード集計サーバ
記録をデータベースに保存し、集計
見る状況と効果を管理画面で
集計サーバ管理画面閲覧管理者ブラウザ
止まらない集計サーバの停止中も、設定とお知らせの配布 止まる集計だけ
配布用リポジトリプラグイン本体・設定値・お知らせの置き場
利用者の端末Claude Code ＋ プラグイン
集計サーバ記録の保存（データベース）・集計・管理画面
利用明細 CSVコストとトークン数の正本
管理者管理画面での確認と、配布用リポジトリの更新
3

仕組み

設定はセッション開始時に適用。記録は裏でまとめて送信

配る流れ

セッション開始時
配られた設定値を settings.json に書き込む変更前の settings.json は自動でバックアップ
セッション開始時
未読のお知らせを表示関連ページを 1 回だけブラウザで開くことがある
利用者が変えたとき
次のセッション開始時に配った値へ戻る（強制）利用者が選ぶ方式は無い

集める流れ

利用中
イベントを端末内に記録（フック）
セッション開始時・応答完了時
前回の送信から 10 分以上経っていれば、溜まった記録をまとめて裏で送信
送れなかったとき
端末に残し、後でまとめて送信14 日・20 MB まで。超えた分は古い順に捨てる

記録・送信は裏で行い、Claude Code の操作を待たせない。エラーが起きても Claude Code は止まらない。端末には Python 3（python3 コマンド）が必要。

配っている設定値

設定値狙い
プラグインの自動更新有効設定値・お知らせの変更を全端末へ届ける
Claude Code 本体の自動更新常に最新版利用者が自動更新を切っていても打ち消す全員の版をそろえる
施策の例（第 1 弾）: 自動コンパクトの閾値コンテキストの 60%大きなコンテキストのまま払うコストを抑える

ほかに「初回だけ書き込み、以後は利用者に任せる」配り方もできる（現在は使っていない）。

4

収集範囲

端末からは使われ方だけ。コストとモデルは CSV から

収集項目（端末から）内容
利用者会社のメールアドレス（CSV との照合用）・端末名
イベント種類・イベント時刻・セッション ID種類はセッション開始・プロンプト送信・ツール使用・ツールのエラー・自動コンパクト・応答完了など
ツールツール名（MCP はサーバ名を含む）・サブエージェントによる使用か・中断か
スキル・コマンドスキル名・コマンド名・その出所
状態コンテキストのトークン数（自動コンパクト直前・応答完了時）・エフォート・権限モード
版Claude Code 本体の版・プラグインの版
設定の適用結果設定ごとの変更前の値と配った値・適用の結果
プラグインのエラー処理の段階名とエラーの種類だけエラーメッセージは送らない

収集しない項目

  • 本文プロンプト本文・Claude の応答本文・会話内容
  • ツールの入出力読み書きしたファイルの中身、実行したコマンドの中身
  • コスト端末では数えない。CSV から入る
  • モデル名端末からは取らない。CSV から入る

利用明細 CSV（AI Gateway）の項目

日付メールアドレスモデルコストトークン数

トークン数は入力・出力・キャッシュ。Claude Code 以外の利用も含む。

5

管理画面

コスト・使われ方・設定の適用と効果・収集の状態

分かること中身
コストと利用者全体のコスト・1 人あたり・月末のコスト見込み・利用者数利用者ごとの一覧（コスト・利用状況）
使われ方ツール・スキル・コマンド・MCP・サブエージェントの利用
設定の適用設定どおりの端末・未導入者・本体とプラグインの版未導入者は CSV に利用があるのに記録が届かない人。一覧は CSV を取り込んでいる間だけ出せる
設定の効果配った設定の前後での使われ方の変化（コンテキストの大きさなど）
収集の状態データの届き具合・プラグインのエラー・記録が途絶えた端末
状況の要約注意・要確認の表示・管理者が書く週次のサマリー
効果の根拠にする使われ方の変化自動コンパクトの例なら、コンテキストの大きさが小さい側へずれたか
効果の根拠にしないコストの前後差時期・業務量・料金など、ほかの要因でも動くため
アクセス
推測しにくい URL ＋ パスワード（社内 VPN の内側）
データの出し入れ
CSV のアップロード・月ごとのダウンロード
6

運用

利用者は導入時の 1 回。管理者は CSV の取り込みと確認

担当時機作業
利用者導入時に 1 回（Windows）python3 の動作確認 → git の会社メールアドレスの確認 → Claude Code で 2 つのコマンドを実行 → 開き直してお知らせが出れば完了
利用者日常操作なし更新が届かない場合だけ手動更新のコマンド 2 つ
管理者導入を進めるとき案内を 2〜3 回に分け、1〜2 週ずつずらす（部署を横断して分ける）施策の効果を、同時期のほかの変化と区別するため
管理者1〜2 週に 1 回程度AI Gateway の CSV のアップロード
管理者随時管理画面での確認・未導入者への声かけ
管理者設定・お知らせの変更時プラグインの版を上げて配布用リポジトリへリリース
7

限界

取りこぼしは許容

  • 長いオフライン・端末の上限超過・エラー時の記録。利用ログに厳密な正確性は求めない
  • プロジェクト単位の設定などによる上書きは、適用率に現れない
  • 端末ごとの停止に気づけるのは、記録が途絶えて 14 日後
  • コストは 2 日遅れ（利用明細 CSV に今日と前日の分がまだ無い）

配色 1「管理画面の配色」: 管理画面と同じ地・カード・インク・アクセントの色。3 層はアクセント色の濃淡。 配色 2「青緑の濃淡」: 3 層を青緑の濃・中・淡で区別し、要点の番号を濃い青緑の丸にする。 配色 3「番号の強調」: 配色 2 をもとに、白地で節の塗りを外し、淡い青緑の大きな番号と罫線だけで要点を区切る。

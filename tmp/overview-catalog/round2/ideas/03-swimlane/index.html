Claude Code 利用管理の仕組み

設定を全員の端末に配り、利用状況とコストを見える化し、設定の効果を確かめる仕組み。

01目的

設定の配布全員の端末へ同じ設定
利用状況とコストの見える化誰がどれだけ使い、いくらかかるか
設定の効果の確認配った設定で使われ方が変わったか

対象　BMSD 本部の Claude Code 利用者　約200名

行わないこと会話の本文・ツールの入出力の収集リアルタイムの把握（設定の反映は分単位、コストは日次）

02全体構成

集計サーバの停止時止まるのは集計だけ。設定とお知らせの配布は続く

構成要素

要素置き場役割
配布用リポジトリBitbucket（社内）プラグイン本体・設定値・お知らせの置き場
利用者の端末Windows / macOSClaude Code ＋ プラグイン。Python 3 が必要設定の適用・お知らせの表示・イベントの記録と送信
集計サーバAIP（または One Cloud）記録の保存（データベース）・集計・管理画面
利用明細 CSVAI Gateway が日ごとに出力コストとトークン数の正本
管理者ブラウザ管理画面の閲覧・CSV のアップロード・配布用リポジトリの更新

03動作の流れ

配布セッション開始時

  • 配られた設定値を settings.json へ書き込み変更前の settings.json は自動でバックアップ
  • 未読のお知らせを表示関連ページを 1 回だけブラウザで開くことがある

配布中の設定値

設定値狙い
プラグインの自動更新有効設定値・お知らせの変更を全端末へ届ける
Claude Code 本体の自動更新常に最新版利用者が自動更新を切っていても打ち消す全員の版をそろえる
施策の例自動コンパクトの閾値コンテキストの 60%大きなコンテキストのまま払うコストを抑える

利用者が変えても、次のセッション開始時に配った値へ戻る（強制）。利用者が選ぶ方式は無い。「初回だけ書き込み、以後は利用者に任せる」配り方も可能（現在は不使用）。

収集記録と送信

利用中
イベントを端末内に記録（フックで記録）
セッション開始時・応答完了時
前回の送信から 10 分以上経っていれば、溜まった記録をまとめて送信
送れなかった記録
端末に残し、後でまとめて送信14 日・20 MB まで。超えた分は古い順に破棄

記録・送信は裏で行い、Claude Code の操作を待たせない。エラーが起きても Claude Code は止まらない。

04収集データ

端末から収集

項目内容
利用者会社のメールアドレス・端末名メールアドレスは利用明細 CSV との照合用
イベント種類（セッション開始・プロンプト送信・ツール使用・ツールのエラー・自動コンパクト・応答完了 など）・イベント時刻・セッション ID
ツールツール名（MCP はサーバ名を含む）・サブエージェントによる使用か・中断か
スキル・コマンドスキル名・コマンド名・その出所
状態コンテキストのトークン数（自動コンパクト直前・応答完了時）・エフォート・権限モード
版Claude Code 本体の版・プラグインの版
設定の適用結果設定ごとの変更前の値・配った値・適用の結果
プラグインのエラー処理の段階名・エラーの種類エラーメッセージは送らない

端末から収集しない

  • 会話プロンプト本文・Claude の応答本文・会話内容
  • ツールの入出力読み書きしたファイルの中身・実行したコマンドの中身
  • コスト端末では数えない
  • モデル名端末からは取らない

利用明細 CSV の項目

日付メールアドレスモデルコストトークン数

トークン数は入力・出力・キャッシュの別。Claude Code 以外の利用も含む。

05管理画面の表示内容

観点内容
コストと利用者全体のコスト・1 人あたり・月末のコスト見込み・利用者数利用者ごとの一覧（コスト・利用状況）
使われ方ツール・スキル・コマンド・MCP・サブエージェントの利用
設定の適用設定どおりの端末・未導入者・本体とプラグインの版未導入者は、CSV に利用があるのに記録が届かない人
設定の効果配った設定の前後での使われ方の変化
収集の状態データの届き具合・プラグインのエラー・記録が途絶えた端末
状況の要約注意・要確認の表示・管理者が書く週次のサマリー

効果の読み方

根拠にする使われ方の変化自動コンパクトの例なら、コンテキストの大きさが小さい側へずれたか
根拠にしないコストの前後差時期・業務量・料金など、ほかの要因でも動く
  • アクセスは、推測しにくい URL ＋ パスワード（社内 VPN の内側）
  • 月ごとの書き出し（CSV の ZIP）も管理画面で行う
  • 未導入者の一覧は、CSV を取り込んでいる間だけ表示できる

06運用の分担

担当時機作業
利用者導入時に 1 回（Windows）python3 の動作確認 → git に会社のメールアドレスが設定済みか確認 → Claude Code で 2 つのコマンドを実行 → 開き直してお知らせが出れば完了
利用者日常操作なし届かない場合だけ手動更新のコマンド 2 つ
管理者導入の展開時案内を 2〜3 回に分け、1〜2 週ずつずらす（部署を横断して分ける）施策の効果を、同時期のほかの変化と区別するため
管理者1〜2 週に 1 回程度AI Gateway の CSV を管理画面からアップロード
管理者随時データの届き具合・エラー・未導入者の確認。未導入者への声かけ
管理者設定・お知らせの変更時プラグインの版を上げ、配布用リポジトリへリリース

07制約

  • 取りこぼしは許容する（長いオフライン・端末の上限超過・エラー時の記録）。利用ログに厳密な正確性は求めない
  • プロジェクト単位の設定などで上書きされた場合は、適用の状況に現れない
  • 端末ごとの停止に気づけるのは、記録が途絶えて 14 日後
  • 利用明細 CSV に当日と前日の分は無い（コストは 2 日遅れ）

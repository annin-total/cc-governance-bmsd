Claude Code 利用管理の仕組み

BMSD 本部の Claude Code 利用者を対象とする、設定の配布・利用状況の見える化・設定の効果の確認

01概要

社内で使う Claude Code について、次の 3 つを行う仕組みである。

DISTRIBUTE設定の配布全員の端末へ同じ設定を配る
VISUALIZE利用状況とコストの見える化誰がどれだけ使い、いくらかかるか
EVALUATE設定の効果の確認配った設定が効いたかを確かめる
対象約 140名（BMSD 本部の利用者） 経路2本（配る・集める） 管理画面4画面 ＋ データ管理

しないこと

  • プロンプト・応答・会話の本文の収集
  • ツールの入出力の収集ファイルの中身・実行したコマンドの中身
  • 利用者個人の監視目的は施策の評価。個人ごとの操作の時系列を見る画面は無い
  • リアルタイムの把握設定の反映は分単位、コストは日次

03仕組み

端末での 1 セッションの流れ。記録・送信は裏で行い、Claude Code の操作を待たせない。

  1. セッション開始時設定の適用・お知らせの表示
    • 配られた設定値を settings.json に書き込む
    • 変更前の settings.json は自動でバックアップ
    • 未読のお知らせを表示（関連ページを 1 回だけブラウザで開くことがある）
  2. 利用中イベントの記録
    • プロンプト送信・ツール使用・ツールのエラー・自動コンパクト・応答完了など
    • フックで端末内に記録
  3. セッション開始時・応答完了時記録の送信
    • 前回の送信から 10 分以上経っていれば、溜まった記録をまとめて裏で送る
送信の間隔10分以上
端末での保持14日
保持の上限20MB

送れなかった記録は端末に残り、後でまとめて送られる。上限を超えた分は古い順に捨てる。

エラーが起きても Claude Code は止まらない。端末には Python 3（python3 コマンド）が必要である。

04配布中の設定

利用者が変えても、次のセッション開始時に配った値へ戻る（強制）。利用者が選ぶ方式は無い。

設定値狙い
自動コンパクトの閾値60%コンテキストがこの割合に達したら実行大きなコンテキストのまま払うコストを抑える効果を測る対象
プラグインの自動更新有効設定値・お知らせの変更を全端末へ届ける
Claude Code 本体の自動更新常に最新版利用者が自動更新を切っていても打ち消す全員の版をそろえる

ほかに「初回だけ書き込み、以後は利用者に任せる」配り方もできる（現在は使っていない）。

06管理画面

4 画面 ＋ データ管理。アクセスは推測しにくい URL ＋ パスワード（社内 VPN の内側）。

概況
全体でいくらかかり、誰が使っているか
  • コスト・利用者数
  • 月末のコスト見込み
  • データの届き具合
  • プラグインのエラー
  • 期間は 7 日 / 28 日 / 12 か月

誰の端末が設定どおりか
  • 適用率
  • 未導入者
    CSV に利用があるのに記録が届かない人
  • 記録が途絶えた端末（14 日以上）
  • 本体とプラグインの版の分布
設定の効果
配った設定は効いたか
  • 適用を始めた日を起点にした前後の推移
  • コンテキストのトークン数の分布
スキル・コマンドの利用
配ったものは使われているか
  • スキル・コマンドごとの利用
データと設定
  • CSV のアップロード
  • 月ごとのダウンロード（ZIP）
  • 会社の休日の登録

効果の読み方

根拠にするコンテキストの大きさが小さい側へずれたか
根拠にしないコストの前後差時期・業務量・料金など、ほかの要因でも動くため

未導入者の一覧は、CSV を取り込んでいる間だけ出せる。

07運用

利用者の作業は導入時が中心。日常の更新は自動である。

担当時機作業
利用者導入時に 1 回（Windows）python3 の動作確認 → git に会社のメールアドレスが設定済みか確認 → Claude Code で 2 つのコマンドを実行して導入 → 開き直してお知らせが出れば完了
利用者日常操作なし届かない場合だけ手動更新のコマンド 2 つ
管理者導入を進めるとき案内を 2〜3 回に分け、1〜2 週ずつずらす（部署を横断して分ける）施策の効果を、同時期のほかの変化と区別するため
管理者1〜2 週に 1 回程度AI Gateway の CSV を管理画面からアップロード
管理者随時データの届き具合・エラー・未導入者の確認。未導入者への声かけ
管理者設定・お知らせの変更時プラグインの版を上げて配布用リポジトリへリリース → 各端末へ自動で届く
限界
  • 取りこぼしは許容する（オフラインが長い・端末の上限超過・エラー時の記録）。利用ログに厳密な正確性は求めない
  • プロジェクト単位の設定などで上書きされた場合は、画面の適用率に現れない
  • 端末ごとの停止に気づけるのは、記録が途絶えて 14 日経ってから

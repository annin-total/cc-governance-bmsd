概要

何のための仕組みで、何をして、何をしないか

社内の Claude Code に
設定を配り、利用を見える化し、
設定の効果を確かめる仕組み

対象約 140名 ・ BMSD 本部の利用者
配設定の配布全員の端末へ同じ設定
見利用状況とコストの見える化誰がどれだけ使い、いくらかかるか
確設定の効果の確認配った設定が効いたか

しないこと

  • プロンプト・応答・会話の本文の収集
  • ツールの入出力の収集ファイルの中身・実行したコマンドの中身
  • 利用者個人の監視目的は施策の評価。個人ごとの操作の時系列を見る画面は無い
  • リアルタイムの把握設定の反映は分単位、コストは日次

構成

配る経路と集める経路の 2 本。サーバから端末へ指示を出す経路は無い

配る経路

  1. 管理者設定値・お知らせを更新
  2. リリース
  3. 配布用リポジトリBitbucket（社内）
  4. git で自動更新
  5. 利用者の端末Windows / macOS

集める経路

  1. 利用者の端末
  2. 記録の送信
  3. 集計サーバAIP（または One Cloud）
  4. 集計
  5. 管理画面管理者がブラウザで閲覧

集める経路（CSV）

  1. 利用明細 CSVAI Gateway・日ごと
  2. 管理者がアップロード
  3. 集計サーバ

× サーバから端末への指示の経路は無し。集計サーバが止まっても配布は止まらない。止まるのは集計だけ。

仕組み

端末での 1 セッションの流れと、配る設定

1
セッション開始時設定の適用・お知らせ
  • 設定値を settings.json に書き込む（変更前は自動でバックアップ）
  • 未読のお知らせを表示
2
利用中イベントの記録
  • プロンプト送信・ツール使用・ツールのエラー・自動コンパクト・応答完了など
  • フックで端末内に記録
3
セッション開始時・応答完了時まとめて送信
  • 前回の送信から 10 分以上経っていれば、溜まった記録を裏で送る

記録・送信は裏で行い、Claude Code の操作を待たせない。エラーが起きても Claude Code は止まらない。端末には Python 3（python3）が必要。

自動コンパクトの閾値60%コンテキストがこの割合に達したら実行。大きなコンテキストのまま払うコストを抑える効果を測る対象
プラグインの自動更新有効設定値・お知らせの変更を全端末へ届ける
Claude Code 本体の自動更新常に最新版全員の版をそろえる。利用者が自動更新を切っていても打ち消す

配り方強制

利用者が変えても、次のセッション開始時に配った値へ戻る。利用者が選ぶ方式は無い。「初回だけ書き込み、以後は利用者に任せる」配り方もできる（現在は使っていない）。

送れなかった記録端末に残り、後でまとめて送信

保持14日上限20MB超えた分は古い順に捨てる

収集

端末からは利用の記録だけ。本文と中身は集めない

収集項目端末から

利用者
会社のメールアドレス・端末名
メールアドレスは CSV との照合用
イベント
種類・イベント時刻・セッション ID
ツール
ツール名（MCP はサーバ名を含む）・サブエージェントによる使用か・中断か
スキル・コマンド
スキル名・コマンド名・その出所
状態
コンテキストのトークン数（自動コンパクト直前・応答完了時）・エフォート・権限モード
版
Claude Code 本体の版・プラグインの版
設定の適用結果
設定ごとの変更前の値と配った値・適用の結果
プラグインのエラー
処理の段階名とエラーの種類だけ
エラーメッセージは送らない

収集しない項目

  • プロンプト本文・応答本文・会話内容
  • ツールの入出力読み書きしたファイルの中身、実行したコマンドの中身
  • コスト端末では数えない。CSV が正本
  • モデル名端末からは取らない。CSV に含まれる

日付メールアドレスモデルコストトークン数

トークン数は入力・出力・キャッシュ。CSV には Claude Code 以外の利用も含まれる。管理者が管理画面からアップロードする。

管理画面 4 画面 ＋ データと設定。推測しにくい URL ＋ パスワード（社内 VPN の内側）

  • データの届き具合
  • プラグインのエラー

  • 適用を始めた日を起点にした前後の推移
  • コンテキストのトークン数の分布
スキル・コマンドの利用配ったものは使われているか
  • スキル・コマンドごとの利用
データと設定CSV のアップロード月ごとのダウンロード（ZIP）会社の休日の登録

効果の読み方

根拠にするコンテキストの大きさが小さい側へずれたか
根拠にしないコストの前後差時期・業務量・料金など、ほかの要因でも動く

未導入者の一覧は、CSV を取り込んでいる間だけ出せる。

運用

利用者の作業は導入時が中心。日常の更新は自動

利用者  導入時に 1 回

  1. （Windows）python3 の動作確認
  2. 会社のメールアドレスが git に設定済みか確認
  3. Claude Code で 2 つのコマンドを実行して導入
  4. 開き直してお知らせが出れば完了
日常
操作なし届かない場合だけ手動更新のコマンド 2 つ

管理者

導入を進めるとき
案内を 2〜3 回に分け、1〜2 週ずつずらす（部署を横断して分ける）施策の効果を、同時期のほかの変化と区別するため
1〜2 週に 1 回程度
AI Gateway の CSV を管理画面からアップロード
随時
データの届き具合・エラー・未導入者の確認。未導入者への声かけ
設定・お知らせの変更時
プラグインの版を上げて配布用リポジトリへリリース → 各端末へ自動で届く
限界
  • 取りこぼしは許容する（オフラインが長い・端末の上限超過・エラー時の記録）。利用ログに厳密な正確性は求めない
  • プロジェクト単位の設定などで上書きされた場合は、画面の適用率に現れない
  • 端末ごとの停止に気づけるのは、記録が途絶えて 14 日経ってから

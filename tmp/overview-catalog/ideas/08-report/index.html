Claude Code 利用管理の仕組み

対象: BMSD 本部の利用者（約 140 名）
読者: 管理側・上長
要点配布・見える化・効果の確認
  1. 01
    設定を全端末へ配り、強制する

    Bitbucket から git で自動配布。利用者が変えても次のセッション開始時に戻る。

  2. 02
    会話の中身は集めない

    集めるのは利用の記録だけ。コストの正本は AI Gateway の CSV。

  3. 03
    配る経路と集める経路は別

    集計サーバが止まっても、設定とお知らせの配布は止まらない。

目的は施策の評価であり、利用者個人の監視ではない。リアルタイムの表示は行わない（設定の反映は分単位、コストは日次）。

1構成と経路

表 1構成要素

要素置き場役割

利用者の端末Windows / macOS設定の適用・お知らせ表示・イベントの記録と送信
集計サーバAIP（または One Cloud）保存・集計・管理画面

集計サーバが止まっても、止まるのは集計だけ。

  • 設定とお知らせの配布は継続
  • 送れなかった記録は端末に残り、後でまとめて送信
  • 端末での保管は 14 日・20 MB まで。超過分は古い順に破棄

2端末での動き

利用者への影響

  • 記録・送信は裏で行い、操作を待たせない
  • エラーが起きても Claude Code は止まらない
  • 前提: 端末に Python 3（python3 コマンド）

3配布する設定値

表 2設定値と狙い

設定値狙い
自動コンパクトの閾値コンテキスト 60% で実行大きなコンテキストのまま払うコストを抑える（効果を測る対象）
プラグインの自動更新有効設定値・お知らせの変更を全端末へ届ける
Claude Code 本体の自動更新常に最新版へ全員の版をそろえる（利用者が自動更新を切っていても打ち消す）

利用者が変えても、次のセッション開始時に配った値へ戻る（強制）。利用者が選ぶ方式は無い。「初回だけ書き込み、以後は利用者に任せる」配り方も可能だが、現在は使っていない。

6効果の評価

効果は「コンテキストの大きさが小さい側へずれたか」で見る。

  • 起点は設定の適用を始めた日
  • コストの前後差は根拠にしない（時期・業務量・料金でも動くため）

導入の進め方

  • 案内を 2〜3 回に分け、1〜2 週ずつずらす
  • 部署を横断して分ける

施策の効果を、同時期のほかの変化と区別するため。

7運用

表 6役割別の作業

担当時機作業
利用者導入時に 1 回（Windows）python3 の動作確認 → git に会社のメールアドレスが設定済みか確認 → Claude Code でコマンド 2 つを実行 → 開き直してお知らせが出れば完了
利用者日常操作なし（更新も自動。届かない場合だけ手動更新のコマンド 2 つ）
管理者導入を進めるとき案内を 2〜3 回に分け、1〜2 週ずつずらす（部署を横断）
管理者1〜2 週に 1 回程度AI Gateway の CSV を管理画面からアップロード
管理者随時データの届き具合・エラー・未導入者の確認。未導入者への声かけ
管理者設定・お知らせの変更時プラグインの版を上げて配布用リポジトリへリリース → 各端末へ自動で届く

8限界

  • 取りこぼしは許容する（長いオフライン・端末の上限超過・エラー時の記録）。利用ログに厳密な正確性は求めない
  • プロジェクト単位の設定などで上書きされた場合は、画面の適用率に現れない
  • 端末ごとの停止に気づけるのは、記録が途絶えて 14 日経ってから

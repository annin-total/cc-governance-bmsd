T4

配布設定値

3 件
No.設定値配り方狙い
1自動コンパクトの閾値コンテキストの 60%強制大きなコンテキストのまま払うコストの抑制。効果測定の対象
2プラグインの自動更新有効強制設定値・お知らせの変更を全端末へ
3Claude Code 本体の自動更新常に最新版強制全員の版の統一。利用者側の無効化も打ち消す
  • 強制: 利用者が変えても、次のセッション開始時に配った値へ戻る。利用者が選ぶ方式は無い
  • 別の配り方として「初回だけ書き込み、以後は利用者に任せる」も可能（現在は不使用）
T5

端末処理

3 件
No.時機処理条件・上限
1セッション開始時設定値を settings.json へ書き込み（変更前は自動でバックアップ）。未読のお知らせを表示関連ページをブラウザで開くことがある（1 回だけ）
2利用中イベントを端末内に記録（フック）—
3セッション開始時・応答完了時溜まった記録をまとめて裏で送信前回送信から 10 分以上。未送信分の保持は 14 日・20 MB まで（超過分は古い順に破棄）
  • 記録・送信は裏で行い、操作を待たせない。エラーでも Claude Code は止まらない
  • 前提: 端末に Python 3（python3 コマンド）
T6

管理画面

4 画面 ＋ データ管理
No.画面答える問い主な中身
1概況全体の費用と利用者コスト・利用者数・月末のコスト見込み・データの届き具合・プラグインのエラー。期間 7 日 / 28 日 / 12 か月
2設定の適用状況設定どおりの端末適用率・未導入者（CSV に利用があり記録が届かない人）・記録が途絶えた端末（14 日以上）・本体とプラグインの版の分布
3設定の効果配った設定の効き目適用開始日を起点にした前後の推移・コンテキストのトークン数の分布
4スキル・コマンドの利用配ったものの利用スキル・コマンドごとの利用
5データと設定—CSV のアップロード・月ごとのダウンロード（ZIP）・会社の休日の登録
  • アクセス: 推測しにくい URL ＋ パスワード（社内 VPN の内側）
  • 効果の判定: コンテキストの大きさが小さい側へずれたか。コストの前後差は時期・業務量・料金でも動くため根拠にしない
  • 未導入者の一覧は CSV の取り込み期間中のみ
T7

運用

6 件
No.担当時機作業
1利用者導入時 1 回（Windows）python3 の動作確認 → git の会社メールアドレス確認 → Claude Code でコマンド 2 つ実行 → 開き直してお知らせ表示で完了
2利用者日常操作なし。更新も自動（届かない場合のみ手動更新のコマンド 2 つ）
3管理者導入の推進時案内を 2〜3 回に分割、1〜2 週ずつずらす（部署横断）。同時期のほかの変化と効果を区別するため
4管理者1〜2 週に 1 回程度AI Gateway の CSV を管理画面からアップロード
5管理者随時データの届き具合・エラー・未導入者の確認。未導入者への声かけ
6管理者設定・お知らせの変更時プラグインの版を上げ、配布用リポジトリへリリース → 各端末へ自動で届く
T8

非対象・限界

6 件
No.区分内容
1非対象利用者個人の監視をしない。個人ごとの操作の時系列を見る画面は無い
2非対象リアルタイムの表示（設定の反映は分単位、コストは日次）
3非対象サーバから端末への指示
4限界取りこぼしの許容（長いオフライン・端末の上限超過・エラー時の記録）。利用ログに厳密な正確性は求めない
5限界プロジェクト単位の設定などによる上書きは、適用率に現れない
6限界端末ごとの停止の検知は、記録の途絶から 14 日後

配る

集める
各端末送信 集計サーバ管理者が
アップロード AI Gateway の CSV利用明細（日ごと）

サーバから端末へ指示を出す経路は無い。
止まるのは集計だけ。設定とお知らせは届き続ける。

送れなかった記録は端末に残る。
後でまとめて送る。14 日・20 MB まで。超えた分は古い順に捨てる。

05 / 10

端末での動き

1 セッションの中で、記録と送信は裏で動く

  1. 1セッション開始時

    設定の適用

    配られた設定値を settings.json に書き込む（変更前は自動でバックアップ）。未読のお知らせを表示。関連ページを 1 回だけブラウザで開くことがある

  2. 2利用中

    イベントの記録

    プロンプト送信・ツール使用・ツールのエラー・自動コンパクト・応答完了などを、フックで端末内に記録

  3. 3開始時・応答完了時

    まとめて送信

    前回の送信から 10 分以上経っていれば、溜まった記録を裏で送る

操作を待たせないエラーでも Claude Code は止まらない要 Python 3（python3）
06 / 10

配っている設定値

3 つの値を、全員に強制で配る

  • 自動コンパクトの閾値60%

    コンテキストが 60% に達したら実行。大きなコンテキストのまま払うコストを抑える。効果を測る対象

  • プラグインの自動更新有効

    設定値・お知らせの変更を全端末へ届ける

  • Claude Code 本体の自動更新常に最新版

    全員の版をそろえる。利用者が自動更新を切っていても打ち消す

利用者が変えても、次のセッション開始時に配った値へ戻る。利用者が選ぶ方式は無い。「初回だけ書き込み、以後は利用者に任せる」配り方もできる（現在は不使用）。

08 / 10

管理画面

4 つの画面が、4 つの問いに答える

  • 全体でいくらかかり、誰が使っているか

    概況

    コスト・利用者数・月末のコスト見込み・データの届き具合・プラグインのエラー。期間は 7 日 / 28 日 / 12 か月

  • 誰の端末が設定どおりか

    設定の適用状況

    適用率・未導入者・記録が途絶えた端末（14 日以上）・本体とプラグインの版の分布

  • 配った設定は効いたか

    設定の効果

    適用開始日を起点にした前後の推移・コンテキストのトークン数の分布

  • 配ったものは使われているか

    スキル・コマンドの利用

    スキル・コマンドごとの利用

データと設定　CSV のアップロード・月ごとのダウンロード（ZIP）・会社の休日の登録。アクセスは推測しにくい URL ＋ パスワード（社内 VPN の内側）

効果は「コンテキストの大きさ」で見る

コストの前後差は時期・業務量・料金でも動くため根拠にしない。小さい側へずれたかで判断する

09 / 10

運用

利用者は導入時だけ。あとは自動

利用者

  • 導入時に 1 回（Windows）python3 の確認 → git のメールアドレス確認 → コマンド 2 つで導入 → 開き直してお知らせが出れば完了
  • 日常操作なし。届かない場合だけ手動更新のコマンド 2 つ

管理者

  • 導入を進めるとき案内を 2〜3 回に分け、1〜2 週ずつずらす（部署横断）。効果を同時期のほかの変化と区別するため
  • 1〜2 週に 1 回AI Gateway の CSV をアップロード
  • 随時届き具合・エラー・未導入者を確認し、声をかける
  • 設定を変えるとき版を上げてリリース → 各端末へ自動で届く

LAYER 1

配る ― 設定値

セッション開始時に settings.json へ書き込む

設定値狙い
自動コンパクトの閾値60%コンテキストが 60% に達したら実行。大きなコンテキストのまま払うコストを抑える（効果を測る対象）
プラグインの自動更新有効設定値・お知らせの変更を全端末へ届ける
Claude Code 本体の自動更新常に最新版全員の版をそろえる。利用者が自動更新を切っていても打ち消す

強制。利用者が変えても、次のセッション開始時に配った値へ戻る。利用者が選ぶ方式は無い。変更前の settings.json は自動でバックアップ。「初回だけ書き込み、以後は利用者に任せる」配り方もできる（現在は不使用）。

LAYER 2

集める ― 収集項目

記録は裏で行い、操作を待たせない。エラーでも Claude Code は止まらない

端末から

利用者会社のメールアドレス（CSV と照合するため）・端末名
イベント種類（セッション開始・プロンプト送信・ツール使用・ツールのエラー・自動コンパクト・応答完了 など）・イベント時刻・セッション ID
ツールツール名（MCP はサーバ名を含む）・サブエージェントによる使用か・中断か
スキル・コマンドスキル名・コマンド名・出所
状態コンテキストのトークン数（自動コンパクト直前・応答完了時）・エフォート・権限モード
版Claude Code 本体の版・プラグインの版
設定の適用結果設定ごとの変更前の値・配った値・適用の結果
プラグインのエラー処理の段階名とエラーの種類だけ（エラーメッセージは送らない）

CSV から（AI Gateway）

  • 日付・メールアドレス・モデル・コスト
  • トークン数（入力・出力・キャッシュ）
  • Claude Code 以外の利用も含む

収集しない

  • プロンプト・応答・会話の本文
  • ツールの入出力 ファイル・コマンドの中身
  • コスト 端末では数えない。CSV が正本
  • モデル名 端末からは取らない

送れなかった記録は端末に残り、後でまとめて送る。14 日・20 MB まで。超えた分は古い順に捨てる。

LAYER 3

見る ― 管理画面

推測しにくい URL ＋ パスワード

画面答える問い主な中身
概況全体でいくらかかり、誰が使っているかコスト・利用者数・月末のコスト見込み・データの届き具合・プラグインのエラー。期間は 7 日 / 28 日 / 12 か月
設定の適用状況誰の端末が設定どおりか適用率・未導入者（CSV に利用があるのに記録が届かない人）・記録が途絶えた端末（14 日以上）・本体とプラグインの版の分布
設定の効果配った設定は効いたか適用を始めた日を起点にした前後の推移・コンテキストのトークン数の分布
スキル・コマンドの利用配ったものは使われているかスキル・コマンドごとの利用
データと設定―CSV のアップロード・月ごとのダウンロード（ZIP）・会社の休日の登録

効果の読み方。コストの前後差は時期・業務量・料金でも動くため、効果の根拠にしない。効果は「コンテキストの大きさが小さい側へずれたか」で見る。未導入者の一覧は、CSV を取り込んでいる間だけ出せる。

限界

  • 取りこぼしは許容する（オフラインが長い・端末の上限超過・エラー時の記録）。利用ログに厳密な正確性は求めない
  • プロジェクト単位の設定などで上書きされた場合は、画面の適用率に現れない
  • 端末ごとの停止に気づけるのは、記録が途絶えて 14 日経ってから

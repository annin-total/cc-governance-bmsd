Claude Code 利用管理の全体像

設定を全員の端末に配り、利用状況とコストを見える化し、設定の効果を確かめる仕組み。対象は BMSD 本部の利用者（約 140 名）。

配る経路 集める経路 閲覧

図は横にスクロールできる。

配る経路

管理者 → Bitbucket → 各端末（git による自動更新）

  • セッション開始時に設定値を settings.json へ書き込む（変更前は自動でバックアップ）
  • 未読のお知らせを表示（関連ページを 1 回だけブラウザで開くことがある）
  • 配る設定値: 自動コンパクトの閾値 60%・プラグインの自動更新 有効・本体の自動更新 常に最新版

利用者が変えても、次のセッション開始時に配った値へ戻る。設定の反映は分単位。

集める経路

各端末 → 集計サーバ（ネットワーク送信）／ AI Gateway の CSV → 管理者 → 集計サーバ

  • 利用中のイベントを端末内に記録（フックで記録）
  • セッション開始時と応答完了時、前回の送信から 10 分以上経っていればまとめて送信
  • CSV はコストとトークン数の正本（コストは日次）

送れなかった記録は端末に残り、後でまとめて送られる（14 日・20 MB まで。超えた分は古い順に捨てる）。記録・送信は裏で行い、Claude Code の操作を待たせない。エラーが起きても Claude Code は止まらない。

役割ごとのやること

利用者

導入時に 1 回
  1. （Windows）python3 の動作確認
  2. git に会社のメールアドレスが設定されているか確認
  3. Claude Code で 2 つのコマンドを実行して導入
  4. 開き直してお知らせが出れば完了
日常操作なし（更新も自動）。届かない場合だけ手動更新のコマンド 2 つ

管理者

導入を進めるとき案内を 2〜3 回に分け、1〜2 週ずつずらす（部署を横断して分ける）。施策の効果を同時期のほかの変化と区別するため
1〜2 週に 1 回程度AI Gateway の CSV を管理画面からアップロード
随時管理画面で、データの届き具合・エラー・未導入者を確認。未導入者に声をかける
設定・お知らせの変更時プラグインの版を上げて配布用リポジトリへリリース。各端末へ自動で届く

管理画面: 概況 / 設定の適用状況 / 設定の効果 / スキル・コマンドの利用 ＋ データと設定。社内 VPN の内側で、推測しにくい URL ＋ パスワード。効果は「コンテキストの大きさが小さい側へずれたか」で見る（コストの前後差は時期・業務量・料金でも動くため根拠にしない）。

収集範囲

端末から収集する

利用者
会社のメールアドレス（CSV との照合用）・端末名
イベント
種類・イベント時刻・セッション ID
ツール
ツール名（MCP はサーバ名を含む）・サブエージェントによる使用か・中断か
スキル・コマンド
スキル名・コマンド名・出所
状態
コンテキストのトークン数（自動コンパクト直前・応答完了時）・エフォート・権限モード
版
Claude Code 本体・プラグイン
設定の適用結果
設定ごとの変更前の値・配った値・適用の結果
プラグインのエラー
処理の段階名・エラーの種類のみ

CSV から取り込む

  • 日付
  • メールアドレス
  • モデル
  • コスト
  • トークン数（入力・出力・キャッシュ）

CSV には Claude Code 以外の利用も含まれる。

対象外収集しない

  • プロンプト本文・Claude の応答本文・会話内容
  • ツールの入出力（ファイルの中身・実行したコマンドの中身）
  • エラーメッセージ
  • コスト・モデル名（端末からは取らない。CSV に含まれる）

目的は施策の評価。利用者個人の監視をしない（個人ごとの操作の時系列を見る画面は無い）。

限界
  • 取りこぼしは許容する（オフラインが長い・端末の上限超過・エラー時の記録）
  • プロジェクト単位の設定などで上書きされた場合は、適用率に現れない
  • 端末ごとの停止に気づけるのは、記録が途絶えて 14 日経ってから

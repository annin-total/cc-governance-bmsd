Claude Code 利用管理の仕組み
九つの問い

社内で使う Claude Code について、設定を全員の端末に配り、利用状況とコストを見える化し、その設定の効果を確かめる仕組み。

対象: BMSD 本部の利用者（約 140 名）
問一何のためか 問二会話は集めるか 問三何を集めるか 問四何を配るか 問五利用者の手間は 問六サーバが止まったら 問七効果の測り方は 問八管理画面で何が見えるか 問九限界は
問一

何のためか

配る・見える化する・確かめる、の三つ。

一
設定の配布

全員の端末へ同じ設定値を届ける

二
利用の見える化

利用状況とコストを管理画面に集約

三
効果の確認

配った設定が効いたかを確かめる

目的は施策の評価。利用者個人の監視をしない。

問二

会話は集めるか

集めない。本文と中身には触れない。

×集めないもの

  • プロンプト本文・応答本文・会話内容
  • ツールの入出力（読み書きしたファイルの中身、実行したコマンドの中身）
  • プラグインのエラーメッセージ

−無いもの

  • 個人ごとの操作の時系列を見る画面
  • リアルタイムの表示（設定の反映は分単位、コストは日次）
問三

何を集めるか

端末からは利用の記録、AI Gateway の CSV からはコスト。

出所項目内容
端末利用者会社のメールアドレス（CSV との照合用）・端末名
イベント種類・イベント時刻・セッション ID
ツールツール名（MCP はサーバ名を含む）・サブエージェントによる使用か・中断か
スキル・コマンドスキル名・コマンド名・その出所
状態コンテキストのトークン数（自動コンパクト直前・応答完了時）・エフォート・権限モード
版Claude Code 本体の版・プラグインの版
設定の適用結果設定ごとの変更前の値・配った値・適用の結果
プラグインのエラー処理の段階名・エラーの種類のみ
CSV利用明細日付・メールアドレス・モデル・コスト・トークン数（入力・出力・キャッシュ）

コストとモデル名は端末では取らない。正本は CSV。CSV には Claude Code 以外の利用も含まれる。

問四

何を配るか

設定値三つ。変えられても、次のセッション開始時に戻る。

設定値狙い
自動コンパクトの閾値コンテキスト 60% で実行大きなコンテキストのまま払うコストを抑える（効果を測る対象）
プラグインの自動更新有効設定値・お知らせの変更を全端末へ届ける
本体の自動更新常に最新版全員の版をそろえる

本体の自動更新は、利用者が切っていても打ち消す。利用者が選ぶ方式は無い。「初回だけ書き込み、以後は利用者に任せる」配り方も可能（現在は不使用）。お知らせも同じ経路で配る。

問五

利用者の手間は

導入時に一度だけ。以後は操作なし。

  1. （Windows）python3 の動作確認
  2. git に会社のメールアドレスが設定済みか確認
  3. Claude Code でコマンド 2 つを実行
  4. 開き直し、お知らせが出れば完了
日常
操作なし。更新も自動（届かない場合だけ手動更新のコマンド 2 つ）
待ち時間
なし。記録・送信は裏で行う
送信
前回から 10 分以上経っていれば、セッション開始時・応答完了時にまとめて送信
エラー時
Claude Code は止まらない
前提
端末に Python 3（python3 コマンド）
問六

サーバが止まったら

止まるのは集計だけ。設定とお知らせの配布は止まらない。

配る経路git による自動更新
管理者→Bitbucket→各端末継続
集める経路ネットワーク送信
各端末→集計サーバ（停止中）集計のみ停止
集める経路（CSV）管理者のアップロード
AI Gateway の CSV→管理者→集計サーバ

サーバから端末へ指示を出す経路は無い。ゆえに集計サーバの停止は配布に及ばない。

送れなかった記録扱い
保管場所端末
保管の上限14 日・20 MB（超過分は古い順に破棄）
再送後でまとめて送信
問七

効果の測り方は

コストの前後差ではなく、コンテキストの大きさの分布で見る。

指標扱い
コストの前後差根拠にしない。時期・業務量・料金でも動く
コンテキストの大きさ根拠にする。小さい側へずれたか
起点設定の適用を始めた日

導入の案内は 2〜3 回に分け、1〜2 週ずつずらす（部署を横断して分ける）。同時期のほかの変化と区別するため。

見方の模式図。実測値ではない。
問八

管理画面で何が見えるか

4 画面とデータ管理。各画面が一つの問いに答える。

概況

全体でいくらかかり、誰が使っているか

コスト・利用者数・月末のコスト見込み・データの届き具合・プラグインのエラー。期間は 7 日 / 28 日 / 12 か月

設定の適用状況

誰の端末が設定どおりか

適用率・未導入者（CSV に利用があるのに記録が届かない人）・記録が途絶えた端末（14 日以上）・本体とプラグインの版の分布

設定の効果

配った設定は効いたか

適用開始日を起点にした前後の推移・コンテキストのトークン数の分布

スキル・コマンドの利用

配ったものは使われているか

スキル・コマンドごとの利用

データと設定

CSV のアップロード・月ごとのダウンロード（ZIP）・会社の休日の登録

管理者の作業頻度
CSV のアップロード1〜2 週に 1 回程度
届き具合・エラー・未導入者の確認随時（未導入者には声かけ）
設定値・お知らせの変更変更時。プラグインの版を上げて配布用リポジトリ（Bitbucket）へリリース

アクセスは推測しにくい URL ＋ パスワード（社内 VPN の内側）。未導入者の一覧は CSV を取り込んでいる間だけ出せる。

問九

限界は

利用ログに厳密な正確性は求めない。

  • 取りこぼしは許容（長いオフライン・端末の上限超過・エラー時の記録）
  • プロジェクト単位の設定などで上書きされた場合、適用率に現れない
  • 端末ごとの停止に気づけるのは、記録が途絶えて 14 日後

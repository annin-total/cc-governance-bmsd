Claude Code 利用管理の仕組み

設定を全員の端末に配り、利用状況とコストを見える化し、その設定の効果を確かめる。

配る 集める
1サーバ停止でも配布は継続配る経路はサーバを通らない。止まるのは集計だけ。
2セッション開始時に適用変えても次の開始時に戻る。お知らせも表示。
310 分以上空けて送信開始時・応答完了時に、裏でまとめて送る。
4未送信は端末に保持14 日・20 MB まで。超えた分は古い順に捨てる。
2 本の経路は独立

サーバから端末へ指示を出す経路は無い。集計サーバが止まっても、設定とお知らせの配布は止まらない。

収集項目

収集する

  • 利用者（会社のメールアドレス・端末名）
  • イベントの種類・イベント時刻・セッション ID
  • ツール名・スキル名・コマンド名
  • コンテキストのトークン数・エフォート・権限モード
  • 本体とプラグインの版・設定の適用結果
  • プラグインのエラー（段階名と種類だけ）

収集しない

  • プロンプト・応答・会話の本文
  • ツールの入出力（ファイルの中身・コマンドの中身）
  • コスト・モデル名（CSV が正本）

利用者個人の監視はしない。目的は施策の評価。個人ごとの操作の時系列を見る画面は無い。リアルタイムにも見ない（設定の反映は分単位、コストは日次）。

やること

利用者

  1. 導入時に 1 回: （Windows）python3 と git のメールアドレスを確認、コマンド 2 つで導入
  2. 日常: 操作なし（更新も自動）

管理者

  1. 導入の案内を 2〜3 回に分け、1〜2 週ずつずらす
  2. 1〜2 週に 1 回: CSV をアップロード
  3. 随時: 届き具合・エラー・未導入者を確認
  4. 設定を変えるとき: 版を上げてリリース

配っている設定値

自動コンパクトの閾値
60% で実行
大きなコンテキストのまま払うコストを抑える。効果を測る対象
プラグインの自動更新
有効
設定値・お知らせの変更を全端末へ届ける
Claude Code 本体の自動更新
常に最新版
全員の版をそろえる。利用者が切っていても打ち消す
効果の読み方　コストの前後差は時期・業務量・料金でも動くため根拠にしない。効果は「コンテキストの大きさが小さい側へずれたか」で見る。

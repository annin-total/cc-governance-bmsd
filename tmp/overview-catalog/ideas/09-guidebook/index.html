Claude Code 利用管理
5 つの要点

設定を全員の端末に配り、利用状況とコストを見える化し、その設定の効果を確かめる仕組み。

対象: BMSD 本部の Claude Code 利用者（約 140 名）

1

目的

3 つの役割
設定の配布全員の端末へ同じ設定
見える化利用状況とコスト
効果の確認配った設定が効いたか

目的は施策の評価。利用者個人の監視をしない。リアルタイムにも見ない（設定の反映は分単位、コストは日次）。

3

端末での動き

1 セッションの流れ

セッション開始時設定の適用・お知らせ

  • 設定値を settings.json へ書き込み（変更前は自動でバックアップ）
  • 未読のお知らせを表示（関連ページを 1 回だけブラウザで開くことがある）

利用中イベントの記録

  • プロンプト送信・ツール使用・ツールのエラー・自動コンパクト・応答完了など
  • 端末内に記録（フックで記録）

セッション開始時・応答完了時まとめて送信

  • 前回の送信から 10 分以上経っていれば送信
  • 送れなかった記録は端末に残し、後で送信（14 日・20 MB まで。超えた分は古い順に捨てる）

記録・送信は裏で行い、Claude Code の操作を待たせない。エラーが起きても Claude Code は止まらない。端末には Python 3（python3 コマンド）が必要。

配る設定値

自動コンパクトの閾値60%大きなコンテキストのまま払うコストを抑える（効果の測定対象）
プラグインの自動更新有効設定値・お知らせの変更を全端末へ届ける
本体の自動更新常に最新版全員の版をそろえる（利用者が切っていても打ち消す）

利用者が変えても、次のセッション開始時に配った値へ戻る。

本文には触れない

集めるもの（端末から）

利用者

イベント
種類・イベント時刻・セッション ID

ツール名（MCP はサーバ名を含む）・サブエージェントによる使用か・中断か
スキル・コマンド
スキル名・コマンド名・出所
状態
コンテキストのトークン数（自動コンパクト直前・応答完了時）・エフォート・権限モード
版
Claude Code 本体・プラグイン
設定の適用結果
変更前の値・配った値・適用の結果

集めないもの

  • プロンプト本文・Claude の応答本文・会話内容
  • ツールの入出力（読み書きしたファイルの中身、実行したコマンドの中身）

  • コスト・モデル名（端末からは取らない）
CSV から入る項目
日付・メールアドレス・モデル・コスト・トークン数（入力・出力・キャッシュ）

CSV はコストとトークン数の正本。Claude Code 以外の利用も含む。

5

運用

利用者・管理者

利用者

導入時に 1 回
  1. （Windows）python3 の動作確認
  2. git の会社メールアドレスの確認
  3. 2 つのコマンドで導入
  4. 開き直してお知らせが出れば完了
日常
操作なし（更新も自動）。届かない場合だけ手動更新のコマンド 2 つ

管理者

導入時
案内を 2〜3 回に分け、1〜2 週ずつずらす（部署を横断）。効果を同時期のほかの変化と区別するため
1〜2 週に 1 回
AI Gateway の CSV を管理画面からアップロード
随時
データの届き具合・エラー・未導入者の確認。未導入者への声かけ
設定の変更時
プラグインの版を上げて配布用リポジトリへリリース
概況コスト・利用者数・月末のコスト見込み・データの届き具合・プラグインのエラー
設定の適用状況適用率・未導入者・記録が途絶えた端末（14 日以上）・版の分布
設定の効果適用開始日を起点にした前後の推移・コンテキストのトークン数の分布
スキル・コマンドの利用スキル・コマンドごとの利用

管理画面は 4 画面 ＋ データと設定（CSV のアップロード・月ごとのダウンロード・会社の休日の登録）。社内 VPN の内側で、推測しにくい URL ＋ パスワード。効果は「コンテキストの大きさが小さい側へずれたか」で見る。コストの前後差は時期・業務量・料金でも動くため、効果の根拠にしない。

限界
  • 取りこぼしは許容する（オフラインが長い・端末の上限超過・エラー時の記録）
  • プロジェクト単位の設定などで上書きされた場合は、適用率に現れない
  • 端末ごとの停止に気づけるのは、記録が途絶えて 14 日経ってから

CLAUDE CODE 利用管理

設定の更新から効果の確認まで

設定の配布全員の端末へ同じ設定を届ける
利用状況・コストの見える化端末の記録と AI Gateway の CSV を集計
設定の効果の確認配った設定が効いたかを見る

対象: BMSD 本部の Claude Code 利用者（約 140 名）。リアルタイムには見ない（設定の反映は分単位、コストは日次）。

流れ

配る経路（Bitbucket から各端末へ） 集める経路（各端末・CSV から集計サーバへ）
  1. 1

    設定の更新

    配る設定・お知らせを変えるとき
    誰
    管理者
    どこ
    配布用リポジトリ（Bitbucket・社内）
    何
    プラグインの版を上げてリリース。中身はプラグイン本体・設定値・お知らせ
  2. 2

    端末への自動配布

    配る分単位
    誰
    プラグインの自動更新
    どこ
    Bitbucket → 各端末（git）
    何
    新しい版が各端末へ届く。利用者の操作は不要

    集計サーバを経由しない。サーバから端末へ指示を出す経路は無いため、集計サーバが止まっても設定とお知らせの配布は止まらない。止まるのは集計だけ。

  3. 3

    セッション開始・設定の適用

    配るセッション開始時
    誰
    利用者（Claude Code ＋ プラグイン）
    どこ
    利用者の端末（Windows / macOS）
    何
    • 配られた設定値を settings.json へ書き込む（変更前の settings.json は自動でバックアップ）
    • 未読のお知らせを表示（関連ページを 1 回だけブラウザで開くことがある）
    設定値
    設定値狙い
    自動コンパクトの閾値コンテキスト 60% で実行大きなコンテキストのまま払うコストを抑える（効果の測定対象）
    プラグインの自動更新有効設定値・お知らせの変更を全端末へ届ける
    本体の自動更新常に最新版全員の版をそろえる（利用者が切っていても打ち消す）

    利用者が変えても、次のセッション開始時に配った値へ戻る。

  4. 4

    利用中の記録

    集める利用中
    誰
    プラグイン（フック）
    どこ
    利用者の端末内
    何
    プロンプト送信・ツール使用・ツールのエラー・自動コンパクト・応答完了などのイベントを記録

    記録と送信は裏で行い、Claude Code の操作を待たせない。エラーが起きても Claude Code は止まらない。

  5. 5

    まとめて送信

    集めるセッション開始時・応答完了時
    誰
    プラグイン
    どこ
    各端末 → 集計サーバ（AIP または One Cloud）
    何
    前回の送信から 10 分以上経っていれば、溜まった記録をまとめて送る。サーバはデータベースに保存して集計する

    送れなかった記録は端末に残り、後でまとめて送られる（14 日・20 MB まで。超えた分は古い順に捨てる）。

  6. 6

    CSV のアップロード

    集める1〜2 週に 1 回程度
    誰
    管理者
    どこ
    AI Gateway → 管理画面 → 集計サーバ
    何
    AI Gateway が日ごとに出す利用明細 CSV を取り込む。コストとトークン数の正本
  7. 7

    管理画面での確認

    随時
    誰
    管理者
    どこ
    ブラウザ（社内 VPN の内側。推測しにくい URL ＋ パスワード）
    何
    概況コスト・利用者数・月末のコスト見込み・データの届き具合・プラグインのエラー
    設定の適用状況適用率・未導入者・記録が途絶えた端末（14 日以上）・版の分布
    設定の効果適用開始日を起点にした前後の推移・コンテキストのトークン数の分布
    スキル・コマンドの利用スキル・コマンドごとの利用

    ほかにデータ管理の画面（CSV のアップロード・月ごとのダウンロード・会社の休日の登録）。概況の期間は 7 日 / 28 日 / 12 か月。

    効果は「コンテキストの大きさが小さい側へずれたか」で見る。コストの前後差は時期・業務量・料金でも動くため、効果の根拠にしない。

収集する項目・しない項目

目的は施策の評価。利用者個人の監視をしない（個人ごとの操作の時系列を見る画面は無い）。

収集する（端末から）

利用者
会社のメールアドレス（CSV との照合用）・端末名
イベント
種類・イベント時刻・セッション ID
ツール
ツール名（MCP はサーバ名を含む）・サブエージェントによる使用か・中断か
スキル・コマンド
スキル名・コマンド名・出所
状態
コンテキストのトークン数（自動コンパクト直前・応答完了時）・エフォート・権限モード
版
Claude Code 本体の版・プラグインの版
設定の適用結果
設定ごとの変更前の値・配った値・適用の結果
プラグインのエラー
処理の段階名・エラーの種類のみ（エラーメッセージは送らない）

収集しない

  • プロンプト本文・Claude の応答本文・会話内容
  • ツールの入出力（読み書きしたファイルの中身、実行したコマンドの中身）
  • コスト（端末では数えない。CSV が正本）
  • モデル名（端末からは取らない。CSV に含まれる）

CSV から入る項目
日付・メールアドレス・モデル・コスト・トークン数（入力・出力・キャッシュ）

CSV には Claude Code 以外の利用も含まれる。

限界
  • 取りこぼしは許容する（オフラインが長い・端末の上限超過・エラー時の記録）。利用ログに厳密な正確性は求めない
  • プロジェクト単位の設定などで上書きされた場合は、適用率に現れない
  • 端末ごとの停止に気づけるのは、記録が途絶えて 14 日経ってから

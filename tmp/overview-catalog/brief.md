# 指示書: 仕組みの紹介ページ

全案が共有する、読者・事実・語彙・形式の決まり。各案はここに書いた事実だけを使う。

## 読者と目的

- 読者は BMSD 本部の管理側・上長。非エンジニアだが、Claude Code の基本用語は知っている
- 目的は「何のための仕組みで、何をして、何をしないか」を短時間で正しく掴んでもらうこと
- 技術的な正確さより分かりやすさを優先する。ただし**下の「事実」を曲げない・盛らない**
- 現在の進み具合（デプロイ済みか等）は載せない。仕組みの説明に徹する

## 語彙

### そのまま使ってよい語

Claude Code、settings.json、フック、トークン、プロンプト、ツール、セッション、モデル、エフォート、

| 使わない | 代わりに |

| compact の直訳「圧縮」 / error の「失敗」 / context の「文脈」 | コンパクト / エラー / コンテキスト |
| ポリシー、policy | 設定、設定値 |
| 準拠、遵守 | 設定どおり、適用済み |

| 監視（利用者を見張る意味で） | 使わない。目的は「施策の評価」 |

### 文体

- 書き言葉で、やや固め。本文は体言止めか「である」調。砕けた表現・呼びかけ・感嘆をしない
- **見出し・項目名・ラベルは名詞句で短く。**散文にしない
  - 例: 「設定する値」→「設定値」、「イベントを記録した時刻」→「イベント時刻」、「収集するログ」→「収集項目」
- 冗長を削る。同じ意味なら短いほうを選ぶ
- 散文は避け、図・表・箇条書きで見せる。補足の散文は小さい文字・薄い色にする

## 事実（これ以外を書かない）

### 一言で

社内で使う Claude Code について、**設定を全員の端末に配り**、**利用状況とコストを見える化し**、**その設定の効果を確かめる**仕組み。対象は BMSD 本部の利用者（約 140 名）。

### しないこと

- プロンプト・応答・会話の本文を集めない
- ツールの入出力（ファイルの中身・実行したコマンドの中身）を集めない
- 利用者個人の監視をしない（目的は施策の評価。個人ごとの操作の時系列を見る画面は無い）
- リアルタイムに見ない（設定の反映は分単位、コストは日次）

### 構成要素

| 要素 | 置き場 | 役割 |
| --- | --- | --- |
| 配布用リポジトリ | Bitbucket（社内） | プラグイン本体・配る設定値・お知らせを置く。管理者が更新すると、端末へ自動で届く |
| 利用者の端末 | Windows / macOS（Claude Code ＋ プラグイン） | セッション開始時に設定を適用し、お知らせを表示する。利用中のイベントを記録し、まとめてサーバへ送る |
| 集計サーバ | AIP（または One Cloud） | 記録を受け取ってデータベースに保存し、集計して管理画面に出す |
| 利用明細 CSV | AI Gateway が日ごとに出す | コストとトークン数の正本。管理者が管理画面からアップロードする |
| 管理者 | ブラウザ | 管理画面で状況を見る。設定値・お知らせを変えるときは配布用リポジトリを更新する |

### 経路は 2 本に分かれている（最重要の構造）

- **配る経路**: 管理者 → Bitbucket → 各端末（git による自動更新）
- **集める経路**: 各端末 → 集計サーバ（ネットワーク送信）。別に、AI Gateway の CSV → 管理者 → 集計サーバ（アップロード）
- サーバから端末へ指示を出す経路は無い。そのため**集計サーバが止まっても、設定とお知らせの配布は止まらない。**止まるのは集計だけ
- 送れなかった記録は端末に残り、後でまとめて送られる（14 日・20 MB まで。超えた分は古い順に捨てる）

### 端末での動き（1 セッションの流れ）

1. セッション開始時: 配られた設定値を settings.json に書き込む（変更前の settings.json は自動でバックアップ）。未読のお知らせを表示する（関連ページを 1 回だけブラウザで開くことがある）
2. 利用中: プロンプト送信・ツール使用・ツールのエラー・自動コンパクト・応答完了などのイベントを、端末内に記録する（フックで記録）
3. セッション開始時と応答完了時: 前回の送信から 10 分以上経っていれば、溜まった記録をまとめて裏で送る
- 記録・送信は裏で行い、Claude Code の操作を待たせない。エラーが起きても Claude Code は止まらない
- 端末には Python 3（`python3` コマンド）が必要

### 配っている設定値

| 設定 | 値 | 狙い |
| --- | --- | --- |
| 自動コンパクトの閾値 | コンテキストが 60% に達したら実行 | 大きなコンテキストのまま払うコストを抑える（効果を測る対象） |
| プラグインの自動更新 | 有効 | 設定値・お知らせの変更を全端末へ届ける |
| Claude Code 本体の自動更新 | 常に最新版へ（利用者が自動更新を切っていても打ち消す） | 全員の版をそろえる |

- 利用者が変えても、次のセッション開始時に配った値へ戻る（強制）。利用者が選ぶ方式は無い
- ほかに「初回だけ書き込み、以後は利用者に任せる」配り方もできる（現在は使っていない）

### 収集する項目（端末から）

| 項目 | 内容 |
| --- | --- |
| 利用者 | 会社のメールアドレス（AI Gateway の CSV と照合するため）・端末名 |
| イベント | 種類（セッション開始・プロンプト送信・ツール使用・ツールのエラー・自動コンパクト・応答完了 など）・イベント時刻・セッション ID |
| ツール | ツール名（MCP はサーバ名を含む）・サブエージェントによる使用か・中断か |
| スキル・コマンド | 使ったスキル名・コマンド名・その出所 |
| 状態 | コンテキストのトークン数（自動コンパクト直前・応答完了時）・エフォート・権限モード |
| 版 | Claude Code 本体の版・プラグインの版 |
| 設定の適用結果 | 設定ごとの、変更前の値と配った値・適用の結果 |
| プラグインのエラー | 処理の段階名とエラーの種類だけ（エラーメッセージは送らない） |

### 収集しない項目

- プロンプト本文・Claude の応答本文・会話内容
- ツールの入出力（読み書きしたファイルの中身、実行したコマンドの中身）
- コスト（端末では数えない。CSV が正本）
- モデル名（端末からは取らない。CSV に含まれる）

### 利用明細 CSV（AI Gateway）から入る項目

日付・メールアドレス・モデル・コスト・トークン数（入力・出力・キャッシュ）。
注: CSV には Claude Code 以外の利用も含まれる。

### 管理画面（4 画面 ＋ データ管理）

| 画面 | 答える問い | 主な中身 |
| --- | --- | --- |
| 概況 | 全体でいくらかかり、誰が使っているか | コスト・利用者数・月末のコスト見込み・データの届き具合・プラグインのエラー。期間は 7 日 / 28 日 / 12 か月 |
| 設定の適用状況 | 誰の端末が設定どおりか | 適用率・未導入者（CSV に利用があるのに記録が届かない人）・記録が途絶えた端末（14 日以上）・本体とプラグインの版の分布 |
| 設定の効果 | 配った設定は効いたか | 適用を始めた日を起点にした前後の推移・コンテキストのトークン数の分布 |
| スキル・コマンドの利用 | 配ったものは使われているか | スキル・コマンドごとの利用 |
| データと設定 | — | CSV のアップロード・月ごとのダウンロード（ZIP）・会社の休日の登録 |

- アクセスは、推測しにくい URL ＋ パスワード（社内 VPN の内側）
- **効果の読み方**: コストの前後差は、ほかの要因（時期・業務量・料金）でも動くため、効果の根拠にしない。効果は「コンテキストの大きさが小さい側へずれたか」で見る
- 未導入者の一覧は、CSV を取り込んでいる間だけ出せる

### 運用

| 誰 | いつ | 何を |
| --- | --- | --- |
| 利用者 | 導入時に 1 回 | （Windows）`python3` が動くか確認 → 会社のメールアドレスが git に設定されているか確認 → Claude Code で 2 つのコマンドを実行して導入 → 開き直してお知らせが出れば完了 |
| 利用者 | 日常 | 操作なし（更新も自動。届かない場合だけ手動更新のコマンド 2 つ） |
| 管理者 | 導入を進めるとき | 案内を 2〜3 回に分け、1〜2 週ずつずらす（部署を横断して分ける）。施策の効果を、同時期のほかの変化と区別するため |
| 管理者 | 1〜2 週に 1 回程度 | AI Gateway の CSV を管理画面からアップロード |
| 管理者 | 随時 | 管理画面で、データの届き具合・エラー・未導入者を確認。未導入者に声をかける |
| 管理者 | 設定・お知らせを変えるとき | プラグインの版を上げて配布用リポジトリへリリース → 各端末へ自動で届く |

### 限界（載せるなら小さく）

- 取りこぼしは許容する（オフラインが長い・端末の上限超過・エラー時の記録）。利用ログに厳密な正確性は求めない
- プロジェクト単位の設定などで上書きされた場合は、画面の適用率に現れない
- 端末ごとの停止に気づけるのは、記録が途絶えて 14 日経ってから

## 形式の決まり（全案共通）

- `ideas/NN-<名前>/index.html` の **1 ファイルで完結**させる。外部の CSS・JS・フォント・画像を読まない（file:// で開け、Claude の Artifact でも同じに見えること）。図はインライン SVG か HTML/CSS で描く
- フォントはシステムフォント（例: `"Hiragino Sans", "Hiragino Kaku Gothic ProN", "Yu Gothic UI", "Meiryo", sans-serif`）
- **ライトテーマのみ**。`body` に背景色を明示する
- 横幅 1280px で最も良く見えること。375px でも横スクロールが出ないこと（崩れない程度でよい）
- `<title>` は 2〜4 語の名前（例: 「Claude Code 利用管理の仕組み」）
- 補足の散文は小さい文字（12〜13px 程度）・薄い色
- 絵文字を使わない

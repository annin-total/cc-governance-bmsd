## 重要な発見（速報。統合時に報告書へ）

- **設定が本体に捨てられると hook が無言で全停止する**（A: UC 01・13）: 型の違う値・壊れた JSON・2 MiB 超などで、本体が settings.json ごと読み捨てる。enabledPlugins も効かずプラグインが無効扱いになり、直した版も届かない。気づけるのは `claude doctor` だけ
- **既存の E2E は撤回を判定していない**（A: UC 06）: 壊した実装で合格し、正しい実装で偽の赤になる
- **本番の送信先を埋めると E2E 12 件が落ちる**（B: UC 50。推定どおり）。送信先が空のまま配っても全件緑
- **CSV の取り込みで無言の喪失**（B: UC 68）: 冪等キーが日なので、同じ日を含む別ファイルがその日を丸ごと置き換える
- **標準ライブラリ名のモジュールで hook が完全に無言**（C: UC 31）: exit 0・行 0 で、validate_plugin.py も合格にする
- MySQL が utf8mb4 以外だと絵文字 1 字でリクエスト全体が 500（B: UC 39）
- バグ候補: `_settings.py` のバックアップの先取り・0444 の上書き・`.tmp` の残留（A: UC 12・13）
- **契約違いの旧版の行が全損する**（C: UC 55）: `ts` を改名した版の event 行は、サーバが 200 を返して捨てるため、端末の spool からも消えてどこにも残らない。版を上げない再 publish は `plugin update` で届かず、警告も出ない
- **spool の破棄は無言**（B: UC 47）: 上限（5MB・7 日）での破棄は error 行にもログにも残らない。前段が 413 を返すと送信が最大 7 日詰まる
- **アンインストールで未送信のログを黙って失う**（A: UC 60）: data（queue・spool・既読）が消える。`statusLine` と配った値は残る
- **親の入口の変数を継いだ `-p` は人が見ずに既読にする**（A: UC 24）
- **一斉起動 20 本以上で SessionStart の hook がほぼ全部 timeout**（A: UC 14）: 設定の適用が抜ける。settings.json は一度も壊れなかったが、`_settings.py` の検査〜置換の窓で他者の書き込みを黙って上書きしうる
- 本文を送らないことの監査（C: UC 38）は、送信の全経路で漏れ 0 件（陽性対照 4 種は検出）
- **401/404 で error 行が送信回数の二乗で増える**（B: UC 46）: 401・404 は「届いた」扱いにならず、k 回で k(k+1)/2 行（k=40 で 820 行）。回復後の取りこぼし・重複は 0。`entry.sh` が exec しないため `docker stop` が 10 秒待つ
- **hook の遅延の主因は pyenv のシム**（C: UC 43）: hook 自体は 30〜60 ms、シムが 1 回あたり約 0.39 s。高負荷時は 5 秒のタイムアウトを超えうる（UC 14 の timeout と整合）
- **error 行の嵐で概況が遅くなる**（B: UC 76）: 1 年分・200 名（313 万行）で 4 画面は 0.1〜1.8 秒。直近 7 日に error 行 70 万で概況が 6.9 秒。`errors` は索引が無く ANALYZE の対象からも漏れている（UC 46 の二乗の増え方と組み合わさると現実的）

# D5 検証の仕組み の精査

## 1. 結論（5 行以内）
1. 報告書が E2E の穴として挙げたもの（撤回を判定しない・`cancelled` を見ない・送信を 1 回しか失敗させない・キーパスを全行で見る）は、いずれも今のコードで裏が取れた。
2. 最大の誤りは、送信先に関する P1 の 2 件（`conftest` での `pytest.exit` と、e2e.md の「送信先が空の開発ツリーで流す」）である。release.md は初回リリースの前に `plugin/config.json` へ本番の値を入れさせ、同時に `pytest e2e` の合格も前提にしている。このため、提案どおりにすると初回リリース以降は E2E が恒久的に流せなくなる。
3. `session()` に `outcome` の判定を足す案は「落ちることを確認済み」と書かれているが、確認されたのは stream-json に `cancelled` が出ることだけで、判定そのものは作っていない。この案は診断の改善にあたるので P2 が妥当である。
4. 取りこぼしは主に 3 つある。UC 32 の「送った値と DB の値・型を突き合わせる」案（スキル自身が認めている、同期忘れを通す穴を塞ぐ）、`_quiet` の 2 秒の静止という前提が高負荷では崩れうること、そして `CC_E2E_RUN` が e2e.md に書かれていないこと。
5. スキルに負荷試験の references を足す案（4.4 P3）は、実行用のスキルの範囲と使う頻度に対して重い。

## 3. 取りこぼし
- **送信先についての設計の食い違い（最重要）。** `release.md:10-13` は、`pytest e2e` の合格と、初回リリースの前に `plugin/config.json` へ本番の値を埋めることの両方を求めている。`release.md:51` の `diff -r` は、`plugin/` と配布物が一致することも求めている。一方 `_market.py:76-77` は、ローカル以外の送信先では publish を拒む。そのため初回リリースの後は、開発ツリーで E2E を 12 件落とす状態が恒常になる。`decisions/plugin.md:112-113`（空のまま置く）は、リリース後の状態に触れていない。報告書の P1（`conftest` の `pytest.exit`・e2e.md の前提）はこれを解消せず、E2E を丸ごと止める。そのうえ、送信先を上書きしていて本来は通る `test_send`・`test_leak`・`test_server` まで巻き込む。
- **UC 50 の notes の「配る `config.json` を機械で検査する」（https・非ローカル・トークンあり）が報告書の表に無い。** notes はこれを「唯一の防波堤」と呼んでいる。「端末から最後に届いた時刻」も 3.3 の本文にしか無く、改善案の表に載っていない。
- **UC 32 の E2E 案が落ちている。** `test_send` で、自分の `event_id` について queue の値と DB の値・型を突き合わせる案である。今の `test_send` は `event_id` が届いたことしか見ない（`test_send.py:53`）。この突き合わせがあれば、契約の同期忘れ（列が捨てられて NULL になる）と型のずれを E2E で捕まえられる。`.claude/skills/e2e/SKILL.md:61-62` が認めている「同期を忘れても合格する」穴を塞ぐものである。
- **`_quiet` の前提（推定・未検証）。** `e2e/_quiet.py:8-9` は、送信プロセスの起動の遅れを「数百 ms」とみなし、2 秒の静止で完了と判断する。ところが UC 43 では、シム経由の hook が高負荷で最大 5.95 s かかった。静止を早まって判断すると、`test_send.py:41`（spool が在ること）などが偽の赤になりうる。
- **`ask()` の経路は `outcome` を見られない。** `_flow.py:42-48` は stream-json を付けない。このため `session()` に判定を足しても、`test_collect`・`test_leak` の打ち切りは原因の読めない失敗のまま残る。
- **`test_notices.py:31-33` は `output` が空だと `JSONDecodeError` で落ちる。** 原因が読めない（UC 50 の notes の「範囲外」節）。報告書は触れていない。
- **UC 47 の E2E 昇格候補が黙って落ちている。** 「送信先が空の版で積み、送信先を入れた版へ上げると、積んだ分が届く」という 1 本である。
- **e2e.md が `CC_E2E_RUN` を書いていない。** 準備のコミット `0750fa0` は `_server.py` だけを変え、`e2e.md:179-180` は `cc-e2e=1` のまま残っている。

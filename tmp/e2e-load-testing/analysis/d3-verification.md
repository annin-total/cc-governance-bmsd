# D3 送信・蓄積・回復 の精査

## 1. 結論（5 行以内）
1. 送信・蓄積に関する報告書の観測事実は、コードで概ね裏が取れた。ただし「重複 0」「失敗の原因の断定」「401・404 に限定した書き方」に誤りと誇張がある。
2. 報告書が取りこぼした重大事項が 2 つある。1 つ目は release.md の手順の矛盾で、`plugin/config.json` を埋めて `diff -r` で一致させる手順のため、2 回目以降のリリースでは前提とする `pytest e2e` が 12 件落ちる。2 つ目は release.md:56 の誤りで、「401 の間もイベントは失われない」とあるが、実際には 7 日・5 MiB の上限で失われる。
3. 報告書の P2「5xx で送信を打ち切る」は害がある。UC39 の 500 を返し続ける 1 ファイルが先頭で後続を最長 7 日止め、その error 行も届かなくなる。error 行を 1 回の送信につき 1 行へ集約する方がよい。
4. 報告書の P1「conftest で `pytest.exit`」は、単独で入れると 2 のリリース手順と衝突する。手順の直しとセットで入れる必要がある。
5. UC50 の「DNS の失敗は無言」「E2E は送信先が空で緑」と UC77 の「打ち切りでの喪失」は、仕様・判断記録ですでに受け入れた限界である。新発見として扱わず、既存の記録を引いて書く。

## 3. 取りこぼし
- **リリース手順が自己矛盾している（P1）。**
  - `release.md:13` は `plugin/config.json` を埋めさせ、`:50` は `diff -r plugin/ 配布側` が差分なしであることを求める。つまり、初回リリースの後は開発ツリーに本番の URL が残る。
  - その状態で `:11` の前提 `pytest e2e` を流すと、`_market.py:77` で 12 件が落ちる（UC50 の run1 と同じ状態）。
  - `decisions/plugin.md:112`（「`plugin/config.json` の送信先は空のまま置く」）とも食い違う。
  - 報告書は UC50 を「E2E の穴」とだけ扱っており、2 回目以降のリリースが前提を満たせないことを見落としている。
- **release.md:56 の「端末は spool を保持するのでイベントは失われない」は誤り。**
  - 7 日（`_spool.py:127-131`）と 5 MiB（`:135-141`）の上限で失われる。
  - 401 の間は error 行が二次的に増え、本物のイベントを押し出す（UC46。約 30 時間の利用で始まる、推定）。
  - `:58` の「401 は spool が吸収する」も、短期間に限った話であると書く必要がある。
- **報告書 4.1 P2（5xx で打ち切り）の副作用。**
  - UC39 では、深い入れ子や MySQL の文字コードが原因で、同じファイルが毎回 500 を返した（`uc-39-long-values/notes.md:133-134`）。
  - 5xx で打ち切ると、名前の古い順に送るため、そのファイルが先頭で後続の正常なファイルを最長 7 日止める。500 の error 行も後続のファイルに入るので届かず、完全に無言になる。
  - `decisions/plugin.md:96-97` が避けている「キューが詰まる」と同じ型である。
- **staging で実際に届いたかを見ていない。**
  - 最初のセッションは `sent_at` が無いので即座に送る（`_spool.py:89-90`）。
  - それでも release.md の 7（staging）は版と動作を見るだけで、そのセッションの行が本番サーバに届いたかを見ない。
  - 送信先とトークンの誤りは端末では検出できない（上表）ので、配布前に止められる唯一の実物の確認機会を逃している。
- **プロキシの事実（UC50 notes）が報告書 4.5 に無い。**
  - 送信プロセスは `HTTPS_PROXY` に従って CONNECT を送る。
  - トンネルの失敗・名前解決の失敗・本文を読まない 413 は、いずれも記録されない。
  - 社内の PC で `HTTPS_PROXY` があると、社内の送信先に `NO_PROXY` が要る可能性がある（未確認）。
- **送信先の変更の扱い（UC46 (2)）が報告書に無い。**
  - spool は宛先を持たず、境界は「送った時刻」になる。サーバを移行するとき、旧側の件数で締めると少し欠けて見える。
- **UC77 notes の「hook 自体は普段 0.5 秒」は、pyenv のシムを含んだ数字である。**
  - `time_hook.py:34` は PATH の `python3` を起動している。UC43 の hook 本体は約 80 ms。

# UC68 CSV の取り込み（No.68・No.69・No.70）

## 目的

マスク済みの実 CSV（AI Gateway の日次コスト。7 月分・8 月分）を、本番と同じ経路（`CSV_DIR` に置いて管理画面の `POST /<ADMIN_PATH>/import`）で取り込み、次を確かめる。

1. 取り込み件数と DB の件数・コスト合計の一致、端末のイベントとの突合
2. 同じ CSV の再取り込みで重複しないか
3. 書式の変化（列の順序・追加・欠落・改名など。No.69）で、無言で壊れるか明示的に止まるか
4. 空セル・引用符・改行入りセル・BOM・CRLF・Shift_JIS などで壊れないか
5. 大きな CSV の取り込み時間
6. No.70: 突合率を意図的に下げたとき、画面とログから原因を追えるか

## 仮説（実装を読んで立てたもの）

- 冪等キーは `day`。取り込むファイルが含む日を `DELETE` してから `INSERT` するので、同じ CSV の再取り込みは重複しない
- その裏返しで、**同じ日を含む別ファイル（一部の行だけの訂正版など）があると、後から処理したファイルがその日の行を丸ごと置き換える**（ファイル名の昇順）。画面はどちらも成功と出す
- 必須列（契約の 12 列）の欠落・改名・大文字小文字・前後の空白はファイル単位のエラーで止まる。列の順序変更・列の追加は無言で通る（正しく動く）
- **同名の列が 2 つあると後ろの列が使われる**（`{name: i}` の上書き）
- 値の形が変わる（`$1.23`・`1,234.5`・トークンが `1.0`）と `coerce` が NULL にし、行は保存・破棄 0 件になる（**無言**）
- 日付の形が変わる（`08/01/2026`・時刻付き）と行ごと破棄され、破棄件数には出る
- BOM は `utf-8-sig` で剥がす。Shift_JIS は非 ASCII があれば `UnicodeDecodeError` でファイル単位のエラー、ASCII だけなら通る
- Python 3.9 の `csv` は NUL を含む行で `csv.Error` を出す（ファイル単位のエラー）
- 末尾の空行は `day` が無い行として破棄件数に数えられる
- 拡張子が `.CSV`（大文字）のファイルは `glob("*.csv")` に拾われず、画面に何も出ない
- 突合率の画面は分子・分母の人数だけで、どの利用者が合っていないかは出ない
- 取り込みは 1 リクエストの中で全ファイルを読み、全行をメモリに載せる。大きな CSV では時間とメモリが行数に比例して増える

## 手順

- `e2e/_server.py` の `DockerServer` で、本番に近い形（イメージ + entry.sh + BASE_PATH、SQLite）のサーバを 1 つ立てる
- 本番と同じ経路で取り込む: CSV を `docker cp` で `CSV_DIR` に置き、管理画面の取込ボタンと同じ `POST /<BASE_PATH>/<ADMIN_PATH>/import`（Basic 認証）を送る。
  結果は応答の HTML（`<p class="ok-box">…: N 行（破棄 M 件）</p>`・`<p class="err">…: 失敗（…）</p>`）から読み、DB（コンテナ内の python3 で SQLite を問い合わせ）と突き合わせる
- 実 CSV は読むだけ。変形版は実行時に作り、`.local/e2e-load-testing/uc-68-csv-import/stage/` に書いてから `docker cp` した（終了後に削除）。コンテナ内のファイル名は `jul.csv`・`aug.csv` などの中立な名前にした
- No.70 は、7 月分の最後の 7 日に使った利用者のアドレスを実行時に CSV から取り、`/ingest` にイベントとして送った（アドレスはどこにも書き出していない）
- 判定のゲート確認: `run.py` の `selftest()` が、壊した期待（行数・コスト・破棄件数・エラー文言・NULL 件数）で食い違いを返すことを、実行のたびに先に確かめる。
  加えて、同じ判定関数が「成功で通るケース」と「必須列エラーで止まるケース」「全行破棄のケース」の両向きで実データに対して期待どおりに動いた

実行コマンド（worktree のルートで）:

```bash
.venv/bin/python tmp/e2e-load-testing/uc-68-csv-import/profile.py <実 CSV のパス>...   # 構造の要約（値は出さない）
CC_E2E_RUN=b-uc68 .venv/bin/python tmp/e2e-load-testing/uc-68-csv-import/run.py        # 取込 36 ケース + No.70 の 4 ケース（約 1 分）
# heavy.lock を取ってから
CC_E2E_RUN=b-uc68 .venv/bin/python tmp/e2e-load-testing/uc-68-csv-import/big.py [行数...] # 既定 50000 200000 500000
```

- `lab.py`: 配置・取込・DB の問い合わせ・CSV の書き出し。`run.py`: 取込のケースと判定。`recon.py`: No.70。`big.py`: 大きな CSV。`profile.py`: 実 CSV の構造の要約

## 負荷の掛け方

`big.py` だけが重い（最大 50 万行・68 MB の CSV を 2 回取り込む）。`heavy.lock` を取ってから行い、終わってすぐ `rmdir` した。
行は 7 月分を複製し、月を 12 か月の範囲でずらし、12 巡ごとに利用者のアドレスを別名にした（日は 372 日に収まる）。

## 結果

時間は 1 回の測定で、相対値としてだけ使う。

**判定: 40 ケース（取込 36 + No.70 の 4）すべて仮説どおり。ただし仮説どおりに無言で壊れる・誤解を招くものがある（下の太字）。**

| --- | --- | --- |

### (4) 壊れやすい値

| 入力 | 扱い |
| --- | --- |
| `Cost` が空（10 行） | 保存・cost は NULL。日次コストは `COALESCE` で 0 として足す。概況 200 |
| `Date` が空（5 行） | 破棄（`破棄 5 件`） |
| **`User Email` が空（7 行）** | **空文字列 `""` で保存。利用者数が 140 → 141 になる（空文字列を 1 人と数える）** |
| 引用符・カンマ・改行入りのセル（`Model` の 3 行） | 保存（改行もそのまま）。概況 200 |
| BOM + CRLF／BOM + LF／CR だけ | すべて正しく取り込む |
| Shift_JIS（実 CSV は ASCII だけなのでそのまま） | 正しく取り込む |
| Shift_JIS で日本語を 1 セル含む | `失敗（'utf-8' codec can't decode byte 0x8e …）`（英語の例外文） |
| UTF-16（BOM 付き） | `失敗（'utf-8' codec can't decode byte 0xff …）` |
| NUL を含むセル | `失敗（line contains NUL）`（Python 3.9 の `csv`） |
| 末尾の空行 3 つ | 保存は 3,144 行、**`破棄 3 件` と出る**（空行を日付の無い行として数える） |
| 列の足りない行・多すぎる行 | 足りない列は NULL、余りは捨てる |
| **拡張子が `.CSV`** | **何も取り込まず、画面に何も出ない**（`glob("*.csv")` が大文字を拾わない） |
| 0 バイトのファイル | `0 行` |
| `User Email` の大文字（50 行） | 小文字にそろえて保存 |
| `Cost` が `NaN`／`-1.5` | `NaN` は NULL（SQLite が NaN を NULL にする）、負の値はそのまま |

### (5) 大きな CSV（`big.py`）

| 行数 | CSV | 取込 1 回目 | 取込 2 回目（全日の DELETE + INSERT） | コンテナのメモリの最大 | 取込後の概況 |
| --- | --- | --- | --- | --- | --- |
| 5,000 | 0.7 MB | 0.15 秒 | 0.11 秒 | 32 MiB | 0.07 秒 |
| 50,000 | 6.8 MB | 3.3 秒 | 2.6 秒 | 112 MiB | 0.20 秒 |
| 200,000 | 27 MB | 12.4 秒 | 12.8 秒 | 545 MiB | 0.32 秒 |
| 500,000 | 68 MB | **93 秒** | 78 秒 | **1,509 MiB** | 0.62 秒 |

- メモリは `docker stats --no-stream` を約 1〜2 秒ごとに読んだ最大値（粗い）。20 万 → 50 万行で時間が 7.5 倍になるのは、メモリの圧迫（3 GiB の VM）によると推測する（未確認）
- 実データの規模（140 人・月 2〜3 千行）なら 1 年分で約 3.8 万行、取込は数秒の見込み（推定）。ただし取込ボタンは **CSV_DIR の全ファイルを毎回取り直す**ので、月ごとのファイルを溜めるほど遅くなる
- 取込は同期のリクエストで行う。`e2e/_server.py` の `request` の既定タイムアウト（30 秒）は 50 万行で超える。AIP の前段のタイムアウトは確かめていない

### No.70（突合率の低下の調査）

7 月分を取り込み、7 月の最後の 7 日に使った利用者のアドレスでイベントを送った（窓は `min(今日, CSV の最終日)` で終わる 7 日）。

| 送ったもの | 概況の突合率のタイル |
| --- | --- |
| CSV にある 20 人 | `20 / 20 人` |
| + 別ドメインの 5 人（`<ローカル部>@alias.example.invalid`） | `20 / 25 人` |
| + CSV のアドレスを大文字にした 3 人 | `20 / 28 人` |

- タイルは正しく下がる。**合わない利用者は 4 画面にもサーバのログにも 1 回も出ない**（出現を数えて 0）。画面から原因は追えない
- SQL では追える: `SELECT DISTINCT user_email FROM events WHERE user_email NOT IN (SELECT user_email FROM cost_daily)` で 8 人、そのうち `LOWER()` で一致するのが 3 人（大文字小文字だけの違い）
- サーバは CSV の `User Email` を小文字にそろえるが、`/ingest` の `user_email` はそろえない（端末が小文字にして送る前提）。小文字化しない旧版の端末や直接の送信があると、大文字小文字だけで突合が外れる

## 想定外だったこと

- 月によって `Date` の書式（`YYYY-MM-DD` と `YYYY/M/D`）と指数表記の大文字小文字が変わる。実装は両方を読めたが、E2E の見本 CSV（`e2e/samples/cost_daily.csv`）は `YYYY-MM-DD` と小数だけなので、8 月の書式は E2E では通っていない
- 空の `User Email` が NULL ではなく空文字列で入り、利用者数に数えられる
- 全行が破棄されたファイルも、成功と同じ緑の枠で出る
- 末尾の空行が破棄件数に数えられる（誤警報になる）
- 最初の実行で、ruff の import 並べ替えが `lab.py` の `sys.path` 設定より前に `_server` を読む順にした（一時スクリプトの書き方の問題。各スクリプトの先頭で `sys.path` を整える形に直し、再実行して同じ結果を確かめた）

## 課題と改善案

### サーバ側の修正案（優先度順）

1. **同じ日を含む複数ファイルを検出する（P1。無言のデータ喪失）**: `import_all` で、ファイルごとの日の集合が重なったら、画面に「`a.csv` と `b.csv` が同じ日（N 日分）を含む。`b.csv` で置き換えた」と出す（止めるか警告に留めるかは設計判断）。
   あわせて、各ファイルの結果に「置き換えた既存の行数」を出す（DELETE の `rowcount`）。`server/tests/test_ingestion_csv_scan.py` に「重なる 2 ファイルで警告が出る」テストを足し、検出を外すと落ちることを確かめる
2. **値の形の変化を検出する（No.69 の無言の破損）**: `_extract_row` で「元のセルが空でないのに `coerce` が NULL にした」件数を列ごとに数え、結果に出す（例: `Cost: 3,144 行が数値として読めない`）。
   全行が破棄されたファイル（`rows == 0 and dropped > 0`）は `err` の枠で出す
3. **同名のヘッダを拒否する**: `_resolve_header_index` で、必須列の名前が 2 回以上現れたら `ValueError`（必須列の欠落と同じ扱い）
4. 空の `User Email` を NULL にそろえる（`coerce` の後で `""` → None）。利用者数の水増しを防ぐ
5. 拡張子を大文字小文字を問わずに拾う（`glob` ではなく `os.listdir` + `name.lower().endswith(".csv")`）。または対象外として見つけたファイル名を画面に出す
6. 末尾などの空行（`[]`）は破棄に数えずに読み飛ばす
7. 文字コードの失敗を日本語で案内する（例: 「UTF-8 として読めない。Shift_JIS なら UTF-8 で保存し直す」）。cp932 への自動切り替えは設計判断（今の実 CSV は ASCII だけで、要らない見込み）
8. 突合: 合わない利用者（または人数と「大文字小文字だけの違い」の人数）を概況に出すかは設計判断（アドレスの表示が要る）。最低限、`/ingest` でも `user_email` を小文字にそろえることを検討する
9. 規模: 実データの規模では不要（YAGNI）。数十万行を扱うなら、ファイル全体の `list(csv.reader)` をやめて行ごとに読み、まとめて INSERT する。取込をリクエストの外に出すかは AIP の前段のタイムアウト次第

未検証: MySQL で `NaN`・`inf` の cost を INSERT したときの挙動（SQLite は NULL にする）。`_import_file_or_error` は pymysql の例外を捕まえないので、ファイル単位の失敗ではなく取込全体が 500 になる可能性がある（推測）。`server/tests` の MySQL 版か UC39 の `mysql.py` の形で確かめる

### `e2e/` の追加・修正

- `e2e/test_server.py` の取込テストに、**同じ CSV を 2 回取り込んで DB の件数が変わらない**ことと、**必須列を消した CSV で「失敗」が出る**ことを足す（共有の `server` fixture で数秒）。網羅（書式・値の形）は `server/tests` に置く
- `e2e/samples/cost_daily.csv` に、8 月分の書式（`YYYY/M/D`・指数表記 `E-`）の合成行を 1〜2 行足す
- `DockerServer` に `sql(query)`（コンテナ内の python3 で SQLite を問い合わせる）を足す。UC39・UC68 の一時スクリプトで同じものを書いた
- `DockerServer.request` にタイムアウトの引数を足す（大きな取込で 30 秒を超える）

### `docs/guide/e2e.md` の修正

- サーバ章に書く: 取込の結果は「`<ファイル名>: N 行`」が出ても合格と見ない。行数・破棄件数・列ごとの NULL を DB で確かめる。冪等キーは `day` で、同じ日を含む別ファイルは黙って置き換わる
- 「実物でも確かめられない限界」に、本番の CSV の書式の揺れ（月ごとの日付書式）は見本 CSV の範囲しか通らないことを書く

### e2e スキルの拡張

- No.68・69 の依頼では、「取込を押して成功が出た」で終えず、DB の件数・合計・NULL を確かめる手順を示す。このフォルダの `run.py` の形（変形を実行時に作り、画面の結果と DB を突き合わせる）を雛形にする
- No.70 は E2E の範囲外と答えつつ、調べる SQL（上の 2 本）を示す

### `docs/knowledge/` に足す外界の事実（実測）

- AI Gateway の日次コストの CSV（2026 年 7・8 月分で確認）: 15 列・CRLF・BOM なし・ASCII だけ。**`Date` の書式が月で変わる（`YYYY-MM-DD` と `YYYY/M/D`）**、`Cost` に指数表記（`e-` と `E-`）、`(Date, User ID, Model, Provider)` で一意、メールアドレスは小文字、`Currency` は USD だけ。利用者 140 人で月 2〜3 千行

# 案 32 分けて並べる

設計（`../../concepts.md`）6 章の案 32。骨組み（ページ・問い・群・タブ・窓）は案 31 と同じで、カードの分け方とチップの見せ方だけを変える。

- 狙い: 1 枚 1 指標。合計の増え方と、営業日数の違いを除いた増え方を並べて読む
- 31 との差: `cost` を `cost_total`（札なし・チップは合計の率）と `per_bd`（1 営業日あたり。札とチップの率を持つ）に分ける。`top_spenders` から `top10_share` を分ける
- 概況のコストの群は `cost_total`・`per_bd`・`per_user_bd` の 3 枚で、概況は計 11 枚。コストと利用者は 12 枚
- コストの群の並びは 合計 → 1 営業日あたり → 1 人あたり → 上位 10% → コストの多い利用者 → モデル → キャッシュ。広いカードの前に 1 列のカードを 4 枚置き、右の列が空かないようにした
- 見せ方: `look.delta` を `{ arrow: true, color: "better" }`（▲▼ を付け、改善だけ青）。絞り込みは薄くする（既定）
- 強み: 合計・1 営業日あたり・1 人あたりが 1 行に並ぶ。カードの添える数字が短い（31 の `cost` は 2 行に折れる）
- 弱み: 合計（札なし）と 1 営業日あたり（札あり）が隣り合い、合計に札が無い理由の説明が要る。概況のコストの群が 3 枚で右の 1 列が空く
- 撮影で気づいたこと:
  - コストの多い利用者は上位 10% を添えない `top_spenders_only` にし、`top10_share` との重複を避けた
  - 改善だけ青のため、悪化と中立（自動コンパクト・受信した記録・モデル）が同じ灰の ▲▼ になり見分けられない
  - `per_bd`・`per_user_bd` の添える数字の末尾（「日」「営業日」）が 1 文字だけ次の行に落ちる。12 か月では 2 枚とも内訳が無く下半分が空く
  - 7 日のデータでは営業日数が前後とも 5 日で、合計と 1 営業日あたりの率が同じ（+13.4%）になり、分けた意味が画面で見えにくい
  - 概況の「下書きを作る」は `per_bd` の札を拾い「1 営業日あたりのコスト」の行になる（31 は「コスト（利用明細）」）
- 撮影: `python kit/shoot.py ideas/32-split`（`shots/`）。`x-go-cost` は概況の最初のカードから移った先。`shots.json` で `x-go-per-bd`・`x-go-cost-total`・`x-cost-open-top10` を足す。検査: `python kit/check.py ideas/32-split`
- 基準日を変えても値は変わらない（モックの制約。データは 09/18 の 1 時点だけ）

# 案 41 基本の並び

ページの責務を分けたまま、各ページのカードを優先度順に 1 つの格子に流す。利用者ごとの一覧はページごとに列を分けて持つ。
見せ方の 4 点（基準超え・コスト・バージョン・ヘッダー）は、画面の右上の比較用の切り替えで 1 点ずつ変えて見比べる。

## ページごとのカードとタブ

| ページ | カード（表示の順） | タブ |
| --- | --- | --- |
| 概況 | サマリー → コスト → 1 人 1 営業日あたり → 月末の見込み → 利用者数 → 基準超え（7 日は日次・週次、28 日は月次）→ 設定の適用 → 本体の未更新 → プラグインの未更新 → プラグインのエラー | なし |
| コストと利用者 | コスト → 1 人 1 営業日あたり → 月末の見込み → 利用者数 → 基準超え → 継続率 → モデル別の内訳 | 利用者ごとのコスト・基準を超えた利用者・日ごとのコスト（12 か月は週ごとのコスト）・モデル・今月のコスト・月ごとの推移（12 か月）・課ごと |
| 利用状況 | 利用日数・指示・セッション（1 人あたり）→ スキル・コマンド・外部ツール・サブエージェント → セッションの大きさ・自動コンパクト・キャッシュ読み込み・確認なしモード | 利用者ごとの頻度・利用者ごとの呼び出し・日ごとの利用・呼び出し先・セッションの大きさ・使われ方 |
| 設定の適用状況 | すべて適用・未適用のある利用者・プラグイン未導入 → 本体の未更新・プラグインの未更新 → 設定ごとの適用率 | 利用者ごとの適用状況・設定ごと・バージョン |
| 設定の効果 | しきい値を守り始めた利用者・セッションの大きさ・自動コンパクト・1 人 1 日あたりのコスト | セッションの大きさ（前後）・日ごとの 1 人あたり |
| 収集の状態 | 受信した記録・記録が途絶えた利用者・プラグインのエラー・項目の欠け・利用明細との照合率・利用明細の鮮度 | 利用者ごとの届き方・受信と項目の欠け・プラグインのエラー |

- 2 列幅のカード（コスト・スキルなど）の前に空いた列は、後ろの 1 列のカードで埋まる。そのため画面の並びは表の順と前後することがある
- キャッシュ読み込みの割合は、コストと利用者のモデルのタブへ移る

## 切り替えの見方

既定は `over=O2`・`cost=C31`・`ver=V3`・`head=H1`。URL の問い合わせで選び、押した値はタブを閉じるまで覚える。

| 問い合わせ | 値 | 意味 |
| --- | --- | --- |
| `?over=` | `O1` | 注意以上の人数を大きく出し、要確認と注意を 1 行に並べる |
| | `O2` | 要確認の人数だけを大きく出し、注意は灰色の 1 行。注意の札を出さない |
| | `O3` | 要確認と注意を 2 つの大きな数字で並べる（2 列幅） |
| | `O4` | 見出しを金額（「1 日 $100 以上」）にし、要確認だけを数える。注意と基準の説明を出さない |
| | `O5` | 概況は O4、コストと利用者は O1 |
| `?cost=` | `C31` | コストを 2 列幅の 1 枚にし、合計と 1 営業日あたりを並べる |
| | `C32` | 合計（札なし）と 1 営業日あたり（札あり）の 2 枚 |
| `?ver=` | `V1` | バージョンの帯を 最新・1 つ前・2 つ以上前 の 3 段の色に。エラーは処理段階ごとの帯 |
| | `V2` | バージョンの帯を 最新・未更新 の 2 色に。エラーは処理段階ごとの帯 |
| | `V3` | 帯は V1 と同じ。エラーは件数の多い種類の上位 3 行 |
| `?head=` | `H1` | ヘッダーの右端にサマリーとデータと設定 |
| | `H2` | サマリーをページの並びに入れ、右端はデータと設定だけ |

# プラグインのローカル検証

開発中の `plugin/` を、本物の `~/.claude/` から切り離した Claude Code で試す。
操作は `pdev.py` 1 本で済む（macOS・Windows 共通。標準ライブラリだけで動く）。本物の設定・履歴・認証には触れない。

仕組み:

- `run/config/` を `CLAUDE_CONFIG_DIR` にした隔離環境で起動する
- `plugin/` を `run/mp/` の擬似マーケットプレイスにコピーし、本番と同じ名前（`governance@cc-marketplace-governance-bmsd`）でインストールする
- コピーした `config.json` だけを書き換え、送信先をローカルのサーバ（`http://127.0.0.1:15000/ingest`、トークン `dev-token`）に向ける。リポジトリの `config.json` には触れない
- Claude Code 本体の自動更新は止める。本体は本物の環境と共有しているため

## 準備

送信先のサーバを起動しておく（`管理画面のローカル起動.md`）。起動していなくても試せるが、そのあいだは端末側に溜まるだけになる。

Windows では、`python3` で Python が起動することを先に確かめる。プラグインの hook は `python3` で動き、通らないと何も起きない（`docs/guide/onboarding.md`）。

## 起動

別のターミナルで、試したい作業フォルダに移動して:

macOS:

```bash
python3 <リポジトリ>/tmp/user-guide/plugin-local/pdev.py
```

Windows:

```powershell
py <リポジトリ>\tmp\user-guide\plugin-local\pdev.py
```

起動のたびに `plugin/` をコピーし直す。初回だけ、擬似マーケットプレイスの登録とインストールが走る。
**初回はテーマの選択とログインを求められる。**ログイン情報は隔離環境の側に残るので、2 回目からは要らない。

引数は `claude` にそのまま渡る（例: `pdev.py -p "hi" --model haiku`、`pdev.py --resume`）。

## コードを変えたら

- Python・`config.json` などの同梱データ: もう一度 `pdev.py` を実行すれば反映される。起動中のセッションに反映したいときは、別のターミナルで `pdev.py -p hi` のように 1 回だけ実行してコピーし直す
- `hooks/hooks.json`: セッションを開き直す

## 見る場所

`run/config/` の中:

| 見たいもの | 場所 |
| --- | --- |
| プラグインが書き換えた設定 | `settings.json`（`governance/backups/` が書き換え前の控え） |
| 送信待ちのイベント | `plugins/data/governance-cc-marketplace-governance-bmsd/queue.jsonl` |
| 届いたデータ | 管理画面 <http://127.0.0.1:15000/dev-admin/> |

送信は 10 分に 1 回まで（セッション開始時か応答の終わりに判定する）。すぐに見たいときは `plugins/data/.../sent_at` を消してから、もう 1 回やり取りする。

## 終了

セッションを終えるだけでよい。隔離環境は残しておいてかまわない（次回はログインなしで起動できる）。

まっさらな状態からやり直すときは、`pdev.py clean`。

`run/` を消す。macOS では隔離環境のログイン情報（Keychain の `Claude Code-credentials-<8桁>`）も消す。本物の認証は消えない。次の起動では再びログインが要る。

## やってはいけないこと

- `CLAUDE_CONFIG_DIR` を付けずに `claude plugin install` を実行する（本物の `~/.claude/` に入り、`settings.json` が書き換わる）
- `run/mp/` の中を編集する（次の起動で上書きされる。`plugin/` のほうを直す）
- `INGEST_URL` を本番の受信先にする

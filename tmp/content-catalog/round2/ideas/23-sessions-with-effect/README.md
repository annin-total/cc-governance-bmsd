# 案 23 セッションに効果を寄せる

**狙い**: 設定の効果を、同じ指標（セッションの大きさ・自動コンパクトに達した割合）の今の値の隣に置く。利用・呼び出し・セッション・コストを 4 ページに分け、設定の適用と受信を端末のページにまとめる。トップを置かない。

| ページ | 問い（群 · タブ数） |
| --- | --- |
| 利用 | 誰が、どれだけの頻度で使っているか（利用者 · 3） |
| 呼び出し | 案 21 と同じ（4） |
| セッション | セッションはどれだけ大きく、しきい値を守り始めた前後でどう並ぶか（使われ方・しきい値の前後 · 4） |
| コスト | いくらかかり、誰とどのモデルに集まり、利用明細と記録が揃っているか（利用明細の利用者・コスト・今月・記録との照合・利用明細 · 6〔12 か月〕） |
| 端末 | 配った設定と最新版が端末に入り、記録が欠けずに届いているか（適用・版と報告・受信〔7 日固定〕 · 6） |

**強み**: 前後の値が同じ指標の直近の値と同じページに並ぶ。12 か月でもセッションのページは前後の群が残る。
**弱み**: コストのページが 5 群・15 枚で最も重く、問いが 2 つになる。期間のあるページに期間で動かない群（前後）が入る。端末が 6 タブで上限。トップが無い。

## 撮影で気づいたこと

- コンソールのエラー 0・横スクロール無し。押せないカードは `csv_freshness` だけ
- セッションのページに「セッションの大きさ（中央）」「自動コンパクトに達した割合」が同じ名前で 2 枚ずつ並び、値が違う（79k と 70k など）。群の見出しと窓の注記で区別するしかない
- 12 か月のセッションのページは、使われ方の群が 1 行の断りになり、前後の群とそのタブ（先頭に並び替わる）だけが残る。空にはならない
- 12 か月のコストのページでは、記録との照合の群（窓 `match`）が 1 行の断りになり、記録の無い利用者のタブも「出しません」になる。12 か月に限り照合の問いが消える
- 利用の「利用者ごとの使い方」のタブはセッションの大きさ・自動コンパクトの列を持ち、セッションの話が利用のページにも出る（タブの中身は目録のまま）
- 12 か月の空のページ（利用・呼び出し）の見え方は案 21 と同じ

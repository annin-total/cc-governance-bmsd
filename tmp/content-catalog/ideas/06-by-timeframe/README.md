# 案 06 時間軸で分ける
**狙い**: 期間の切り替えをページに置き換え、切り替えで出たり消えたりするカードを無くす。
| ページ | 問い |
| --- | --- |
| 今月 | 今月はいくらで着地し、誰に集まっているか |
| 直近（7・28 日だけ） | 最近、誰が何にどれだけ使っているか |
| 1 年（12 か月固定） | 利用とコストはどう伸びてきたか |
- **消える**: 期間の切り替えの 12 か月、概況・設定の適用状況・設定の効果・スキル・コマンドの利用のページ、K113・K114・T42。**足す**: 今月の利用者の順位、K10・K12・K21・K23・K24・K30・K40・K41・K52・K53・K63・K83、T04〜T06・T08・T24
- **強み**: 12 か月で空になるページが無い。時間の問いとページが 1 対 1
- **弱み**: 直近が 4 群・20 枚・9 タブで最も重い。設定と受信が「直近」に入るのは時間軸として不自然
- **足した値**（`data-extra.js`）: `fixed.cal`（暦月 × 利用者。生成は `../08-monthly-report/build_extra.py`）。末尾で `meta.periods` を 7・28 に絞り、直近の切り替えから 12 か月を外す（撮影の 12m は 7 日と同じになるため消した）
- 端末ごと（T21）に本体の版の列を足した（`fixed.m.core_by_terminal` を端末に結合）
- 足した部品: `parts.js`（concepts.md 3 節の K・T を定義にした辞書。05〜08 で同じ写し）・`extra.css`（タブ・区分が多いと重なるため折り返す、利用者・モデルの列を折り返さない）
- **足すと良い収集**: `event_plugin_version`（1 年のページに版ごとの推移を出す）

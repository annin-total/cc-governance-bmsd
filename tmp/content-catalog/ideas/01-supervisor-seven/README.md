# 案 01 監督の 7 ページ

- **狙い**: 過去の監督案（トップ＋6 ページ）を決まりに合わせて描き、ほかの案の基準線にする
- **ページ**: トップ（全体でいま何を見るべきか）・利用（誰がどれだけの頻度で使っているか）・コスト（いくらかかり、誰に集まっているか）・スキルとコマンド（配ったものや機能が使われているか）・設定の適用状況（配った設定が有効か）・設定の効果（しきい値は働いているか）・収集の状態（数字の元が正しく届いているか）＋データと設定
- **消える / 足す**: 概況を解体し、報告停止を収集の状態へ。頻度（K02〜K05）・利用明細の人数（K10〜K13）・順位と集中（K23・K24・T04）・モデルとキャッシュ（K40・K41・T06）・記録の無い利用者（T32）を足す
- **強み**: ページごとに問いが 1 つ。設定の適用状況は「値が合っているか」に閉じる
- **弱み**: 7 ページでカードが薄い。トップは参照だけでも 9 枚あり、縦に長い。利用の群「利用明細」とサブエージェント・報告停止のカードは、同じページに開く先のタブが無く押せない（木のとおり）
- **足した値**: 12 か月の継続率（暦月ごと・`m.retention_rows`）・T32 の 2 並びの結合 `m.uncollected_rows`・T08 の系列 `x.model_keys`・コマンドの定義元の空欄を「記録なし」に `x.command_source`
- **足した値**（`data-extra.js`。スクラッチパッドの `extra.py` が data.js と seed の DB から作る）: 利用明細の利用者だけの並び `x.billed`・記録の利用者だけの並び `x.activity`・端末に本体の版を結合 `fixed.x.terminals`
- **足した部品**: `parts.js`（concepts.md 3 節の K・T の辞書と窓。案 01〜04 で同じ写し）。`index.html` は kit の写しに `data-extra.js`・`parts.js` の 2 行を足しただけ。12 か月では出るタブを先に並べる。トップのカードは ia.js で参照元ページのタブへのリンクに書き換える
- **足すと良い収集**: `post_compact_context`（しきい値の直接の測定）、`event_plugin_version`（収集の状態を版ごとに）

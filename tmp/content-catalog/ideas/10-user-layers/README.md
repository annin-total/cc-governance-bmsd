# 案 10 利用者の層を軸にする

**狙い**: 人数の合計ではなく、よく使う人・ときどき使う人・たまに使う人・使い始めた人・離れた人の層で利用を見る。コストとスキルも層で割る。
- **利用者の層** — 使う人の中身はどう分かれ、どう移っているか
- **コスト** — いくらかかり、どの層・誰に集まっているか
- **スキルとコマンド** — どの層まで機能が届いているか
- **設定と端末** — 設定が入り、端末が記録を送っているか
**今から消えるもの**: 概況・設定の効果のページ（コストの前後）・スキルとコマンドの呼び出し回数のカード（タブで読む）。**足すもの**: 層の人数・層ごとのコスト・層ごとのスキルの割合・層の移り変わり・状態ごとのコスト（K86）。
**強み**: 「人数は増えたが、よく使う人は増えていない」を 1 枚で言える。一覧を層の区分で絞れる。
**弱み**: 層の境（営業日の利用率 60%・20%）が仮の基準。seed が一様な乱数のため、ほぼ全員がよく使う人になり、見た目では差が出ない。層は利用明細の窓、使い方は記録の窓で、層の一覧は 2 つの窓の列が並ぶ。
**足した値・部品**（`index.html` は kit の写しに `data-extra.js` の読み込みを 1 行足した）: `data-extra.js`（seed の DB から計算）に、利用者ごとの層（`x.people[].layer`）、層ごとの人数・コスト・スキルの割合（`x.layers`）、前の期間の層 × 今の層（`x.layers.moves`）、12 か月の暦月ごとの層と継続率（`x.month_layers`）、端末ごとの本体の版。12 か月の層は 12 か月の営業日の利用率で分ける。層の移り変わりは列ごとの `each` で行列にした。
**足すと良い収集**: `headcount_adoption_rate`（社員名簿で使っていない人を層に加える。部署ごとの層）。

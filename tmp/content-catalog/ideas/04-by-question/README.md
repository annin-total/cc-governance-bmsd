# 案 04 問いで分ける

- **狙い**: ページにも群にも問いを 1 つずつ書き、カードを群あたり 4 枚までに絞る
- **ページ**: 人数と頻度（何人が、どれだけの頻度で使っているか）・支出（いくらかかり、どこに集まっているか）・作業の中身（何をどう任せているか）・設定の適用（配った設定が効いているか）・データの確かさ（この画面の数字は信用できるか）＋データと設定
- **消える / 足す**: 概況・設定の効果（前後差 K113・K114・T42 を出さない）・スキル・コマンドの利用のページ、K50・K51 のカード。増えた利用者（K26）・任せ方（K06・K07・K67・T15）・鮮度（K108）・記録の無い利用者（T32）を足す。T05 は列を頻度に絞る
- **強み**: 群の見出しがそのまま読み方になり、1 画面で読み切れる
- **弱み**: 群の見出しが文で長い。人数の群（利用明細）と確認なしの群は同じページに開く先のタブが無く押せない。コストの前後差をやめるのは新しい判断
- **足した値**: 増えた順の並び `x.gainers`（K26）・12 か月の継続率 `m.retention_rows`・T32 の結合 `m.uncollected_rows`
- **足した値**（`data-extra.js`。スクラッチパッドの `extra.py` が data.js と seed の DB から作る）: 利用明細の利用者だけの並び `x.billed`・記録の利用者だけの並び `x.activity`・端末に本体の版を結合 `fixed.x.terminals`
- **足した部品**: `parts.js`（concepts.md 3 節の K・T の辞書と窓。案 01〜04 で同じ写し）。`index.html` は kit の写しに `data-extra.js`・`parts.js` の 2 行を足しただけ。12 か月では出るタブを先に並べる
- **足すと良い収集**: `turn_failure_rate`（応答が失敗していないか）、`tool_duration`（作業の重さ）

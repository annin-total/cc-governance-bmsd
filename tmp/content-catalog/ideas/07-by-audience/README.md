# 案 07 見る人で分ける
**狙い**: 管理者の日常・月次の報告を作る人・プラグインの保守者に 1 ページずつ渡し、点検項目を利用状況から外す。
| ページ | 問い |
| --- | --- |
| 利用状況（7・28 日だけ） | 誰がどれだけ、何に使い、いくらかかっているか |
| 報告 | 報告に載せる今月・前月・1 年の数字は何か |
| 運用の点検 | 端末・設定・収集は正しく動いているか |
- **消える**: 概況・設定の適用状況・設定の効果・スキル・コマンドの利用のページ、K113・K114・T42、確認なしモード（T05 の列で読む）。**足す**: K10・K12・K21・K23・K24・K30・K40・K52・K55・K85・K104・K107・K108、T04〜T06・T08・T25・T32
- **強み**: 利用状況が 2 群で軽い。報告の作業が 1 ページで終わる。点検は保守者だけが開く
- **弱み**: 運用の点検が 5 群・19 枚・9 タブで最も重い。管理者が保守者を兼ねるなら分けた意味が薄い
- **足した値**: seed からの計算は無し。`data-extra.js` は data.js の並べ替え・結合だけ（T32 の 2 つの並びを 1 表に、T21 に本体の版、T08 のモデル名の並び）。`meta.periods` を 7・28 に絞る（撮影の 12m は消した）
- 書き込みの結果（K85）は値を持たない（seed に失敗の区分が無い。内訳の帯だけ）
- 足した部品: `parts.js`（concepts.md 3 節の K・T を定義にした辞書。05〜08 で同じ写し）・`extra.css`（タブ・区分が多いと重なるため折り返す、利用者・モデルの列を折り返さない）
- **足すと良い収集**: `event_plugin_version`（点検で版ごとのエラー・欠けを比べる）、`turn_failure_rate`

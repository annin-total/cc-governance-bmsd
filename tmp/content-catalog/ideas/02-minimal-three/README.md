# 案 02 最小の 3 ページ

- **狙い**: 開く場所を 3 つに絞る。期間で動くのは利用とコストの 2 ページ、端末は期間を選ばない点検に閉じる
- **ページ**: 利用（誰がどれだけ、何に使っているか）・コスト（いくらかかり、誰とどのモデルに集まっているか）・端末（端末に設定が入り、記録が届いているか）＋データと設定
- **消える / 足す**: 概況・設定の効果・スキル・コマンドの利用のページ、コストの前後差（K113・K114・T42）。定着度・届いた人の割合（K03・K52・K55）・順位と集中（K23・K24・T04）・モデル（K40・K41・T06）を足す
- **強み**: ナビで迷わない。端末のページだけ見れば設定・版・受信が揃う
- **弱み**: 端末のページは群 5・タブ 7 で縦に長い（撮影で約 2,400px）。スキル・コマンドの一覧が利用のタブに埋もれる。コストの前後差をやめるのは新しい判断
- **足した値**: なし（下の共通の 3 つだけ）
- **足した値**（`data-extra.js`。スクラッチパッドの `extra.py` が data.js と seed の DB から作る）: 利用明細の利用者だけの並び `x.billed`・記録の利用者だけの並び `x.activity`・端末に本体の版を結合 `fixed.x.terminals`
- **足した部品**: `parts.js`（concepts.md 3 節の K・T の辞書と窓。案 01〜04 で同じ写し）。`index.html` は kit の写しに `data-extra.js`・`parts.js` の 2 行を足しただけ。12 か月では出るタブを先に並べる
- **足すと良い収集**: `session_model_share`（利用の中身としてのモデル）、`headcount_adoption_rate`（分母を社員数に）

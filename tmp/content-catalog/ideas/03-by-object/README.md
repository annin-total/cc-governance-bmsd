# 案 03 対象で分ける

- **狙い**: 調べたいものを名詞（利用者・モデル・スキルとコマンド・設定・端末）で引けるようにする
- **ページ**: 利用者（誰がどれだけ使い、いくらかかっているか）・モデル（どのモデルにいくらかかり、トークンはどう使われているか）・スキルとコマンド（どの機能が誰に使われているか）・設定（配った設定が効き、権限はどう使われているか）・端末（端末は最新で、記録を送っているか）＋データと設定
- **消える / 足す**: 概況・設定の効果のページ（設定へ統合。前後差は T42 の中だけ）。確認なしの記録の割合を人数（K63）に置き換え。単価・利用者数・トークン（K43・K46・T07）、ツール・MCP（K60・K58・T13）、適用率の推移（K83・T24）を足す
- **強み**: 探し物の場所が名詞で決まる。権限モードが設定に入り、利用量のページから安全の話が消える
- **弱み**: 全体のコストと今月の見込みがモデルのページにある。利用者のページに記録と利用明細の 2 窓が並ぶ。端末のページのプラグイン未導入は開く先（利用者ごと）が設定のページにあり押せない
- **足した値**: effort の件数 `x.effort`・T32 の結合 `m.uncollected_rows`・T08 の系列 `x.model_keys`・適用率の最新週 `fixed.x.compliance_last`・コマンドの定義元の空欄を「記録なし」に `x.command_source`
- **足した値**（`data-extra.js`。スクラッチパッドの `extra.py` が data.js と seed の DB から作る）: 利用明細の利用者だけの並び `x.billed`・記録の利用者だけの並び `x.activity`・端末に本体の版を結合 `fixed.x.terminals`
- **足した部品**: `parts.js`（concepts.md 3 節の K・T の辞書と窓。案 01〜04 で同じ写し）。`index.html` は kit の写しに `data-extra.js`・`parts.js` の 2 行を足しただけ。12 か月では出るタブを先に並べる
- **足すと良い収集**: `subagent_type_share`（サブエージェントの種類）、`mcp_server_origin`（配った MCP と個人の MCP を分ける）

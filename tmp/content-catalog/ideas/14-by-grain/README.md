# 案 14 粒度で分ける

**狙い**: 全体の集計（カードが主）・利用者ごとの一覧・端末ごとの一覧を分け、監査・評価で開くページを 1 つにする。

| ページ | 問い |
| --- | --- |
| 全体の集計 | 全体でどれだけ使われ、いくらかかっているか（群: 利用明細・今月・記録・しきい値、タブ T02・T03・T01・T06・T11・T12・T40） |
| 利用者 | 一人ひとりはどれだけ使い、いくらかかり、設定は入っているか（群: 分布〔明〕K23・K25・K26／分布〔記〕K02・K08、タブ T04・T07・T05・T20・T09・T17） |
| 端末 | 一台ずつ、設定・版・記録は正常か（群: 端末〔30〕・受信〔記 7 日〕・照合〔照 7 日〕、タブ T21・T23・T22・T30・T31・T32） |

**消える**: 概況・設定の適用状況・設定の効果・スキル・コマンドの利用のページ。K113・K114・T42。K80〜K82（T20・T22 で読む）。
**足す**: K02・K03・K08・K10・K21・K23〜K26・K30・K40・K41・K52・K53・K55・K104、T04・T05・T07・T09・T17・T32。
**強み**: 利用者の一覧（コスト・トークン・使い方・設定）が 1 ページに揃い、同じ絞り込みでタブを行き来できる。
**弱み**: 全体の集計が 4 群・7 タブで何でも入る場所になりやすい。利用者のタブは窓が 3 種類（〔明〕〔記〕〔30〕）でタブの補足で区別するしかない。2 つの群が同じ「分布」で、横の窓の表記でしか見分けられない。
**足した値**（`data-extra.js`、seed の DB と data.js から生成）: K26 の増加順の並び（`x.people_up`）、T32 の 1 表（`x.gap_users`: 利用明細だけ／設定の報告だけ・コスト・最後の記録と報告の日）、T21 の本体の版。`index.html` に読み込みを 1 行足した。 **判断**: T20 は期間と無関係なので 12 か月でも出す。K26 は 12 か月では前と比べないため自前の断りのカードにした。 **足すと良い収集**: `headcount_adoption_rate`（利用者の一覧に部署を足し、部署で絞る）。

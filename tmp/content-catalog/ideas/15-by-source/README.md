# 案 15 データの出所で分ける

**狙い**: 利用明細・端末の記録・設定の報告という出所ごとにページを作る。ページの中の窓がそろい、12 か月は利用明細のページだけが持つ。

| ページ | 問い |
| --- | --- |
| 利用明細（7 日・28 日・12 か月） | 誰に、どのモデルで、いくらかかったか（群: コスト・利用者・モデルとトークン・今月、タブ T04・T02・T06・T07・T03・T08） |
| 利用の記録（7 日・28 日だけ） | どれだけの頻度で、何を使っているか（群: 頻度・スキルとコマンド・受信・照合、8 タブ） |
| 設定の報告 | 端末に設定が入り、最新か（群: 適用・導入と版、タブ T20〜T24） |
| 設定の効果 | しきい値は働いているか（群: コンテキスト・コストの前後、タブ T40〜T42） |

**消える**: 概況・設定の適用状況（設定の報告へ）・スキル・コマンドの利用（利用の記録へ）。確認なしモードの記録（K63 へ）。 **足す**: K02〜K04・K10〜K13・K21・K23・K24・K30・K40・K41・K43・K52・K53・K55・K63・K83・K104、T04〜T08・T13・T24・T32。
**強み**: 群の窓の決まりがページ単位で自然に守られ、12 か月で空になるページが無い。利用者数が 2 つある理由がページ名で説明される。
**弱み**: ページ名が問いでなく出所で、「利用者の数」を探すと 2 ページを見る。受信の点検が利用の記録に入り、中身と点検が同居する。
**足した値**（`data-extra.js`）: T32 の 1 表（7・28 日）、T08 の系列（`x.model_keys`）、T21 の本体の版。**足した部品**（`ia.js` 内）: ページごとの期間の選択肢（`periodChoices`。描く前に `meta.periods` を差し替える）、T08 は 12 か月のときだけタブに入れる。 **注意**: 撮影は全ページ 3 期間を撮るため、利用の記録の 12 か月の画像は 7 日と同じ（選択肢に無いので 7 日に落ちる）。 **足すと良い収集**: `event_plugin_version`（記録を版で割る）、`session_model_share`（記録に端末側のモデル。利用明細のモデルとは突き合わせない）。

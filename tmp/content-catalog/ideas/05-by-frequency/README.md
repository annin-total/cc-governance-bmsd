# 案 05 見る頻度で分ける
**狙い**: 毎日開くページを軽くし、月に 1 度の締めと、たまの分析を分ける。
| ページ | 問い |
| --- | --- |
| 日々の確認（記録は 7 日固定） | 今日、手を打つべきことはあるか |
| 月の集計 | 今月と前月はいくらで、誰に集まったか |
| 分析（7・28 日・12 か月） | 使われ方とコストの中身はどうなっているか |
- **消える**: 概況・設定の適用状況・設定の効果・スキル・コマンドの利用のページ、K113・K114・T42。**足す**: 暦月の利用者の順位、K12・K13・K24・K40・K41・K52・K55・K67・K83、T04〜T06・T08・T13・T24
- **強み**: 日々の確認は軽い集計 3 群だけ。月の締めが 1 ページで終わる
- **弱み**: 分析が 5 群・9 タブで何でも入る場所になる。設定が日々（K81）と分析（K82）に割れる
- **足した値**（`data-extra.js`）: `fixed.cal`＝seed の cost_daily を暦月 × 利用者で集計（今月・前月の順位・月ごとの継続率）。生成は `../08-monthly-report/build_extra.py`。末尾は data.js の並べ替えだけ（最新週の適用率・モデル名の並び など）
- 12 か月の継続率（K13）は暦月の継続率（前月の利用者のうち翌月も使った割合）で出す
- 足した部品: `parts.js`（concepts.md 3 節の K・T を定義にした辞書。05〜08 で同じ写し）・`extra.css`（タブ・区分が多いと重なるため折り返す、利用者・モデルの列を折り返さない）
- **足すと良い収集**: `turn_failure_rate`（日々の確認にレート制限などの失敗を足す）

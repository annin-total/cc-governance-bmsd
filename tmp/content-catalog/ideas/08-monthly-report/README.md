# 案 08 月次の報告を中心にする
**狙い**: 暦月で締める数字を独立した月次のページに集め、ほかのページはローリングの窓だけにする。
| ページ | 問い |
| --- | --- |
| 月次 | 今月はいくらで着地し、前月はいくらだったか |
| 利用（7・28 日・12 か月） | 誰がどれだけの頻度で使っているか |
| コスト（7・28 日・12 か月） | 直近の期間にいくらかかり、何に集まっているか |
| 設定と端末 | 設定が入り、端末が記録を送っているか |
- **消える**: 概況・設定の効果・スキル・コマンドの利用のページ（スキル・コマンドは利用のタブへ）。**足す**: 月ごとの利用者の順位（区分で月を選ぶ）、K02〜K04・K10〜K13・K21・K24・K26・K30・K40・K41、T04〜T06・T08・T09・T17
- **強み**: 月次の報告と日々の分析が混ざらない。営業日あたりの比較が暦月の群に閉じる
- **弱み**: 12 か月のコストが月次とコストの 2 か所にあり、コストの 12 か月から K20・K26・T02・T09 を外す例外が要る（注記の文言を ia.js でこのページだけ差し替え）。利用の 12 か月はタブがすべて空
- **足した値**（`data-extra.js`）: `fixed.cal`＝seed の cost_daily を暦月 × 利用者で集計。`build_extra.py <seed.db> <出力...>` で生成（末尾に `tail.js` を付ける）。K26 の並び（増えた額の順）は data.js の並べ替え
- 足した部品: `parts.js`（concepts.md 3 節の K・T を定義にした辞書。05〜08 で同じ写し）・`extra.css`（タブ・区分が多いと重なるため折り返す、利用者・モデルの列を折り返さない）
- **足すと良い収集**: `headcount_adoption_rate`（月次に社員に対する利用率・部署ごとのコストを載せる）

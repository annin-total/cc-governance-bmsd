# 案 11 モデルとトークンを前に出す

**狙い**: コストの中身（モデルの構成・キャッシュの割合・100 万トークンあたりの単価）を独立したページにし、コストのページは金額と人に絞る。
- **コスト** — いくらかかり、誰に集まっているか
- **モデルとトークン** — 金額は何でできているか
- **利用** — 誰がどれだけの頻度で使っているか
- **スキルとコマンド** — どの機能が誰に使われているか
- **設定** — 配った設定が効いているか
- **端末と収集** — 端末が最新で、記録が届いているか
**今から消えるもの**: 概況・設定の効果のページ（設定へ）・確認なしモードのカード。**足すもの**: K40〜K46・K67〜K69、モデル（T06）・利用者ごとのトークン（T07）・月ごとの推移（T08）・コンテキスト（T15）。
**強み**: キャッシュ読み込みの割合と単価が主役になり、コストの増減の理由を追える。
**弱み**: 6 ページで利用とスキルとコマンドが薄い。モデルとトークンのページに記録の窓（コンテキスト）が混ざる。利用のページの利用明細のカードは開くタブが無い。
**足した値・部品**（`index.html` は kit の写しに `data-extra.js` の読み込みを 1 行足した）: `data-extra.js` に、トークンの内訳の組（`x.token_parts`）、月ごとの推移の系列名（`x.model_keys`）、12 か月の継続率（直近の完了した月）、端末ごとの本体の版。12 か月だけのタブ（T08）はキットに無いため、7・28 日では空の行（`x.months = []`）と案内の文で出す。
**足すと良い収集**: `session_model_share`（端末側のモデルと 1M コンテキストの利用率）、`resume_cache_write_usd`・`resume_cache_expiry`（キャッシュ書き込みを再開の行動に分解）。

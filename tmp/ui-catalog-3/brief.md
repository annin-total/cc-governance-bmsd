# 管理画面デザイン・カタログ 第 3 弾 指示書

今の管理画面（`base/*.html`。規約は親リポジトリの `docs/spec/design-system.md`、利用者の好みは下）に、次の 4 つを足すデザイン案を比べる。

## 足す機能（決まっていること）

1. **期間の切り替え**「7 日」「28 日」「12 か月」。効くのは概況とスキル・コマンドの利用だけ（設定の適用状況・設定の効果には出さない）
   - 7 日・28 日: 直近 N 日とその前の N 日を比べる。グラフは日ごと。目盛りは 7 日は毎日、28 日は月曜
   - 12 か月: 直近 12 か月の推移だけ（前の期間と比べない）。グラフは週ごと（月曜始まりの週）、目盛りは月（各月の最初の週）。**出せるのは利用明細（CSV）由来の項目（コスト・利用者数）だけ**。記録由来の項目（受信・欠け・エラー・使われ方・スキル）は 12 か月では出さない（どう見せるかは案ごとに考える）
   - コストは CSV の最終日で終わる（今日より前）
2. **月末のコストの見込み**（期間の切り替えと無関係に暦月）: 見込み = 今月の実績 × 月の営業日数 ÷ 経過した営業日数（経過は CSV の最終日まで）。営業日 = 平日かつ国民の祝日でない日。比べる値は今月と前月の「営業日あたり」、前月の合計と営業日数。経過営業日が少ないと「—」。会社のコスト概算に使う重要な数字
3. **数値の表示**: 1,000 以上は整数に丸める（$2,259）。トークンは 100 万未満は k（951k）、100 万以上は M（1.2M）。表の列の中では単位を混ぜない。**ツールチップ**: グラフの棒・点・区間に当てると具体的な値（例「09/23（火） $368」）。JS 前提でよい
4. **エクスポートのページ**: 月を選んで、その月の全ログ（記録・設定の報告・エラー・利用明細の 4 表、利用者名つき）を表ごとの CSV の ZIP でダウンロード。目的は手元の Python での分析。**概況にある「CSV を取り込む」もこのページへ移す**。入口はヘッダーの右端が第一候補（案で変えてよい）

## 利用者の好み（守る）

- 落ち着いたグレージュ（今の tokens.css）。色数は控えめ。ダークモード・配色切り替えなし
- 極太・特大を避ける（最大 40px・太さ 600）。小さめの文字
- 要点をカードで 1 ページに見渡し、詳しい一覧はタブ。調整しやすさ（定義の配列から描画・CSS 変数）
- シンプルさを保つ。足すことでごちゃごちゃさせない。既存のデザインとの整合性を最優先

## 作るもの

- 各案 `ideas/NN-<slug>/`: `index.html`（概況に機能を載せたもの）と `export.html`（エクスポートのページ）。必要なら `assets.html`（スキル・コマンドの利用）
- **土台は `base/` の本物の HTML・CSS**（写して改変する）。新しい部品の CSS は `base/static/tokens.css` の変数を使い、足した変数は案の CSS に書く
- 値は `data/data.js`（window.DATA）から
- 案の焦点（下の表）以外の部分は、次の「既定の扱い」にする（案ごとに全部を作り直さない）
  - 切り替え: 画面の見出しの右に分段（「7 日」「28 日」「12 か月」）
  - 見込み: 概況の「利用」の群にカード 1 枚
  - ツールチップ: カーソルの近くに小さな浮いた札（地は --card、細い罫、影は弱く）
  - エクスポート: 月を選ぶ欄とボタンだけの素朴なフォーム＋その下に CSV の取込
- スクリーンショット（幅 1440、fullPage。**上段の要点は 1440×900 に収める**）:
  `shot-7d.png`・`shot-28d.png`・`shot-12m.png`（概況の 3 状態）・`shot-tip.png`（ツールチップを出した状態。マウスを当てて撮る）・`shot-export.png`、案の焦点に応じて追加
- `README.md`（10 行以内）: 名前・焦点・狙い・部品（新しく足すものと既存の再利用）・実装の工数感・懸念

## 案の一覧

| No | 名前 | 焦点 | 骨子 |
| --- | --- | --- | --- |
| 01 | 素直な追加 | 全体 | すべて既定の扱い。比べるための基準線 |
| 02 | 見出しが切り替えになる | 切り替え | 群の見出しの横の期間の文言（「直近 7 日と、その前の 7 日」）自体を分段の切り替えにする。場所が増えないが、画面全体に効くことが伝わるか |
| 03 | 固定の期間バー | 切り替え | ナビの下に細い帯を常設（スクロールしても残る）。切り替えと具体的な日付（09/02〜09/29 と 08/05〜09/01）と CSV の最終日を 1 行に |
| 04 | 目立たない選択 | 切り替え | 見出しの右に小さな選択（select）。視覚的な重さを最小に |
| 05 | 今月の帯 | 見込み | 概況の最上部に全幅の「今月」の帯: 見込み・実績・営業日の進み（15 / 21 日の細い棒）・前月との営業日あたりの比較。群の上に置く |
| 06 | 見込みの累積グラフ | 見込み | 見込みのカードに、今月の累積の実線＋月末までの破線の見込み＋前月の累積の薄い線（営業日で横軸をそろえるか暦日かも判断） |
| 07 | 十字線と値の読み取り | ツールチップ | 浮いた札を出さず、縦の線（十字線）とカード見出しの横の値の表示が、当てた日に切り替わる |
| 08 | グラフと表の連動 | ツールチップ | タブのグラフに当てると表の同じ行が強調され、表の行に当てるとグラフの棒が強調される |
| 09 | 12 か月の長期表示 | 12 か月 | 12 か月を選ぶと、概況が「長期」の型に変わる: 週ごとのコストの大きな推移グラフ＋月ごとの合計の行＋利用者数の推移。記録由来の群は 1 行の注記に畳む |
| 10 | 12 か月は薄く残す | 12 か月 | 群とカードの配置は変えず、記録由来のカードは「12 か月では出さない」と薄く表示（空の札）。配置が動かないことを優先 |
| 11 | 月の一覧からダウンロード | エクスポート | 月の一覧表（月・記録の行数・おおよその大きさ・ダウンロードのボタン）。選ぶ操作なしで押すだけ。取込はページの上部に |
| 12 | 取り込むと書き出すの 2 列 | エクスポート | ページを左右 2 列（取り込む｜書き出す）に。書き出す側は月を選ぶと、含まれる表と行数・大きさ・列の一覧が見える |
| 13 | 月の格子 | エクスポート | 12 か月の格子（カレンダー風の 4×3）で、各月に行数と大きさ。押すとダウンロード |
| 14 | 数値の静かな表示 | 数値 | 単位（$・k・M・人・件）を小さく薄く、数字は等幅で右揃え。丸めた値の正確な値はツールチップで出す |

## 担当の作業

- 割り当ての案を作り、撮った画像を Read で見て、崩れ・余白・揃え・文字の階層・桁揃えを直してから終える。**既存の画面との整合性と単純さを最優先。**品質に妥協しない
- 仮に置いた値・判断は README に書く

## 材料

- `base/*.html`・`base/static/`: 本物の画面の写し（file:// で本物と同じに見える）。`base/*.png` が今の見た目
- `data/data.js`（window.DATA）: 今日 2026-09-29、CSV の最終日 2026-09-28。`daily_cost`（399 日、提供元ごと・利用者数）、`periods.7`/`periods.28`（今の概況・スキルのカードの値を 7 日と 28 日で計算したもの）、`twelve_months.weeks`（53 週、月曜始まり、最後の週は途中）、`month_forecast`（9 月: 営業日 19・経過 17・実績 $8,959.84・見込み $10,013.94、前月の合計・営業日、祝日一覧）、`tokens`（k と M の例）、`export`（月ごとの 4 表の行数と大きさ、列名）
- seed のエラーは直近 28 日にしか無い（それ以前の月の errors は 0 行）

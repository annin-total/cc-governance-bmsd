# 08 異常を先に（概況）

- **狙い**: 開いた瞬間に「いま手を打つべきこと」だけが目に入るようにする。最上部は要対応・注意の項目だけの一覧（無ければ「異常なし」の 1 行）で、節は状態の見出し行だけに畳み、必要なときに開く。
- **情報の組み立て**: 確認が要る項目（エラーの種類ごと・基準を超えた欠け。件数と端末数を右に、判定の基準を一覧の下に明記）→ ほかの画面の要対応へのリンク 1 行 → 点検の節（エラー / 項目の欠け / 受信の状況。各行に状態・要点の数字・期間）→ 利用の実態の節（コスト / 利用者数 / 使い方。状態の判定をしない）。すべて畳んだ状態で始まる。
- **色と文字**: 白地に墨、罫線は細い灰。状態色は要対応（赤）・注意（黄土）・正常（緑）・判定なし（灰の白抜き丸）の 4 つだけで、色は文字・点・左の線に使い、面は淡色にとどめる。ゴシック 1 系統、例外名とバージョンは等幅。
- **UI 部品**: 異常の一覧（左の色線＋状態の文字＋数字＋「内訳へ」で該当の節を開く）、details による畳み込み（見出し行に状態・要点・期間）、ナビの「要対応あり」の点。
- **工数感**: 小〜中。見た目は CSS と details で済む。判定の基準（エラー 1 件以上・欠けの増加 5 ポイント）を仕様として決め、サーバ側で状態を計算する必要がある。
- **懸念**: 基準（特に「エラー 1 件以上で要対応」「欠けが 5 ポイント増で注意」）は仮で、実データでは常に赤が並ぶおそれがある。一覧と節で同じ数字を 2 度出す（一覧は節の要約）。ほかの画面の件数を概況に出すには画面をまたぐ集計が要る。shot-2.png は「異常なし」の見え方を示すため、値を差し替えた表示。

設定の効果

自動圧縮のしきい値を 60% にそろえた前後で、コストとコンテキストの大きさを比べる

設定: 自動圧縮のしきい値（env.CLAUDE_AUTOCOMPACT_PCT_OVERRIDE）、配布した値 60。

日の数え方: 利用者ごとに、設定を守り始めた日を 0 日目とした前後 14 日。暦日ではない。

コスト・トークン・対象者の前後

守り始めた日の前後 14 日（0 日目を除く） · 提供元 AWS Bedrock · 1 人あたり

平均は日ごとの値の単純平均。細い線が 28 日の推移で、左半分が守る前、右半分が守った後。

0 日目（守り始めた当日）は前後が混ざるため除いている。

この差を設定の効果と読まない。時期による変動（繁忙・モデルの切り替えなど）を差し引いていない。設定が無くても前後で ±十数% の差が出る。

設定が働いているかは、下のコンテキストの分布で見る。

コンテキストの大きさの分布

守り始めた日の前後 14 日 · 区間の幅 2 万トークン · 各区間の記録の割合（件数の違う前後を割合でそろえた）

圧縮直前（PreCompact）は自動圧縮が走る直前のトークン数。しきい値が効けば小さい側に寄る。

応答終了（Stop）は各応答が終わった時点のトークン数。

件数 0 の区間は集計に現れないため、図では 0 として描いている。

端末から送られた値と、全社の利用明細（CSV）の値。コストとトークンは CSV を正とする。監査・人事評価・勤怠管理には使わない。

# 管理画面デザイン・カタログ 指示書

## 共通の前提

- 見る人: BMSD 本部で Claude Code の利用を管理する管理者（数人）。広い画面の PC で見る
- 画面が答える問い: 誰がどれだけ使っているか／設定（施策）は守られているか／施策に効果があったか／データの収集は正常か
- 材料: `data/context.json`（実際の値）、`data/glossary.md`（言い換え表）、`data/sections.md`（節と問い）、`current/*.png`（今の画面）
- 1 案 = 静的な HTML 1 ページ（`ideas/NN-<slug>/index.html`＋必要なら同じフォルダの css/js）。値は context.json から写す（JS で読み込んでも、HTML に直接書いてもよい。file:// で開いて表示できること）
- 外部への読み込みをしない（CDN・Web フォント不可。フォントは OS の `system-ui`・`Hiragino`・`Yu Gothic`・明朝系などのローカルフォント指定で）
- グラフはインライン SVG（手書きか JS で生成）。ライブラリ不可。JS は必要なだけ使ってよい（タブ・絞り込み・並べ替え・畳み込み）
- **今の画面は暫定の仮デザインであり、docs/spec/dashboard-style.md の規約には縛られない。アイデアの発散を優先する。**率の分子・分母の併記や期間の明記は、読み違いを防ぐ工夫として参考にしてよい（必須ではない）
- 文言: 変数名そのままを出さない。短く、普通に読んで解釈が分かれない語。長い説明は薄い色・小さい字に下げる（情報の階層を文字の大きさ・濃さ・余白で作る）。比喩を使わない
- 色: 基本は少ない色数・落ち着いた・わずかにクラシック寄り。状態色は ok/warn/ng/neutral の 4 つまで
- 全案で共通のナビ（4 画面ぶん）を出してよいが、作り込むのは各案の「1 ページ」だけ
- 各案の冒頭（HTML 内のコメントではなく、`ideas/NN-<slug>/README.md`）に: 案の名前、狙い（2 行）、情報の組み立て、色と文字、使った UI 部品、実装時の工数感（小・中・大）と理由、懸念 を 10 行以内で

## 担当の作業

1. 割り当ての案を作る（互いに似ても構わないが、各案の骨子は崩さない）
2. Playwright（python）で幅 1440・fullPage のスクリーンショットを `ideas/NN-<slug>/shot.png` に撮る。タブ・切り替えのある案は主要な状態を `shot-2.png` などで追加
3. 撮った画像を自分で見て（Read で開ける）、崩れ・はみ出し・文字化け・読みにくさを直してから終える。品質に妥協しない。シニアの UI デザイナーとして、余白・揃え・文字の階層・数字の桁揃え（tabular-nums・右揃え）まで詰める

## 下準備で分かった、今の画面の問題（デザインで解消する）

- 概況のタイル「送信した利用者」のキーは `terminals` だが、中身は人数（`COUNT(DISTINCT user_email)`）。「人」と表記する
- `/policy` の版の分布の列名は「件数」だが、中身は端末数
- 拡張（プラグイン）の版の分布が概況と `/policy` の 2 か所に出ている。1 か所にまとめる
- 実データは users=40・days=74。表は長い（最新値 44 行、日別費用 143 行）。畳み・絞り込み・グラフ化の候補

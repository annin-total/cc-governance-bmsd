# 指示書: 管理画面の概況のモック

管理画面の最初のページ「概況」（URL はホームのパス）を作り直す。**載せる中身の趣旨**は下で決まっている。**カードの分け方・カードの中の構成・語・強調の度合い**は決まっておらず、案ごとに変えて比べる。

## 前提

- 読者は本部の管理者。日々の状況確認と、週報を書くときに使う
- 今の管理画面と揃える。見た目は `docs/spec/design-system.md` と `server/ccgov/web/static/*.css`、カードの作りは `server/ccgov/web/templates/components/card.html`（見出し・値・補足・小さい図）、語は `server/ccgov/web/labels.py` と `server/ccgov/web/screens/words.py`
- **この文書の語は仮の語である。**画面に出す語は、今の画面にある語を優先し、無ければ初見で意味が通る最適な語を自分で探す（例: 今の画面は「コスト（利用明細）」「月末のコスト見込み（9 月）」「1 人 1 営業日あたり」「すべての設定を適用」「未適用のある利用者」「プラグイン未導入」「送信した利用者」「利用明細にいた利用者」）
- 値はダミー。今日・基準日は 2026-10-01（木）。利用明細 CSV の最終日は 2026-09-29（火）（CSV は今日と前日の分が無い）

## 色（最重要）

- **カードの見た目は他のページと同じにする。**今の配色（`tokens.css`。青系のアクセント `--accent`・`--chip-up` を含む）とカード・群・タブ・印の作りをそのまま使う
- 新しい色は極力増やさない（禁止ではない。無理のない範囲で、配色ごとに必要なら 1〜2 色まで）
- そのうえで、注意・要確認（状態）と悪化・改善（増減）が**視覚的に区別できる**こと。何に注目すべきかが一目で分かること。良し悪しの向きはカードごとに決まる（コスト・未適用・未導入・エラーは増えると悪化。利用者は増えると改善）

### 配色の切り替え（モック用、仮）

- 各案の右上に「配色（仮）」の切り替えを置く。`<html data-scheme="...">` を差し替え、`[data-scheme=...]` の CSS 変数と少しの規則で見た目を変える。構造（HTML）は変えない
- 1 つめは全案共通の **「今の配色」**（今の画面そのまま。状態は点＋語の印、増減は今の `change` のチップ）
- 2 つめ以降は、下の表で各案に割り振った**独自の配色 3 つ**。配色は色の値だけでなく「色をどこに使うか」（状態の示し方・増減の示し方・アクセントの量）を変える。表は方向の指定であり、具体の色と名前は担当が決める（名前は 2〜6 文字の名詞句）
- 各配色の名前と、何を変えたかの 1 行を、ページの最下部に小さく一覧で書く

### 品質を上げるための調整

- 配色は色の値だけでなく、文字のマーカー・記号・ラベル・余白・太さなどの細かい調整を含めてよい（無理に変えなくてよい。品質を高めることを優先する）
- ただし今の画面（development の `server/ccgov/web/static/`・`templates/`）のスタイルから逸脱しない
- 各案のレイアウトは「大まかな骨組み」として扱い、品質のために必要なら柔軟に調整してよい
- 値の書き方は今の画面の決まりに合わせる（金額の丸め・単位・日付の書き方は `server/ccgov/web/filters.py`・`labels.py`）

### 状態での絞り込み

- ページの上部（期間のタブの近く）に「表示: すべて / 注意以上 / 要確認」の切り替えを置く。該当しないカード・行を薄くする（例: `opacity`）。既定は「すべて」
- 薄くする度合いや、薄くする単位（カード・行）は案ごとに決めてよい

## 画面の上部

- ヘッダーのナビ: 概況 / サマリー / コストと利用者 / ツール利用状況 / 設定の適用状況 / 設定の効果 / 収集の状態 / データと設定（概況以外の名前は仮。このモックの対象外）
- 期間のタブ: 7 日 / 28 日 / 12 か月（既定 7 日）と、基準日の日付入力（既定は今日）
- コストを数える期間は「基準日と CSV の最終日の早いほうで終わる N 日」。この例では今期 09/23〜09/29、前の期間 09/16〜09/22。数えた範囲を群の見出しの横に出す

## 載せる中身（趣旨。分け方は案ごとに変える）

画面の中の要素は**重複させない**（サマリーを除く）。同じ数字を 2 か所に出さない。

| 趣旨 | 中身 | 警告（注意 / 要確認） |
| --- | --- | --- |
| サマリー | 人が書く週報の最新 1 件。見出し・タイトル（本文と同じ大きさの太字）・対象期間と作成日・本文（プレーンテキスト、改行を保つ。**折りたたまず全文を出す**）・履歴へのリンク。注意・要確認の件数を添えてよい | — |
| コストの総額 | 今期の合計と前の期間との差・率。今期 4 営業日・前 3 営業日 | 1 営業日あたりの前の期間比 +10% / +15% |
| 1 営業日あたり | 合計 ÷ 営業日数 | 同上（総額と同じ判定。1 枚にまとめるなら判定も 1 つ） |
| 1 人 1 営業日あたり | 上の値 ÷ 期間内に利用明細にいた利用者。利用者一覧（コスト順）へのリンク | 前の期間比 +10% / +15% |
| 月末のコスト見込み | 9 月の見込み（9 月の CSV は 09/29 まで）と 8 月の実績との比 | 前月の実績比 +10% / +15% |
| 利用者 | 期間内に利用明細にいた人数と、前の期間との差 | 前の期間比 −10% / −15% |
| 基準を超えた利用者 | 個人のコストが基準を超えた人数。日（期間中のいずれかの 1 日 $50 / $100）・週（基準日までの 7 日の合計 $70 / $150）・月（基準日までの 28 日の合計 $280 / $600）の 3 つ × 注意・要確認。人数から該当者の一覧へ。期間のタブに連動しない | 基準を超えた人が 1 人以上 |
| 設定の適用 | 対象者を、すべて適用・未適用のある・プラグイン未導入に分ける（3 つで対象者全員になる） | 未適用・未導入が 1 人以上で注意 |
| モデルの内訳 | コストのモデル別の割合（任意。載せない案があってよい） | — |
| 収集の状態 | プラグインのエラー件数とデータの届き具合の要約 | エラー 1 件以上で注意 |

## 形式

- `ideas/NN-<名前>/index.html` の 1 ファイル完結（今の CSS を写してページ内に置く。外部の読み込みなし、file:// で開ける）
- 幅 1280px。1280×800 の 1 画面目に重要なものから入るとよい（必須ではない。優先順を考えて並べる）
- 左右にサマリーとカードを分ける並べ方は採らない
